# 라이트쎈 중2-1 — 정답 PDF 가 **교재와 다른 판**이다 (2026-11-04)

정답 그림을 다시 자르다가 찾았다. 2026-09-22 에 419문항이 어긋난 **진짜 까닭**이다.

## 증거

| | |
|---|---|
| 정답 PDF 지면에 찍힌 제작 표시 | `중등라이트쎈-빠른정답(01-09).indd` **18. 4. 26.** → **2018년 판** |
| 교재 파일 이름 | `22개정 라이트쎈 중2-1.pdf` → **2022 개정판** |
| 번호 범위 | 교재 최대 **1153** · 정답 목록 최대 **1176** (23개 더 많다) |

## 문제를 풀어 맞대 보면

정답 목록의 번호는 OCR 로 읽어 **그림에 찍힌 번호와 1176개가 모두 일치**한다.
그런데 **교재 문항과는 안 맞고, 어긋난 폭이 구간마다 다르다.**

| 교재 번호 | 문제 | 풀면 | 목록 N | 목록 N+1 |
|---|---|---|---|---|
| 0174 | (−5x³)×(−9x⁶) | 45x⁹ | −30b¹¹ | **45x⁹** ✓ |
| 0351 | A−B (서술형) | 16x²+5x−26 | ③ | **16x²+5x−26** ✓ |
| 0461 | (4x−1)/5−(x+3)/2≥1 | x≥9 | x≤9 | **x≥9** ✓ |
| 0569 | 「몇 분 미만」 | 분 | 11장 | 10회 ✗ |
| 0861 | y=(5/4)x−1 | 기울기 5/4 | 기울기 3 | 기울기 −1/3 ✗ |
| 1036 | 「몇 분 후」 | 80분 | 90 km | ③ ✗ |

앞쪽은 **한 칸**, 뒤로 갈수록 더 벌어진다. 개정하면서 문항이 더해지고 빠졌기 때문이다.
**어떤 보정으로도 못 맞춘다.**

## 그래서 2026-09-22 작업이 틀렸던 것이다

그때 「판 확인: 문제집 0013~0020 ↔ 정답 0013~0020 이 8개 모두 일치 → 같은 판」 으로 통과시켰다.
**앞쪽 8개만 봤다.** 밀림은 뒤로 갈수록 생기므로 앞쪽만 보면 반드시 통과한다.

→ **판 확인은 앞·중간·뒤에서 고르게, 문제를 풀어서 해야 한다.**

## 이번에 다시 자른 것은 어떤가

`aocr.py` + `aassign2.py` + `acrop.py` 로 **1176개 전부** 번호를 확정했다
(옛 방법은 1,116개였고 그중 419개가 어긋났다). 그림마다 **번호가 함께 찍혀 있어**
어느 문항의 답인지 그림만 봐도 안다.

**2018년 판 기준으로는 정확하다.** 다만 교재가 22개정이라 맞지 않는다.

## 해야 할 일

**22개정 라이트쎈 중2-1 의 정답 PDF 가 필요하다.** 그것만 있으면 지금 만든 도구로 바로 끝난다.

그때까지 이 교재의 정답 그림은 **믿을 수 없다**. 학생이 QR 로 채점하면 틀린 답을 본다.

## 만든 도구 (다른 교재에도 쓴다)

```
python ascan.py 12          # 번호 덩어리 찾기
python aocr.py 1 7          # 번호를 OCR 로 읽기 (확인용이지 꽂는 용도가 아니다)
python aassign2.py          # 자리 순서 + OCR 로 번호 확정, 어긋나면 비운다
python acrop.py             # 번호를 **포함해서** 자른다
```

- `aassign.py`(옛것)는 쓰지 않는다. 개수만 맞으면 꽂아서 밀림이 쌓인다.
- `ascan.py` 의 `len(g)>=2` 를 뺐다 — 네 글자가 한 덩어리로 붙은 번호가 통째로 빠졌다(0434·0448).
- `aocr.py` 의 임시 그림 이름에 프로세스 번호를 넣었다. 같은 이름을 쓰면 두 번 돌릴 때
  **서로의 그림을 읽는다**(에러 없이 OCR 이 62군데 어긋났다).
- `acrop.py` 는 쪽 가운데를 넘지 않는다 — 한 쪽에 책 두 면이 들어 있다.
