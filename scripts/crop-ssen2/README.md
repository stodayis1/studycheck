# 쎈 공통수학2 — 스캔본에서 문항 번호 찾기

쎈은 글자층이 없는 **스캔본**이라 지면을 그림으로 보고 번호를 읽어야 한다.
여기 모인 조각들은 그 과정에서 걸린 함정을 하나씩 막은 결과다.

## 결과

`qnum.json` — 문항 1323개의 번호와 자리(쪽·단·좌표·단계색).
`qstep.json` — 번호 → 단계(A/B/C). 10개 중단원 × A·B·C = 30구간으로 딱 떨어진다.

빠짐 0 · 순서 역전 0 · 중복 0.

## 어떻게 돌아가나

1. `s2det.colmask` — 번호는 단계마다 색이 다르다(A 주황 · B 초록 · C 파랑).
   난이도 딱지(하·중·상)와 유형 배지도 같은 색이라 크기로 가른다.
2. `scan.wide` — 후보를 **너그럽게** 모은다. 좁게 잡으면 「1046 •중•」처럼
   딱지가 붙어 덩어리가 커진 번호를 통째로 놓친다. 걸러내기는 읽은 값으로 한다.
3. `numask.left4` — 덩어리에서 **왼쪽 네 글자만** 남긴다. 번호는 늘 맨 앞이다.
4. `repmask` — 대표문제만 「갈색 상자 위 흰 글자」로 반대다. 밝고 색기 없는
   화소를 모으되, 뒤에 붙는 「대표 문제」 한글은 키가 절반이라 걸러진다.
   숫자끼리 붙어 세 덩어리로 잡히는 일이 있어 **개수가 아니라 틈으로** 끊는다.
5. `selftrain` — 빠른정답(다른 책·다른 색)으로 만든 숫자 틀은 본문에서 자주
   빗나간다. **본문에서 이미 확정된 번호들로 틀을 다시 만들면** 그 책 글꼴을
   그대로 익힌다. 이 한 단계로 못 읽던 것이 대부분 풀렸다.
6. `rowsort` — 한 쪽 안의 읽는 차례. A단계는 한 단에 문항이 가로로 둘씩 들어가
   (0623 옆에 0624) y 를 고정 간격으로 묶으면 1픽셀 차이로 앞뒤가 뒤집힌다.
   가까운 y 끼리 줄로 묶고 줄 안은 x 로 세운다.

## 번호를 확정하는 차례

읽기 → 범위 안 읽기 → 한 글자 고침 → 자리 메우기, 네 가지를 **번갈아 반복**한다.
확정된 번호 사이의 빈 자리 수와 빠진 번호 수가 맞으면 차례대로 메우고,
읽은 값이 앞뒤 번호 사이에 들지 않으면 잘못 읽은 것으로 보고 떼어 낸다.
마지막에 **1~1323 이 빠짐 없이, 역전 없이** 맞는지로 전체를 검산한다.

## 조심할 것

- **빠른정답의 A/B/C 구간 경계를 믿지 말 것.** 두 군데가 5문항씩 어긋나 있었다
  (251~255, 405~409). 책에 인쇄된 번호 **색**이 사실이다. 「B단계 유형 뽀개기」
  머리말 바로 아래가 0251 이다.
- **난이도 딱지를 번호로 세지 말 것.** 하·중·상 동그라미가 번호와 같은 줄,
  같은 색으로 서 있어 두 번 잡힌다. 읽어 보면 네 자리 숫자가 아니다.
- 1000번대는 앞의 `1` 이 가늘어 `9` 로 읽히기 쉽다. 번호는 1323 을 넘지 않으므로
  앞뒤 번호 사이에 드는지로 걸러진다.
