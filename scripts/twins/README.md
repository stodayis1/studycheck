# 쌍둥이·유사문제 맞추기, 그리고 그림 손질

## 왜 있나

문제은행의 목적은 유형 분류가 아니라 **문항별 쌍둥이·유사문제를 시중교재 사이에서
찾아 주는 것**이다. 유사문제(같은 유형)는 기계가 하지만, 쌍둥이(숫자만 다른 같은 문제)는
**그림을 눈으로 읽어야** 가려진다 — 선택지가 ①6②7③8④9⑤10 으로 똑같은데 서로 다른
문제인 경우를 공통수학2에서 실제로 봤다.

## 쌍둥이 맞추기

| 단계 | 명령 |
|---|---|
| 한 유형의 그림 내려받기 | `node scripts/twins/fetch.mjs 공수2-01-01 <폴더> [--level 3]` |
| 한 장에 모아 붙이기 | `python scripts/twins/sheet.py <폴더> <나갈이름>` |
| 읽고 찾은 것을 넣기 | `node scripts/twins/apply.mjs findings/중1-1-01.json [--dry]` |

- 한 장이 **1500px를 넘으면 화면에서 줄어들어 글씨를 못 읽는다.** `sheet.py` 의 `MAXH` 가 그 값이다.
- 찾은 결과는 `findings/*.json` 에 남긴다 (`쌍둥이`: id 묶음들, `유형고침`: 잘못 붙은 유형).
- 같은 문제가 교재 서너 권에 실리므로 짝이 아니라 **묶음**이다 → `problems.twin_group`.
  묶음 번호는 그 묶음에서 가장 작은 id.

## RPM 교재 번호 지우기 (2026-10-22)

RPM 중등 4,470문항 그림에 **교재 원본 번호가 남아 있었다.** 학습지는 1, 2, 3… 으로 다시
번호를 매겨 인쇄하므로 학생이 헷갈린다. (공통수학1 RPM 1,184문항은 이미 깨끗했다.)

```
node scripts/twins/rpm_io.mjs fetch  <작업폴더>     # 내려받기 (원본은 orig/ 에 남는다)
python scripts/twins/rpm_fix.py      <작업폴더>     # 번호만 지워 fixed/ 에
node scripts/twins/rpm_io.mjs upload <작업폴더>     # 다시 올리기
```

### 함정 — 네 번 고쳤다
1. **앞의 0 은 흐린 색**으로 찍힌다. 「0081」은 「81」만 또렷해 글자가 둘로 잡힌다
   → 아는 번호의 자릿수만큼 왼쪽으로 더 열어 지운다.
2. **묶음 지시문 「[0147~0150]」 의 숫자도 색 글자다.** 문항이 그 묶음의 첫 번째면
   지시문의 번호와 제 번호가 같아서 **지시문 쪽을 지우고 정작 번호는 남겼다.**
   → 줄의 **맨 왼쪽 덩어리 하나만** 후보로 삼고, 「[」로 시작하는 줄은 통째로 건너뛴다.
3. **번호가 한두 자리면** 아무 글자나 「맞다」고 통과한다 → 확신(conf 0.06)과 글자 수를 함께 본다.
4. **글자 사이가 벌어져 덩어리가 쪼개진다**(0413 → 「4」+「13」) → 같은 줄의 가까운
   숫자 덩어리만 이어 붙인다 (난이도 딱지는 글자 폭이 넓어 안 붙는다).

### 안전장치
**아는 번호(local_no)와 읽은 값이 맞는 후보만** 지운다. 안 맞으면 손대지 않고
`report.json` 에 적는다. 고친 뒤 **같은 검사기를 다시 돌려 번호가 남았는지 센다** —
0 이 나와야 올린다. 원본은 `orig/` 에 그대로 남아 되돌릴 수 있다.

## 라이트쎈 지시문 빠짐 — 이웃에서 빌려 붙이기는 **실패** (2026-10-22)

라이트쎈 A단계는 묶음 지시문 아래 문항이 여러 개 달리는데, 자를 때 지시문을 **같은 칸에서만**
찾은 탓에 **같은 줄 오른쪽 칸 문항이 지시문을 못 받았다** (`crop.py` 의 `cands` 조건).
학생이 「5/6」만 보고는 뭘 하라는지 알 수 없다. 51문항 (중2-1 32 · 중1-2 12 · 중3-2 5 · 중2-2 2).

같은 묶음 이웃의 지시문 띠를 떼어 붙여 보려 했다 (`light_inst.py` · `light_fix.py`).
**쓰면 안 된다** — 표본 6개 중 1개만 맞았다:
- 지시문이 이미 있는 문항에까지 붙여 **같은 문장이 두 번** 나왔다 (0861·0056·0622)
- 지시문이 아닌 것을 떼어 왔다 — 「B°」 배지(0534), **개념 상자의 그림과 소제목**(0730)
- 「빠졌는가」를 높이·덩어리 수·글 폭·이웃과의 화소 비교로 차례로 바꿔 봤지만
  칸이 다르면 글자 위치가 달라 번번이 빗나갔다.

**제대로 고치려면 원본 PDF 에서 다시 잘라야 한다.** 지금 남아 있는 것은
`2022개정 중2-2 수학 라이트쎈.pdf` 뿐이고 중1-2·중2-1·중3-2 문제편은 없다.
다시 자를 때는 쎈 공통수학2 의 `scripts/crop-ssen2/heads.py` 처럼 **읽는 순서대로 책 전체를
훑어** 지시문을 물려주면 칸과 쪽을 넘어가도 붙는다 (라이트쎈 `crop.py` 는 같은 칸만 봤다).

### 원본 PDF 로 고쳤다 (2026-10-22, 이어서)

PDF 는 바탕화면 `빅픽쳐/문제은행/` 아래에 다 있었다 (Downloads 만 보고 없다고 했던 것).
`light_inst_fix.py` 로 **PDF 에서 지시문 줄의 자리를 직접 찾아** 붙였다 — 29문항 고쳤다.

```
node   scripts/twins/byid.mjs <작업폴더>/cur <id,id,…>        # 지금 올라가 있는 그림
python scripts/twins/light_inst_fix.py <작업폴더> <PDF> <qnums_ok.json> x
node   scripts/twins/upload_fixed.mjs <작업폴더> <작업폴더>/cur/meta.json
```

함정:
- 지시문은 **반쪽을 가로지른다.** 단으로 나눠 찾으면 못 찾는다 — 한 칸에 문항이 가로로
  둘씩 들어가(0021 | 0022) 단 경계가 지시문보다 좁다.
- 지시문 머리 「[0021~0024]」 는 200dpi 에서 **폭 135px** 다. 번호(~75px)보다 넓지만
  150px 로 걸러내면 놓친다.
- **개념 상자의 형광펜 줄도 넓은 색 글자**라 지시문으로 잡힌다 (0176·0624). 눈으로 걸러냈다.

### 마무리 — 51개 중 46개 복구 (2026-10-22)

세 가지를 더 고치고 나니 중3-2(문제편 PDF 없음) 5개만 남았다.

1. **묶음이 칸·쪽을 넘어 이어진다.** 반쪽의 첫 문항은 지시문이 앞 칸에 있다
   (0004·0005 는 왼쪽 칸에서 시작한 묶음). → `find_band` 가 읽기 순서로 거슬러 올라간다.
2. **쪽 맨 위 개념 상자에도 넓은 색 글자가 있다** (0176·0624 가 그걸 물었다).
   → 지시문은 첫 문항보다 위로 멀리 가지 않으므로 그 선 위쪽은 버린다.
3. **형광펜 띠**도 넓은 색 덩어리다 → 지시문은 진한 글자(어두운 채널 150 미만)로 가린다.

**자르기가 망가진 6개**는 번호 검출이 엉뚱한 글자를 잡아 **좌표가 딴 데**를 가리킨 탓이었다
(0392 는 x678 인데 같은 반쪽의 다른 문항은 827, y 도 1309 가 아니라 850 이었다).
쪽을 직접 보고 자리를 잡아 다시 잘랐다 — 5개 복구, 중3-2 0382 는 PDF 가 없어 못 했다.
라이트쎈 그림에는 교재 번호를 넣지 않으므로 **번호 줄 아래부터** 잘랐다.

남은 것: **중3-2 5개**(0382·0520·0521·0538·0540) — 문제편 PDF 가 있어야 고칠 수 있다.

## 공통수학2 쌍둥이 대조 (2026-10-23 시작)

교재 일곱 권(쎈·유형만렙·마플시너지·풍산자 필수유형·풍산자 라이트유형·개념+유형 유형편/개념편)이
같은 유형표를 쓰므로 유형 하나를 통째로 모아 읽는다.

```
node scripts/twins/fetch.mjs  공수2-01-01 <폴더>
python scripts/twins/sheet2.py <폴더> <나갈이름>      # 2열 — 한 장에 12~16문항
node scripts/twins/apply.mjs  scripts/twins/findings/공수2-01-01.json
node scripts/twins/stat.mjs                           # 진행 상황
```

- `sheet2.py` 는 `sheet.py` 의 2열판이다. 한 장에 6문항밖에 못 담던 것을 12~16문항으로 늘렸다
  (쌍둥이는 보통 첫 두세 줄로 판가름 나므로 330px 에서 자르고 「…이어짐」을 적어 둔다).
- **유형이 잘못 붙은 문항이 자주 나온다.** 같은 파일의 `유형고침` 으로 함께 고친다.
  `apply.mjs` 는 유형을 고칠 때 **소단원도 따라 옮긴다**(안 그러면 문제은행 화면에서 엉뚱한 곳에 남는다).
- 유형을 고쳐야 묶을 수 있는 **교차 쌍둥이**는 파일을 둘로 나눠 **고치기 → 묶기** 차례로 적용한다.

### 진행 (공통수학2)

| 대단원 | 소단원 | 쌍둥이 붙은 문항 / 전체 |
|---|---|---:|
| I 도형의 방정식 | 01~08 | 1,965 / 2,499 (79%) |
| II 집합과 명제 | 09~13 | 1,371 / 2,002 (68%) |
| III 함수 | 14~16 | 591 / 973 (61%) |
| III 함수 | 17 유리식·유리함수 | 221 / 712 (31%) |
| III 함수 | 18 무리식·무리함수 | 231 / 595 (39%) |
| **합계** | **142개 유형 전부** | **4,301 / 6,781 (63%)** |

묶음 1,324개, 교재 3권 이상 걸친 묶음이 574개다. (2026-10-24 끝)

17·18 이 낮은 것은 일이 덜 된 게 아니다 — **유리식·무리식 계산 문제는 교재마다 식을
새로 지어내서 숫자만 다른 같은 문제가 원래 적다.** 그래프·점근선·대칭 쪽은 잘 맞는다.
`show.mjs` 로 묶음을 눈으로 확인할 수 있고, `clean.mjs` 는 유형을 고치며 혼자 남은 묶음을 비운다.

### 두 번 데었다 — 도구가 묶음을 망가뜨린 자리 (2026-10-24)

1. **`apply.mjs` 는 파일 하나씩 넣으므로 묶음이 서로 덮어쓴다.** 묶음번호는 「그 묶음에서
   가장 작은 id」라서, 뒤 유형 파일에서 앞 유형의 문항을 다시 적으면 **그 문항만 새 번호로
   옮겨 가고 원래 짝이 혼자 남는다.** 공통수학2에서 694문항이 이렇게 떨어져 나갔다.
   → `merge.mjs` 로 findings 전체를 읽어 **이어진 것끼리 한 묶음으로 합친다.**
   여러 유형에 걸쳐 작업한 뒤에는 `apply` 말고 `merge` 로 한 번 더 돌릴 것.

2. **`order` 없이 `range` 로 페이지를 넘기면 쪽마다 차례가 달라 행을 놓친다.**
   `clean.mjs` 가 짝의 한쪽을 못 읽어 **멀쩡한 쌍을 「혼자」로 보고 601문항을 비웠다.**
   `twin_id` 가 남아 있어 되살렸지만(`02_적용-쎈B묶음복구.sql`), 안 남아 있었으면 끝이었다.
   → 이 저장소의 **모든** 페이지 넘기기에 `.order('id')` 를 붙인다.
   `.in('id', ids)` 도 한 번에 700개 넘게 넣으면 **말없이 일부만** 들어간다 → 100개씩 끊는다.

### 알게 된 것

- **유형 번호가 통째로 밀린 구간이 있다.** 마플시너지 0440~0458(접선 19문항)이 06-05 에,
  0525~0546(평행이동 22문항)이 07-01 에, 0562~0580(대칭이동 19문항)이 08-01 에 몰려 있었다.
  풍산자 필수유형도 184~192·302~315·326~341 이 같은 식이었다. 합쳐 190문항 가까이다.
  유형 하나를 모아 읽다 보면 「이 교재 문항만 내용이 다르다」가 눈에 띄어 걸린다.
  소단원 맨 앞·맨 뒤 유형부터 읽으면 빨리 보인다.
- 유형만렙 0380~0387 은 **평행이동** drill 인데 번호만 보고 대칭이동으로 옮겼다가 되돌렸다.
  drill 은 그림에 답만 찍혀 있어(「(1,3)」) 지시문이 보이는 이웃 번호를 같이 봐야 한다.

- 마플시너지 유형 1-03·1-04·1-06 이 글자 맞추기에서 엉뚱한 소단원으로 갔다
  (「두 점 사이의 거리의 활용 - …」 이라는 긴 이름이 `01-05 두 점 사이의 거리의 활용` 과 너무 닮았다).
  `scripts/crop-mapl2/fix.py` 에 손으로 바로잡아 두었고, 이미 올라간 13문항은
  `retype_local.mjs` 로 고쳤다.
- **크롭이 잘려 있었다.** 가로 끝을 `W//2`·`0.965W` 로 어림잡은 탓에 마플시너지는 왼쪽 단이
  35px(91%), 유형만렙은 오른쪽 단이 43px 잘렸다. `gutter.py` 로 **쪽마다 단 사이 빈 띠를 재어**
  고치고 두 교재를 다시 올렸다. 대조를 시작하지 않았으면 못 찾았을 것이다.
