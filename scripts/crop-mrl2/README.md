# 유형만렙 공통수학2 — 스캔본에서 문항 뽑기

문제편 `q.pdf`(264쪽, **글자 없는 순수 스캔**), 해설 `sol.pdf`(172쪽, 글자층 있음).
문항은 **0001~1272**, 1,272개.

## 왜 이렇게 복잡한가

번호가 **세 가지 꼴**로 인쇄돼 있다. 하나만 보고 만들면 나머지를 통째로 놓친다.

| 구간 | 번호 생김새 | 놓치는 까닭 |
|---|---|---|
| A단계(개념 익히기) | 앞자리 0 은 **회색**, 뜻있는 자리만 초록 (`0001`) | 색만 찾으면 앞의 0 을 잃어 번호칸이 잘린다 |
| 유형 꼭지 | 네 자리 모두 남색, 옆에 난이도 동그라미 (`0168 하`) | 동그라미를 번호에 붙여 읽는다 |
| 유형점검·실력향상 | 네 자리 모두 **검정** (`0086 유형 11`) | **색으로는 아예 안 보인다** (60쪽 넘게 통째로 빠짐) |

여기에 더해 이 책에는 이런 함정이 있었다.

1. **번호는 왼쪽 정렬이다.** 글자 폭이 제각각이라(`0009` 와 `0011`) 오른쪽 끝이 10px 넘게 흔들린다.
   오른쪽 끝을 기준선으로 삼으면 안 된다 → 색 덩어리를 씨앗으로 **왼쪽으로 넓혀** 회색 0 까지 먹는다.
2. **단 안에 번호가 다시 2열로 놓이는 자리**가 있다 (`0626` 왼쪽 / `0627` 오른쪽).
   단마다 기준선을 하나로 못 박으면 오른쪽 것을 통째로 잃는다. 읽는 차례도
   (쪽, 단, y, x) 로 정렬하면 안 되고 **줄로 묶은 뒤 x 로** 정렬해야 한다 (y 가 1px 달라 뒤집힌다).
3. **묶음 지시문 `[0009~0011]`** 이 번호와 똑같이 생겼다. 사이의 `~` 는 **회색**이라 색으로는 못 가른다.
   → 맨 앞 글자 폭으로 가른다. `[` 는 **3~6px**, 숫자 `1` 은 **9~11px** 로 또렷이 갈린다.
   폭이 넓은지로만 가르면 `1121 대표문제` 처럼 꼬리표 붙은 번호를 지시문으로 버린다.
4. **스캔 얼룩**이 거의 모든 줄에 1~2 화소씩 있어 `any()` 로 글줄을 나누면 쪽 전체가 한 줄이 된다 → **화소 수**로 끊는다.
5. 쪽마다 세로로 난 **2px 짜리 스캔 줄**이 번호 앞자리로 잡혀 번호칸을 가로막는다 → 폭 4px 미만 조각은 버린다.
6. **`1111` 은 1이 넷이라 폭이 48px 밖에 안 된다.** 최소 폭을 50 으로 두면 통째로 놓친다.
7. **낱장이 뒤바뀌어 있다.** 인쇄 187·188쪽이 PDF 192·193쪽에 들어 있다 (`pgorder.py`).
   PDF 차례대로 번호를 매기면 그 구간 40문항이 통째로 어긋난다.

## 어떻게 푸는가

```
build.py   ── 한 번에 다 돈다
  1 후보 모으기   cand.py  = mdet2.py(색) ∪ mnum.py(생김새)
                 번호칸을 **반드시 네 칸**으로 쪼갠다(cut4) — 1이 섞이면 세 칸으로 세어진다
  2 글자 배우기   gl.py(뭉치 나누기) → read40.py(눈으로 0~9 붙이기) → selfread.py(본보기로 다시 배우기)
                 ※ 이 책은 번호가 세 빛깔이라 미리 배운 글꼴로는 못 읽는다. 스스로 배워야 한다
  3 차례 맞추기   align.py — 해설 PDF 가 알려 준 **1~1272 완전한 차례**와 통째로 정렬
  4 못 박고 채우기 anchor.py — 읽은 값이 **꼭 맞는 것만** 못으로 박고, 못 사이는 개수가 맞을 때만 채운다
  5 구조대       rescue.py — 그래도 빈 구간만 느슨한 기준으로 다시 훑는다
  6 자르기       cut.py
```

`align.py` 의 띠(band)는 **후보 수와 번호 수의 차이보다 넓어야** 한다. 좁으면 대각선이 띠 밖으로
나가 짝이 하나도 안 맞는다 (후보 1465 : 번호 1272 일 때 실제로 그랬다).

- 붙인 번호 **1,272 / 1,272** — 정확히 1..1272
- 차례 뒤집힘 **0**, 번호가 끊긴 쪽 **0**

(구조대가 후보를 보태면 줄번호가 밀리므로 반드시 함께 저장할 것).

## 정답 (`ans.py`)

해설 PDF 는 글자층이 있어 「0001 답 4」 처럼 정답이 들어 있다. 다만 출판사 수식 기호가 섞여
(`j2`=√2, `@`=제곱, `a|b`=분수) 글자 그대로는 못 쓴다. 그래서 **정답 줄을 그림으로 오리고**,
동그라미 번호·정수만 글자로도 적어 둔다.

함정:
- 「답」 글자가 쪽에 따라 **기호 글꼴**로 바뀌어 `'답'` 으로 못 찾는다 → 번호 **오른쪽 같은 줄**을 통째로 줍는다.
- 번호가 「010」+「2」 로 쪼개지고 사이에 탭이 끼기도 한다 → 스팬 차례가 아니라 **가로로 맞닿은 것**끼리 묶는다.
- 그래도 글꼴이 다른 쪽(해설 81쪽 등)이 있다 → `page.search_for('0851')` 로 자리를 얻는 뒷길을 둔다.
- **분수는 위아래로 포개져 있어** x 차례로 이으면 `2|3` 이 「23」이 된다 → 포개짐을 재서 그런 것은 글자로 안 적는다.
- 정답 아래로 풀이 한 줄이 딸려 온다 → 첫 **빈 줄**에서 끊는다(`cut_tail`).

결과: **1,272 / 1,272** (글자로도 적은 것 752, 나머지는 그림).

## 유형 분류 (`band.py` · `badge.py` · `tag2.py` · `build2.py`)

이 책의 가장 좋은 점은 **유형 이름을 책이 직접 달아 준다**는 것이다.
스캔본이라 글자는 없지만, 파란 띠를 잘라 모아 눈으로 읽으면 그대로 유형표가 된다.

| 재료 | 쓰임 |
|---|---|
| 파란 **유형 띠** (`band.py`) | 「유형 10 한 직선에 평행 또는 수직인 직선의 방정식」 → 유형 이름 |
| **대표 문제** 알약 (`badge.py`) | **유형이 여기서 시작한다** — 유형 경계를 정하는 가장 든든한 신호 |
| 「유형 08」 **꼬리표** (`tag2.py`) | 유형 점검 문항이 어느 유형인지 |
| 난이도 **동그라미** 빛깔 | 하(초록 H≤100) · 중(파랑 135~165) · 상(보라 ≥190) |
| 해설의 **구간 표시** (`secs.json`) | 「유형 완성 26~35쪽」 — 문항이 어느 구간인지 |
| 해설의 **채점 기준** | 서술형 문항 |

책은 중단원 10개에 유형 **173개**, 앱 `standard_types` 는 소단원 18개에 142개다.
띠에서 155개를 읽고, 18개는 **대표 문제 차례**로 메웠다 — 중단원마다 대표 문제 수와
유형 수가 정확히 맞아떨어져(6-01~04, 10-01~03 등) 자리로 메운 값도 믿을 수 있다.

### 함정

- 띠 색이 단원마다 다르다 → 빛깔을 가리지 말고 **채색 띠**로 찾는다.
- 「대표 문제」 알약은 **연보라(채도 13~50)** 로 아주 옅다. 알약 안 흰 글자가 세로줄을 끊으므로
  금을 0.25 로 낮추고 작은 틈은 잇는다.
- 꼬리표 숫자 위아래에 **장식 선**이 있다. 그걸 같이 자르면 글자가 망가져 **아무거나 읽힌다**
  (한동안 전부 「41」로 읽혔다). 잉크 많은 가운데 줄만 남겨야 한다.
- 유형 점검 끝에 **서술형이 붙어 유형 번호가 다시 1부터** 시작한다. 그 턱에서 보간하면
  앞 문항들이 한 유형에 뭉친다 → 턱 앞에서는 한 칸씩 올려 간다.

### 유형을 정한 방법 (1,272문항)

| 방법 | 수 | 정확도 |
|---|---:|---|
| 대표 문제 (유형 완성) | 647 | **정확** |
| 꼬리표 (유형 점검) | 128 | **정확** |
| 꼬리표 사이 보간 | 71 | 양 끝이 정확한 사이값 (표본 검사 일치) |
| 자리 비례 (개념 확인 386 · 실력 향상 40) | 426 | **소단원은 맞고 유형은 어림** |

개념 확인(A단계)은 소단원 머리(`01-1 두 점 사이의 거리`)만 있고 유형 표시가 없어
그 중단원의 유형을 차례대로 고르게 나눴다. 소단원은 맞지만 소단원 안의 유형은 어림이다.
나중에 소단원 머리를 읽어 더 좁힐 수 있다.
