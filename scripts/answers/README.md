# 개념+유형(비상) 정답 글자 뽑기

답지 화면이 그림 대신 **글자**로 나오게 하려고, 해설 PDF에서 정답을 읽어 `answer_text`에 넣는다.
(글자 정답이 있으면 객관식·숫자는 자동 채점까지 된다)

| 파일 | 하는 일 |
|---|---|
| `ky_yh.py` | **유형편** — 해설 뒤쪽 유형편 구간의 **빠른 정답표**(DIN-Bold 9.3pt)에서 읽는다. 자세한 풀이(10.1pt)와는 글자 크기로 가른다 |
| `ky_gn.py` | **개념편 유제** — 번호가 `08-` + `2`로 쪼개져 있고, 정답은 바로 뒤 **굵은 글꼴**(NPBIE·NPRUTB)로 온다. 풀이는 다른 글꼴이라 글꼴로 가른다 |
| `apply.py` | 뽑은 정답을 problems에 넣는다. 한글 수식 표기를 바꾼다(`@`→², `#`→³, `$`→⁴, 백틱→공백) |

## 주의점

- **2단 구성이다.** y좌표만으로 정렬하면 좌·우 칸이 섞여 번호가 들쭉날쭉해진다 → `(쪽, 칸, y)` 순으로 정렬할 것
- **책의 중단원과 학원 소단원이 다르다.** 공통수학1 개념편은 책이 18번 번호를 리셋하는데 학원 소단원은 10개다.
  그래서 번호로 키를 만들면 안 맞는다 → **순서로 짝지었다**(해설 유제 수와 DB 유제 수가 315로 정확히 같은 것을 확인하고,
  이미 들어 있던 정답과 대조해 내용이 같은 것까지 확인한 뒤 적용)
- 예제(필수예제)는 **풀이 전체가 정답**이라 한 줄로 못 뽑는다. ∴ 줄만 모으면 쪽 머리말이 섞이거나 빈 줄이 된다.
  예제는 지금처럼 **풀이 상자 그림**을 쓴다.

## 쓰는 법

```
python scripts/answers/ky_yh.py "<정답과해설 PDF>" out.json <유형편 시작쪽-1>
python scripts/answers/ky_gn.py "<정답과해설 PDF>" out.json <개념편 끝쪽>
python scripts/answers/apply.py out.json "개념+유형 유형편" 공통수학2
```

## 글자 층이 없는 교재 — 이미 잘라 둔 정답 그림을 «두 번 따로» 읽는다 (2026-10-27, 라이트쎈 중1-2)

해설 PDF 가 스캔 그림이면 위 방법(글꼴로 가르기)을 못 쓴다. 대신 문항마다 이미 잘라 둔
정답 그림(`problem-images` 의 `*_a.png`)을 읽는다. ocr-check 스킬(`~/.claude/skills/ocr-check`)의 방식이다.

1. 정답 그림을 번호표와 함께 한 장에 30개씩 모은다 → **판독1**(Claude)
2. **25개씩·다른 배율**로 다시 모은 묶음을 **다른 세션**이 판독1 을 보지 않고 읽는다 → **판독2**
3. 객관식(①~⑤)·숫자만 엄격히 대조한다. 다른 곳은 원본을 크게 키워 정한다
4. 숫자는 tesseract 로 한 번 더 읽고, 다른 곳만 원본을 눈으로 본다(옆 그림 조각에 잘 끌린다)
5. **객관식·숫자만** 글자 정답으로 바꾼다. 단위가 붙은 답(8 cm · 70° · 20 %)·O/X·이름·식은 그림 그대로
   (채점은 공백·쉼표만 지우고 글자 그대로 비교해서, 단위가 붙으면 학생이 「8」 이라고 써도 틀린다)

**★ 두 판독이 같아도 틀릴 수 있다 — 원본과 한 번 더 맞출 것 (2026-10-27).**
정답 그림 자체가 **옆 문항의 답**으로 잘려 있으면 두 판독 모두 그 그림을 정확히 읽어 같게 틀린다.
1-2 0800 이 그랬다(그림은 0801 의 ②, 풀이는 ③). 그래서 **그림 두 번 + 원본 한 번** 세 겹으로 맞춘다.
- 원본: 빠른정답 표(2-1 정답 PDF 앞 7쪽 · 3-2 정답 PDF 2~5쪽) 또는 풀이 본문의 「답」(1-2 · 2-2 는 빠른정답 표가 없다)
- 원본과 그림이 다른 곳은 원본 쪽을 눈으로 보고, 원본이 객관식·숫자면 **원본 값**을 넣는다(그림이 밀린 것)
- 밀림은 정답 자르기 스크립트가 번호를 하나 잘못 읽어 생긴다 — 2-1 은 끝자리 5 번호, 1-2·2-2 는 다음 번호가 빠진 문항 바로 앞에 몰렸다

| 교재 | 전체 | 객관식 | 숫자 | 그대로(그림) | 원본으로 바로잡음 | SQL |
|---|---|---|---|---|---|---|
| 라이트쎈 중1-2 | 645 | 180 | 57 | 408 | 1 (0800) | `라이트쎈_중1-2_정답.sql` · `라이트쎈_중1-2_0800_바로잡기.sql` |
| 라이트쎈 중2-1 | 898 | 270 | 149 | 479 | 21 | `라이트쎈_중2-1_정답.sql` |
| 라이트쎈 중2-2 | 748 | 201 | 145 | 402 | 8 | `라이트쎈_중2-2_정답.sql` |
| 라이트쎈 중3-2 | 376 | 115 | 67 | 194 | 0 | `라이트쎈_중3-2_정답.sql` |

전부 DB 적용·운영 QR 확인 완료(2026-10-27). 각 SQL 옆에 `_되돌리기` 가 있다.
**정답 그림 자체의 잘못 153건**(밀림·잘림·섞임)은 `라이트쎈_정답그림_오류.md` — 그림 정답으로 남는 107건은 다시 잘라야 한다.

## 글자 층이 **있는** 스캔 해설 — 빠른정답 표를 원본으로 (2026-10-27, 쎈 공통수학2)

해설 PDF 앞쪽의 **빠른정답 표**는 번호와 답이 한 줄에 같이 있어, 밀림이 생길 수 없는 원본이다.
그래서 정답 그림보다 이쪽을 먼저 읽는다. 세 겹으로 맞췄다.

| 겹 | 무엇 | 쓰는 것 |
|---|---|---|
| ① 원본 | 빠른정답 표를 번호와 함께 읽어 `read_*.json` → `merge_reads.py` 로 `표판독.json` | **정하는 값** |
| ② 기계 | `ocr_answers.py` (tesseract, 4배 확대+이진화) | **어디를 다시 볼지 알려 주는 깃발일 뿐** |
| ③ 그림 | `sheet_check.py` 로 「번호 · 넣을 값 · 정답 그림」을 한 칸에 나란히 놓고 눈으로 | 마지막 확인 |

**★ OCR 을 믿고 값을 정하지 말 것.** 쎈 공수2 에서 표와 OCR 이 다른 242건을 하나씩 봤더니
**전부 OCR 이 틀렸다** — 빼기표를 못 읽고(−12→12), 자릿수를 늘리거나 줄인다(36→3860, 116→6).
OCR 은 「여기를 다시 보라」는 깃발로만 쓴다.

### 차례

```
python scripts/answers/ocr_answers.py <정답그림폴더>                 # ② 기계
python scripts/answers/merge_reads.py <표판독폴더> <정답그림폴더>     # ①②를 맞댄다
python scripts/answers/make_sql.py 표판독.json DB현황.json 쎈 공통수학2 1 <나갈폴더>
node   scripts/answers/fetch_by_id.mjs <나갈폴더>/_검산목록.json <볼폴더>   # 바꿀 것만 그림 받기
python scripts/answers/sheet_check.py <볼폴더> <목록.json> <볼폴더>/check  # ③ 눈으로
node   scripts/answers/run_sql.mjs scripts/answers/<적용>.sql            # 적용 (그 .sql 그대로)
node --import ./scripts/ts-resolve.mjs scripts/answers/qr_check.mjs 쎈 공통수학2   # QR 채점 확인
```

- `run_sql.mjs` 는 **.sql 파일을 그대로 읽어** 돌린다(목록을 베껴 쓰지 않는다). 한 건이라도
  안 바뀌면 멈추고 종료코드 1 을 낸다 — id 하나를 없는 번호로 바꾼 사본에서 실제로 멈추는 것을 확인했다.
- `qr_check.mjs` 는 임시 시험지를 만들어 **진짜 `app/api/grade/[code]/route.ts` 의 GET()** 을 부르고,
  확인이 끝나면 그 시험지를 지운다.

| 교재 | 전체 | 객관식 | 숫자 | 그대로(그림) | 원본으로 바로잡음 | SQL |
|---|---|---|---|---|---|---|
| 쎈 공통수학2 | 1,323 | 404 | 363 | 556 | **56** | `쎈_공통수학2_객관식_바로잡기.sql` · `쎈_공통수학2_숫자정답.sql` |
| 쎈 공통수학1 | 1,316 | 426 | 440 | 450 | 0 | `쎈_공통수학1_숫자정답.sql` · `쎈_공통수학1_객관식정답.sql` |

바로잡은 56건은 꼴이 셋뿐이었다 — ②→③ 27 · ③→⑤ 17 · ⑤→③ 12.
예전에 기계로 읽어 넣을 때 동그라미 숫자를 헷갈린 자국이다. 채점 기록 0건이라 피해는 없었다.
정답 그림 자체가 잘못 잘린 13장은 `쎈_공통수학2_정답그림_오류.md`(글자 정답이 들어가 있어 급하지 않다).

### 빠른정답 표가 **없는** 책 — 이미 있는 객관식이 대조표가 된다 (2026-10-27, 쎈 공통수학1)

쎈 공통수학1 은 문제편·해설편 어디에도 빠른정답 표가 없다(해설 본문에 「답 ○○」가 문항마다 붙어 있다).
원본 표가 없으면 **정답 그림이 한 칸씩 밀려 잘렸는지**를 확인할 길이 없는 것처럼 보이지만, 있다.

**이미 DB 에 들어 있는 객관식 정답과 내 판독을 맞대면 된다.**
자르기가 밀렸다면 책 전체에 흩어진 그 수백 개가 줄줄이 어긋난다.
공수1 은 425개 중 **425개가 일치**해서 자르기가 맞다는 것이 확인됐다(공수2 는 같은 대조로 56개를 찾아냈다).

그래서 빠른정답 표가 없는 책은 이렇게 간다.

```
node   scripts/answers/fetch_by_id.mjs 쎈/공통수학1 <그림폴더> --all     # 정답 그림 전부
python scripts/answers/ocr_answers.py <그림폴더>                          # ② 기계
python scripts/answers/sheet_read.py  <그림폴더> <읽을폴더>               # ① 눈 (값을 안 적는다)
#   → 읽은 것을 r00.json … 으로 적고 판독1.json 으로 합친다
python scripts/answers/make_sql.py 판독1.json db.json 쎈 공통수학1 1 <나갈폴더>
```

- `sheet_read.py` 는 **넣을 값을 그림 옆에 적지 않는다** — 값이 보이면 그 값에 눈이 끌려 그림을 그대로 못 읽는다.
  값을 적어 나란히 보는 것은 마지막 확인(`sheet_check.py`) 때만 한다.
- OCR 과 다른 곳만 골라 크게 다시 본다(공수1 은 440개 중 105개가 달랐고 **전부 OCR 이 틀렸다**).

### ★ 적용 도구가 조용히 반만 적용한 일 (2026-10-27)

`run_sql.mjs` 가 `answer_kind` 를 「number 인가? image 인가?」로만 찾고 있어서,
`answer_kind='choice'` 로 적힌 SQL 을 돌렸더니 **글자 정답만 들어가고 종류는 image 인 채로 남았다**(0383).
문항 수는 맞아서 검사도 통과했다. 고친 뒤로는
  · 적힌 종류를 그대로 읽고(종류를 하나씩 적어 두지 않는다)
  · 바꾼 뒤 값을 **되읽어** 종류와 글자가 둘 다 들어갔는지 확인한다.
**수만 세는 검사는 반만 적용된 것을 못 잡는다.**

## 객관식인데 정답이 숫자로 들어간 1,839문항 (2026-10-27 발견)

RPM 1,361 · 개념+유형 478 문항이 `answer_kind='choice'` 인데 `answer_text` 가 `3`·`2,5` 처럼 숫자다.
QR 채점은 ①~⑤ 글자만 읽어서 **무엇을 골라도 오답**이 된다(채점 기록 0건이라 피해는 없었다).
`객관식_숫자정답_바꾸기.sql` (+ `_되돌리기`) 로 ①~⑤ 로 바꾼다. 새 교재를 넣을 때 객관식 정답은 반드시 ①~⑤ 로 넣을 것.
