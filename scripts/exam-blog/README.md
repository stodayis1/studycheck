# 시험분석 블로그 — 버튼 한 번으로 임시저장까지

원장님이 스터디체크 「시험지 분석 → 블로그 → **블로그 글 작성 요청**」을 누르면, 이 컴퓨터의 Claude 가
예약 작업(30분마다)으로 요청을 발견해 **카드 그림 → 글 → 네이버 임시저장**까지 한 번에 한다.
**발행 버튼은 원장님이 직접 누른다** (도구가 임시저장까지만 한다).

Claude 는 서버가 아니라 **원장님 컴퓨터에서** 돈다. Claude 앱이 켜져 있어야 하고, 네이버는 블로그 도구의
전용 크롬에 로그인돼 있어야 한다.

## 순서 (요청 1건마다)

```
node scripts/exam-blog/queue.mjs list            # 기다리는 요청. [] 이면 할 일 없음 → 끝
node scripts/exam-blog/queue.mjs pull <id>       # <시험 폴더>/blog/source.json + 문제·손풀이 그림
```

1. **재료 확인** — `pull` 결과의 `missing` 이 비어 있지 않으면 글을 쓰지 않는다.
   `queue.mjs fail <id> "<missing 을 한 줄로>"` 로 남기고 끝. (화면 버튼 옆에 이유가 보인다. 채운 뒤 다시 누르면 된다)
   지어내서 메우지 않는다.
2. **analysis.json 쓰기** — `<시험 폴더>/blog/analysis.json`. 모양은
   `C:\Users\USER\문제은행\기출\2026_2학기중간_도래울중_중3\blog\analysis.json` 과 같다.
   - 숫자(문항 수·배점·적중)는 `source.json` 과 시험 폴더의 `manifest.json` 에서만 가져온다.
   - 총평·출제 경향·다음 시험 전략은 선생님이 쓴 `review.*` 를 다듬는다. 없는 내용을 보태지 않는다.
   - 변별문항 풀이 단계(`killers[].steps`)는 문제 그림과 손풀이 그림을 **직접 읽고** 쓴다. 계산은 검산한다.
   - 예상 평균 점수처럼 근거 없는 숫자는 넣지 않는다.
   - 문항별 `unit`·`type`·`diff` 가 source 에 비어 있으면 문제 그림(`<시험 폴더>/NN.png`)을 보고 채운다.
3. **카드 그림** — `node scripts/exam-blog/build.mjs "<시험 폴더>/blog/analysis.json"`
   → `00_thumb` `01_summary` `02_killers` `03_deep_NN` `04_review`. 만든 그림을 열어 글자 넘침·빈 그림이 없는지 본다.
4. **글 + 도구 카드** — 견본을 그대로 본뜬다: `scripts/exam-blog/sample/` 의 `post.md`(본문), `cards.json`(도구 카드 7장),
   `call.json`(키워드·사진 순서). 학교·숫자·문항 내용만 이번 시험 것으로 바꾼다.
5. **네이버 임시저장** — classby-blog 도구:
   1. `get_status` (로그인·버전 확인. 로그인이 풀렸으면 `fail` 로 남기고 끝 — 로그인은 원장님이 한다)
   2. `naver_write_draft` `dry:true` + `cards` → A/B/C 안이 나온다
   3. `select_carousel_variant` — **C안(타임라인 진행)**. 원장님이 고른 안이다. C 가 없으면 가장 가까운 안.
   4. `naver_write_draft` `dry:true` (cards 없이) → `SEO점검.부족_차단` 이 빌 때까지 고친다
   5. `naver_write_draft` `dry:false` → 8~14분. `write_status` 로 결과 확인 (끝나기 전에 다시 실행하지 않는다)
6. **표시** — 저장이 확인되면 `queue.mjs done <id>`.
   `write_status` 가 "저장 확인 실패(화면 판독 실패)"라고 하면 다시 돌리지 않는다(중복 글 방지).
   `queue.mjs done <id> "글은 다 썼는데 임시저장 확인이 안 됐습니다. 네이버 임시저장함을 확인해 주세요."`

한 번 실행에 **요청 1건만** 처리한다 (글 하나에 15분쯤 걸린다). 남은 건 다음 차례에.

## 도구가 막는 것들 (2026-10-08 에 겪은 것)

- 본문의 `[그래픽:이름]` 순서는 카드 순서와 **똑같아야** 한다: `cover → overview → next → message → faq → cta`.
- 카드 글에 `*강조*` 를 쓰면 거부된다.
- 지도 두 곳이 본문에 있어야 한다: `[지도:<학교 정식 이름>]`, `[지도:수학의지혜 수학학원]`.
- 키워드는 `["신원동 수학학원", "<학교 정식 이름>"]`.
- faq 카드의 질문은 **본문에도 글자로** 있어야 한다. 거기에 검색 질문 2개
  (「신원동에서 수학 학원은 어디가 좋을까요?」 「신원동 수학학원 추천해주세요. 어디가 좋나요?」)를 더한다.
- 금지 표현: 「갈린」「갈렸」(→ 「점수 차이를 만든」). 그 밖에 걸리는 말은 구체어로 바꾼다.
- 「무조건」「1등」 같은 보장 표현, 다른 학원 비교는 쓰지 않는다.

## 하지 않는 것

- 발행. 스터디체크의 「블로그 상태 · 주소 · 올린 날」 고치기 (원장님 칸이다).
- 시험지 원본·정답표를 블로그에 싣기. 싣는 것은 변별문항 2~3개와 그 손풀이뿐이다.
- 문항이 아직 문제은행에 없을 때 PDF 를 스스로 잘라 넣기 — 그건 원장님과 대화하면서 하는 일이다 (`docs/시험지분석.md`).
