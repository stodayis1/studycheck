# 스터디체크 요청 처리 — 적중 대조 · 카드뉴스 · 블로그 글

원장님이 스터디체크 「시험지 분석」에서 **요청 버튼**을 누르고 Claude 에게 **「요청 처리해줘」** 라고 하면,
요청 목록을 읽어 차례로 끝까지 처리한다. 묻지 않고 끝까지 간다 — 버튼을 누른 것이 승인이다.

| 요청 (`kind`) | 버튼이 있는 곳 | Claude 가 하는 일 |
|---|---|---|
| `match` 적중 대조 | 「이너프원 매칭」 탭 | 기출 ↔ 이너프원 그림 대조 → 매칭 넣기 |
| `cards` 카드뉴스 | 「블로그」 탭 카드뉴스 칸 | 카드에 들어갈 글(analysis)을 써서 올린다 → 화면이 카드를 그린다 |
| `blog` 블로그 글 | 「블로그」 탭 | 카드 그림 → 글 → 네이버 **임시저장** (발행은 원장님이 직접) |

왜 버튼이 서버에서 바로 AI 를 부르지 않나: 그러면 쓸 때마다 사용료가 따로 나간다. 원장님이 2026-10-10 에
"적중 대조와 카드뉴스는 Claude 에게 시킨다"고 정했다 (서버가 부르는 길은 코드에 남아 있지만 화면에서 뺐다).
Claude 는 서버가 아니라 **원장님 컴퓨터에서** 돈다. 버튼이 Claude 를 깨울 수는 없다 — 원장님이 말을 걸거나,
예약 작업(`예약작업_지시문.md`)이 주기적으로 목록을 봐야 한다. (예약은 지금 쓰지 않는다. 원장님 결정 2026-10-08)

```
node scripts/exam-blog/queue.mjs list            # 기다리는 요청 (kind · 시험). [] 이면 할 일 없음 → 끝
```

같은 시험에 여러 요청이 있으면 `match → cards → blog` 순서로 한다 (앞의 것이 뒤의 재료다). 목록이 그 순서로 나온다.
하나가 끝날 때마다 `done`/`fail` 을 남긴다. 화면 버튼 옆에 그 결과가 보인다.

## match — 적중 대조

1. 문항이 문제은행에 있어야 한다 (`exam_questions.problem_id`). 없으면 `fail <id> --kind match "먼저 문항 넣기를 해 주세요"`.
2. 기출 문항 그림을 받는다: `queue.mjs pull <id>` 는 변별문항만 받으므로, 전체는 시험 폴더(`C:\Users\USER\문제은행\기출\<시험>\NN.png`)에
   이미 있으면 그걸 쓰고, 없으면 보관함 `problem-images` 의 `exam/<시험지 id>/<문항 id>.png` 를 내려받는다.
3. 단원별로 3~4묶음으로 나눠 **서브에이전트로 동시에** 대조시킨다. 묶음 그림은
   `C:\Users\USER\문제은행\이너프원\2026-2학기\sheets\<교재>\NNN.png` (10문항씩, 칸마다 빨간 `[S세트-번호]`).
   볼 교재: 중2 → 중2 상·중·하, 중3 신원중 → 신원중3 1·2권 A·B, 중3 그 밖 → 타학교중3 1·2권.
   결과는 `matches_A.json …` 로 받는다: `{"matches":[{"no","book","set","pno","level","memo"}]}`.
4. **직접 확인한다.** 문항마다 상위 2개 매칭을 그림으로 나란히 놓고(기출 | 이너프원 crops) 정도를 고친다.
   묻는 것이 다르면 「매우 유사」를 「유형 유사」로 낮춘다. 부풀리지 않는다.
5. `node scripts/exam-paper/add-matches-by-set.mjs <id> <matches.json>` 로 적중률을 먼저 보고, `--go` 로 넣는다.
6. `queue.mjs done <id> --kind match "적중률 96% (23문항 중 22문항). 쌍둥이 9·13·19번, 적중 아님 17번"`
   원장님께도 적중률 · 쌍둥이 · 약한 적중 · 적중 아님 번호를 알린다. 적중 기준은 유형 유사까지.

## cards — 카드뉴스

1. `queue.mjs pull <id>` → `missing` 이 비어 있지 않으면 `fail <id> --kind cards "<빠진 것>"`. 지어내서 메우지 않는다.
2. `<시험 폴더>/blog/analysis.json` 을 쓴다. 모양은 `lib/examBlogAnalysis.ts` 가 만드는 것과 같다
   (견본: `C:\Users\USER\문제은행\기출\2026_2학기중간_도래울중_중3\blog\analysis.json`). 다른 점 하나:
   **그림 열쇠는 `"image": "q:<번호>"`, `"solution": "s:<번호>"`** — 화면이 이 열쇠로 그림을 찾는다.
   - 숫자(문항 수 · 배점 · 적중)는 `source.json` 에서만. 배점을 모르는 문항은 `pts: 0` (카드가 배점을 숨긴다).
   - 총평 · 경향 · 전략 · 한마디는 선생님이 쓴 `review.*` 를 다듬는다. 없는 주장을 보태지 않는다.
   - `killers[].steps` 는 **정확히 4개**. 문제 그림과 손풀이를 직접 읽고 쓰고 검산한다.
   - 예상 평균 · 등급컷 같은 근거 없는 숫자, 보장 표현, 다른 학원 비교는 쓰지 않는다.
   - 글자 수는 `lib/examBlogAnalysis.ts` 의 `SPEC` 을 지킨다 (카드 칸에 들어가야 한다).
3. `node scripts/exam-blog/queue.mjs put-analysis <id> "<시험 폴더>/blog/analysis.json"` → 스터디체크에 올라간다.
4. 글자 넘침 확인: 열쇠를 로컬 그림으로 바꾼 사본으로 `build.mjs` 를 돌려 카드를 열어 본다 (화면과 같은 양식이다).
5. `queue.mjs done <id> --kind cards`. 원장님은 「블로그」 탭에서 카드를 보고, 「글 고치기」 · 「모두 내려받기」 를 한다.

## blog — 블로그 글 (네이버 임시저장)

```
node scripts/exam-blog/queue.mjs pull <id>       # <시험 폴더>/blog/source.json + 문제·손풀이 그림
```

1. **재료 확인** — `pull` 결과의 `missing` 이 비어 있지 않으면 글을 쓰지 않는다.
   `queue.mjs fail <id> "<missing 을 한 줄로>"` 로 남기고 끝. (화면 버튼 옆에 이유가 보인다. 채운 뒤 다시 누르면 된다)
2. **analysis.json** — `pull` 결과에 `analysisFromApp` 이 있으면(카드뉴스가 이미 있고 원장님이 글을 고쳤을 수 있다)
   **새로 쓰지 말고 `analysis.app.json` 을 그대로 쓴다**: `analysis.json` 으로 복사하고, 그림 열쇠만 바꾼다
   (`"image": "q:6"` → `pull` 이 알려 준 `images[6]`, `"solution": "s:6"` → `solutions[6]`). 블로그 본문도 이 글에 맞춘다.
   없으면 위 「cards」 2번대로 쓴다 (열쇠만 로컬 그림 경로로).
3. **카드 그림** — `node scripts/exam-blog/build.mjs "<시험 폴더>/blog/analysis.json"`
   → `00_thumb` `01_summary` `02_killers` `03_deep_NN` `04_review`. 만든 그림을 열어 글자 넘침·빈 그림이 없는지 본다.
4. **글 + 도구 카드** — 견본을 그대로 본뜬다: `scripts/exam-blog/sample/` 의 `post.md`(본문), `cards.json`(도구 카드 7장),
   `call.json`(키워드·사진 순서). 학교·숫자·문항 내용만 이번 시험 것으로 바꾼다.
5. **네이버 임시저장** — classby-blog 도구:
   1. `get_status` (로그인·버전 확인. 로그인이 풀렸으면 `fail` 로 남기고 끝 — 로그인은 원장님이 한다)
   2. `naver_write_draft` `dry:true` + `cards` → A/B/C 안이 나온다
   3. `select_carousel_variant` — **C안(타임라인 진행)**. 원장님이 고른 안이다. C 가 없으면 가장 가까운 안.
   4. `naver_write_draft` `dry:true` (cards 없이) → `SEO점검.부족_차단` 이 빌 때까지 고친다
   5. `naver_write_draft` `dry:false` → 8~14분. `write_status` 로 결과 확인 (끝나기 전에 다시 실행하지 않는다)
6. **표시** — 저장이 확인되면 `queue.mjs done <id>`.
   `write_status` 가 "저장 확인 실패(화면 판독 실패)"라고 하면 다시 돌리지 않는다(중복 글 방지).
   `queue.mjs done <id> "글은 다 썼는데 임시저장 확인이 안 됐습니다. 네이버 임시저장함을 확인해 주세요."`

### 도구가 막는 것들 (2026-10-08 에 겪은 것)

- 본문의 `[그래픽:이름]` 순서는 카드 순서와 **똑같아야** 한다: `cover → overview → next → message → faq → cta`.
- 카드 글에 `*강조*` 를 쓰면 거부된다.
- 지도 두 곳이 본문에 있어야 한다: `[지도:<학교 정식 이름>]`, `[지도:수학의지혜 수학학원]`.
- 키워드는 `["신원동 수학학원", "<학교 정식 이름>"]`.
- faq 카드의 질문은 **본문에도 글자로** 있어야 한다. 거기에 검색 질문 2개
  (「신원동에서 수학 학원은 어디가 좋을까요?」 「신원동 수학학원 추천해주세요. 어디가 좋나요?」)를 더한다.
- 금지 표현: 「갈린」「갈렸」(→ 「점수 차이를 만든」). 그 밖에 걸리는 말은 구체어로 바꾼다.
- 「무조건」「1등」 같은 보장 표현, 다른 학원 비교는 쓰지 않는다.

## 하지 않는 것

- 네이버 발행. 스터디체크의 「블로그 상태 · 주소 · 올린 날」 고치기 (원장님 칸이다).
- 시험지 원본·정답표를 블로그에 싣기. 싣는 것은 변별문항 2~3개와 그 손풀이뿐이다.
- 이미 있는 매칭 지우기. 같은 (기출 번호 · 이너프원 문항)은 건너뛰고 새것만 더한다.
- 문항이 아직 문제은행에 없을 때 PDF 를 스스로 잘라 넣기 — 「문항 넣기」는 원장님이 화면에서 한다 (`docs/시험지분석.md`).
