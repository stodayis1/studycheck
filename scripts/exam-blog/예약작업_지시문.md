## 1. 요청 확인 (먼저, 빠르게)
작업 폴더 C:\Users\USER\studycheck 에서:
  node scripts/exam-blog/queue.mjs list
결과가 [] 이면 아무것도 하지 말고 "요청 없음" 한 줄만 남기고 끝낸다. 다른 일은 하지 않는다.

## 2. 요청이 있으면 — 가장 오래된 1건만 처리
반드시 scripts/exam-blog/README.md 를 처음부터 끝까지 읽고 그 순서대로 한다. 요약:
1) node scripts/exam-blog/queue.mjs pull <id> → <시험 폴더>/blog/source.json 과 문제·손풀이 그림이 모인다.
2) 결과의 missing 이 비어 있지 않으면 글을 쓰지 않는다. node scripts/exam-blog/queue.mjs fail <id> "<빠진 것들을 한 줄로>" 를 실행하고 끝낸다. 없는 내용을 지어내 메우지 않는다.
3) <시험 폴더>/blog/analysis.json 을 쓴다. 모양은 C:\Users\USER\문제은행\기출\2026_2학기중간_도래울중_중3\blog\analysis.json 과 같게. 숫자는 source.json·manifest.json 에서만, 총평·전략은 선생님이 쓴 review 를 다듬어서, 변별문항 풀이 단계는 문제 그림과 손풀이 그림을 직접 읽고 검산해서 쓴다. 예상 평균 점수 같은 근거 없는 숫자는 넣지 않는다.
4) node scripts/exam-blog/build.mjs "<시험 폴더>/blog/analysis.json" 으로 카드 그림을 만들고, 그림을 열어 글자 넘침·빈 그림이 없는지 확인한다.
5) scripts/exam-blog/sample/ 의 post.md · cards.json · call.json 을 본떠 이번 시험의 글과 도구 카드를 만든다. 문체는 견본처럼 짧은 문장, 학부모 대상, 과장·보장 표현·타 학원 비교 금지.
6) classby-blog MCP 도구로 임시저장한다 (도구가 지연 로딩이면 ToolSearch 로 mcp__classby-blog__get_status, naver_write_draft, select_carousel_variant, write_status 를 불러온다): get_status → naver_write_draft(dry:true, cards 포함) → select_carousel_variant 로 C안(타임라인 진행) → naver_write_draft(dry:true, cards 없이)를 SEO점검.부족_차단 이 빌 때까지 고침 → naver_write_draft(dry:false) → 8~14분 뒤 write_status 로 확인. 진행 중에 다시 실행하지 않는다. README 의 「도구가 막는 것들」을 미리 지킨다.
7) 저장이 확인되면 node scripts/exam-blog/queue.mjs done <id>. write_status 가 "저장 확인 실패(화면 판독 실패)"라고 하면 재시도하지 말고(중복 글 방지) node scripts/exam-blog/queue.mjs done <id> "글은 다 썼는데 임시저장 확인이 안 됐습니다. 네이버 임시저장함을 확인해 주세요." 로 남긴다.
8) 네이버 로그인이 풀렸거나 도구가 막히는 등 끝까지 못 가면 node scripts/exam-blog/queue.mjs fail <id> "<이유를 쉬운 말로>" 를 남긴다. 로그인·인증은 원장님만 한다.

## 절대 하지 않는 것
- 네이버 발행 버튼 누르기, 글 삭제.
- StudyCheck 데이터 지우기·고치기 (queue.mjs 의 done/fail 표시 외에는 DB 를 건드리지 않는다). 코드 수정·커밋·push 도 하지 않는다.
- 시험지 원본·정답표를 글에 싣기. 싣는 것은 변별문항 2~3개와 그 손풀이뿐.
- 한 번 실행에 2건 이상 처리하기.
