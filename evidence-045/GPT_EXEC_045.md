## 2. R045-01/02: 저장 SQL을 실행 가능한 안전 경계로

- `apply_learning_action()`는 **서버 전용**이다. PUBLIC/anon/authenticated 직접 실행 차단과 필요한 서버 역할 실행권을 명시한다. 역할 기본권한에 기대지 않는다. 같은 객체의 기존 직접 권한도 다룬다. 전체 프로젝트 기본권한은 건드리지 않는다.
- SECURITY DEFINER 호출자/역할 경계, payload 형식·문맥·참조 소유권을 검사한다. 함수 소유자 `current_user`를 호출자라고 가정하지 않는다. 서버가 인증·활성 학생·기존 과제 배정·허용 문항·run 범위를 확정하고 서버 채점을 한다. 학생이 보낸 graded/producer/범위를 신뢰하지 않는다.
- `p_graded`를 전달받는 설계이면 ‘DB가 채점한다’고 쓰지 않는다. DB가 직접 채점할 범위를 택할 경우에도 확인 문항/영상 권한의 검증이 누락되면 안 된다.
- **동일 행동 키의 중복/충돌 판정 이전에 시도를 생성하거나 updated_at를 바꾸지 않는다.** 문항·과제/source·run·kind·구간 등 의미 문맥을 보존한다. 행동 식별 키에 대한 동시 처리를 직렬화/원자적으로 재판정한다.
- 같은 학생/문항이라도 다른 과제/재학습 시도는 구분한다. 기존 시도의 의미를 잃는 유일키를 수정한다.
- 충돌 수신을 감사용으로 보존하는 것과 학습 상태 변경을 구분한다. 부분 유일키 방향은 유지 가능하나 그것만으로 동시성/인가가 해결됐다고 하지 않는다.
- `v_changed || 'payload'`/`'occurred_at'`는 명시적 `array_append` 등으로 바꾸고 엔진에서 해당 분기를 시험한다.
- 첫 applied와 duplicate의 채점·attempt 반환 모양을 맞춘다.
- 재실행/미지의 기존 동명 객체 상황은 예상 정의를 확인하고 모르면 중단한다. 기존 운영 표·정책을 재작성하거나 풀지 않는다.
- rollback은 차단·이번 run+고정 시험계정 정리·기능 철수 단계를 구분한다. 역할 권한을 빠짐없이 회수하고 범위 밖 삭제는 금지한다. 원장님용 최종 실행본은 psql 전용 `\set`/`:'var'` 편집을 요구하지 않는 형태로 만든다. 지금 원장님에게 실행을 요구하지 않는다.

## 3. R045-03/04: 실제 API→콘텐츠→저장→재조회 경로를 잇는다

- 운영 모드의 `/api/learning/act`가 무조건403, 직원 허용 뒤 teacher가501인 상태를 ‘연결 완료’로 남기지 않는다.
- demo 보호를 없애는 것이 아니라 **모드별 의존성**을 주입한다. 엔진이 시연 상수·testStore를 운영에서도 직접 부르지 않게 한다. 운영 설정 누락은 데모로 대체하지 않는다.
- 기존 학생 인증을 재사용한다. session_uid 조회 오류와 정상 0행을 구분하고, 활성 학생/역할 규칙을 유지한다. user_id fallback은 기존 정책과 일치할 때만 사용한다. 임의 client studentId로 접근하지 않는다.
- 기존 배정된 과제에서 첫 세트 허용 문항만 사용한다. 타 학생/미배정/범위 밖 요청은 콘텐츠 읽기·저장 전에 차단한다.
- 운영 문제 이미지 표시 경로, 기존 YouTube 플레이어 연결, 기존 수식 렌더링을 재사용한다. HTML video에 YouTube embed 주소를 넣는 상태로 ‘실영상 재생 지원’이라 하지 않는다. 해설 이미지 경로는 학생 DTO에서 제외한다.
- `forStudent()`는 answer만 빼는 spread 대신 **명시적 학생 허용 필드**를 사용한다. 모범답·해설/정답 경로·내부 검수 사유·서버 필드는 나오지 않게 한다.
- `loadAttempt()`가 task/source를 올바르게 복원하게 한다. 도움 시점의 자산ID·버전·승인구간을 보존하고 빈 값/full로 만들어 복원하지 않는다. 원요청과 서버 검증 관측의 의미를 분리한다.
- `problemId` bigint는 문자열을 유지한다. 객관식 자유 입력은 유효 토큰 검사 후 채점한다 (`30`을 `③`로 판정하면 안 됨). 미지원은 오답이 아니라 명시적 미지원이다.
- 장면 start/end는 null·빈문자열·boolean을 Number로 변환하지 않는다. 정확한 수치·순서·길이 범위를 검사한다. 첫 장면이라는 이유로 추천 구간으로 삼지 않는다.
- 정답이 학생에게 나타나지 않는 것, 과제·재풀이·도움 기록이 재로그인 뒤 동일한 근거로 복원되는 것, 강사 요약/draft의 일치까지 같은 route로 시험한다.

## 4. 콘텐츠 검수 기준은 다음으로 확정한다

### 공개 목적 구분

‘현재 원문 답을 대신 주지 않는 질문 도움’과 ‘정식 개념/증명 강의’를 구분한다. 원문 최종 답·정답 번호·완성 풀이가 그대로 드러나는 자료는 질문 도움으로 승인하지 않는다. 공식·다른 대표예제의 정답이 있다는 이유로 모든 강의를 금지하지 않는다.

구간 UI는 전체 파일 접근통제를 대신하지 않는다. 실제로 전달하는 전체 파일/연결 범위를 기준으로 검수한다. 첫 시범은 그 범위가 안전한 기존 자산/카드로 선정하며 새 스트리밍 제품을 만들지 않는다.

### 확인문제

- 기본은 **검수된 기존 문제은행의 다른 문항**. 첫 읽기 세트 최대10개 안에서 원문/확인 역할을 나눈다.
- 영상에서 답을 이미 본 동일 문제의 정답을 독립 해결로 세지 않는다. 개념03의 Check 정답 때문에 영상 전체를 금지하지 않는다.
- 증명/이유 확인은 짧은 근거 질문·가정 선택·빠진 단계 등을 쓸 수 있다. 판정 기준 없으면 맞음·숙달을 만들어 기록하지 않는다.
- 확인 성공, 원문 도움후 재풀이 성공, 시간차 재확인, 숙달을 계속 분리한다.

### 검수 입력

서버 전용의 버전 있는 소수 승인 명세로 첫 세트를 연결해도 된다. 새 테이블/전용 검수 시스템 완성이 선행조건이 아니다. 개발자가 원문/자산/구간/전체 전달 범위/확인문제 근거를 준비하고 윤T 또는 지정자가 묶음 확인한다. 전체185편/550구간 검수, 학생별 매번 수동검수를 요구하지 않는다.

후보3개·두유형 상한은 유지한다. 대표예제 우선·개념 글 안내는 브리핑에 기록된 방침으로 존중한다. 세 번째 대체 후보를 쓰려면 적합성 근거와 선택변경을 남기며 네 번째로 추가하지 않는다. 재생/학생접근/검수/확인문제 상태는 각각 증거로 채운다. 학생접근은 매 요청의 학생/과제 범위다.

## 5. PostgreSQL은 폐기형 로컬에서 먼저 시험한다

사용 가능한 native PostgreSQL17 또는 공식 개발용 컨테이너로 격리 시험한다. 설치가 필요하면 앱 package.json과 분리된 시험환경에 한정한다. 키·운영설정·실제 데이터 사용 금지, 외부 포트/터널 공개 금지. 운영 DB를 첫 쓰기 시험장으로 쓰지 않는다.

필수: 설치/재적용, 기본 execute 직접권한 유무 두 설정, anon/authenticated 거부, 서버 허용, 학생A/B 범위, 정상/동일중복/같은ID다른문맥/충돌저장, 동시요청, 중간실패 전체되돌림, readback와요약일치, rollback범위. 엔진/fixture/명령/종료코드를 제출한다.

GPT는 이번에 PG엔진 실행을 완료하지 못했다. 따라서 동봉 증거는 SQL 엔진 통과 로그가 아니다. Docker/PG를 쓸 수 없으면 무엇이 없는지 구체적으로 보고하되, **운영 첫 실행으로 대신하겠다고 하지 말라.** 나머지 route연결 작업을 멈추지도 말라.
