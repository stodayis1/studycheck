# 매쓰홀릭 붙여넣기 규칙 고치기

원장님이 매쓰홀릭 학습지 제목·종류 규칙을 말씀하시면(「월간평가는 코어테스트로 올리면됨」,
「레벨 없고 00회차는 이너프원이야」) **네 곳**을 같이 고친다. 한 곳만 고치면 조용히 어긋난다.

## 고칠 곳 (순서대로)

| 순서 | 파일 | 무엇 |
|---|---|---|
| ① | `lib/matholic.ts` | 판정 함수 — 여기가 유일한 규칙 자리 |
| ② | `app/teacher/assignments/matholic/page.tsx` | 그 판정을 **실제로 쓰는** 곳 (읽기 + 저장) |
| ③ | `scripts/matholic-check.ts` | 새 규칙마다 검사 한 줄 |
| ④ | `app/teacher/manual/page.tsx` | 선생님이 읽는 안내 — 제목 쓰는 법이 바뀌면 반드시 |

①만 고치고 ②를 안 고치는 실수가 가장 많다. 함수는 고쳤는데 화면이 안 부르면
**에러가 안 나고** 규칙이 없는 것과 똑같다. 고친 함수의 이름으로 `grep` 해서
부르는 자리를 눈으로 확인한다.

## 판정 함수 지도 (`lib/matholic.ts`)

- `coreTestRound(row)` → 평가관리로 보낼 것인가, 몇 회차인가
- `isEnoughOne(row)` → 아예 안 넣을 것인가 (이너프원)
- `isDailyTest(row)` → 학습일지 데일리테스트 칸 **(레벨보다 먼저 — 2026-11-10)**
- `isWrongNote(row)` → 오답 학습지인가
- `matchTextbook(title, books)` → 제목에 든 **교재 이름** (목록은 `textbook_catalog`)
- `isTextbookLinked(row, books)` → 쌍둥이인가 (「교재」·「교과서」·쪽 범위·교재 이름)
- `worksheetTypeOf(row)` → `main`(레벨) · `similar`(오답) · `twin`(쌍둥이)
- `needsLevel(row)` → 레벨이 없으면 막을 것인가
- `prevLevelOf(list, date)` → 오답이 물려받을 직전 레벨
- `findStudents(name, all)` → 매쓰홀릭 이름 → 학생 (정확 → 꼬리 뗌 → **이름의 일부**)
- `nameDiffers(name, student)` → 이름이 다르게 등록됐나 (화면에 적어 줘야 한다)
- `wrongNoteFix(unitName, level, prevMainLevel)` → 오답 제목·레벨

규칙 표는 `KINDS` 바로 위 큰 주석에 있다. **거기에 날짜와 원장님 말씀을 그대로** 적는다 —
한 달 뒤에 「왜 이렇게 했지」를 코드만 보고는 알 수 없다.

## 검사

```
node --import ./scripts/ts-resolve.mjs scripts/matholic-check.ts
```

`npx tsx` 는 **안 된다** (top-level await → cjs 오류). 위 명령만 쓴다.

마지막 줄 「통과 N / 전체 N」이 같아야 통과. 그리고 **반드시 망가뜨려 시험한다** —
일부러 틀린 사본을 만들어 같은 명령에 경로로 넘기고, 새로 넣은 검사가 **실패하는지** 본다.

```
node --import ./scripts/ts-resolve.mjs scripts/matholic-check.ts <틀린사본.ts>
```

실패하지 않으면 검사가 없는 것이다.

## 함정 (실제로 당한 것)

1. **판정 순서.** 매쓰홀릭은 TOMA 건에도 종류를 「월간평가」로 붙여 준다.
   월간평가를 먼저 보면 TOMA 본고사가 「월간평가」로 밀린다 (2026-11-02, 검사가 잡았다).
   새 낱말을 넣을 때는 **이미 있는 낱말과 겹치지 않는지** 먼저 본다.
2. **`needsLevel` 이 막아 버린다.** 레벨을 물려받게 만든 종류(오답)는 `needsLevel` 에서도
   빼야 한다. 안 빼면 그 줄이 통째로 「레벨이 없어요」로 막히고, 화면은 멀쩡해 보인다.
3. **`strictNullChecks` 가 꺼져 있다.** `{ok:true}|{ok:false}` 꼴 유니온은 좁혀지지 않는다.
4. **Bash heredoc 은 역슬래시를 한 겹 먹는다.** 정규식이 든 패치 스크립트는 Bash heredoc
   말고 **Write 도구로 파일을 만들어** 돌린다 (`python -I <경로>`).
5. **점수가 두 군데 생기는 것.** 데일리테스트를 학습지로도 넣으면 성취도·브리핑이 두 번 센다.
   새 종류를 만들 때 「이 점수가 이미 다른 칸에 들어가지 않나」를 먼저 본다.
6. **이름이 아니라 레벨이 열쇠인 규칙이 있다.** 「레벨이 없고 N회차」처럼 **없는 것**으로
   가르는 규칙은 `row.level` 을 함수에 넘겨야 한다 — 넘기는 자리를 빼먹으면 늘 false 다.
7. **주석에 적어 두고 코드를 안 쓴 것.** 2026-10-31 에 「교재 이름이 적혀 있으면 쌍둥이」를
   규칙 표에 적었는데 **대조하는 코드가 없었다.** 「교재」 낱말과 쪽 범위만 보고 있었다.
   규칙을 적을 때는 그 줄을 **실제로 돌리는 함수 이름**을 같이 적는다.
8. **교재 목록(`textbook_catalog`)의 함정** — 2026-11-02 기준 98건.
   · 「쎈」은 **한 글자**다. 그냥 찾으면 「분수의」의 「수」처럼 단원 이름 속 한 글자에 걸린다.
     한 글자 이름은 **앞뒤가 한글이 아닐 때만** 본다.
   · 「쎈」이 「쎈B」·「베이직쎈」·「라이트쎈」·「쎈연산」 안에 들어 있다 → **긴 이름부터**.
   · 전각·반각이 섞여 있다(「개념＋유형」/「개념+유형」) → `normBook` 으로 꼴을 맞춘다.
   · 교재명 뒤 괄호에 **학생 이름**이 붙은 것이 넷 있다 → 괄호를 뗀 꼴로 대조하면
     학생 이름은 들어오지 않는다. **검사 파일에 실명을 적지 않는다**(가짜 이름으로).
   · 「모의고사 1부/2부」가 유형서로 들어 있다 — 「모의고사」만 적힌 제목은 안 걸린다.
9. **판정은 맞는데 화면이 말을 안 하는 것.** 2026-11-02 에 원장님이 「비상교과서가 쌍둥이로
   안 걸린다」 하셨는데, `worksheetTypeOf` 는 **맞게 twin 을 돌려주고 있었다.** 줄마다
   어느 갈래로 들어가는지 화면에 아무 표시가 없어서 안 걸린 줄 아신 것이다.
   → 판정을 더하면 **그 판정이 화면 어디에 보이는지**까지 같이 본다. 안 보이면 없는 것과 같다.
   (「왜 이렇게 골랐는지」 줄과 갈래 칩 둘 다 확인할 것.)
10. **이름이 두 곳에 다르게 올라가 있다.** 스터디체크는 「성+이름 붙여쓰기」, 매쓰홀릭은
   이름만 쓰시는 학생이 있다. 정확히 같은 이름이 없을 때만 **이름의 일부**로 찾고,
   여럿 걸리면 고르지 않는다. 고른 뒤에도 **이름이 다르면 화면에 그대로 적는다** —
   조용히 바꿔 치면 엉뚱한 학생에게 점수가 들어가도 아무도 모른다.
   · 2026-11-02 기준 재원생 194명 중 서로 품는 이름은 한 쌍뿐이라(꼬리 숫자) 위험이 낮다.
     새로 손대기 전에 `position(a.name in b.name) > 0` 로 **다시 세어 본다.**
11. **막이를 풀면 DB 가 대신 막는다.** 레벨 없이 들어가게 `needsLevel` 을 푼 날,
   `student_worksheets.current_level` 이 NOT NULL 이라 19건이 통째로 실패했다
   (「violates not-null constraint」 — 저장 단추를 누른 **뒤에야** 보인다).
   → 「없어도 되게」 바꿀 때는 **그 칸이 DB 에서 NOT NULL 인지 먼저 본다.**
   ```sql
   select column_name, is_nullable, column_default from information_schema.columns
   where table_name = 'student_worksheets' and is_nullable = 'NO';
   ```
   지금 NOT NULL 인 칸: subject · grade_level(기본값 없음) · unit · current_level(2.5) · status.
   레벨은 못 찾으면 **Lv1**(`levelForInsert`) 로 넣고 화면에 그렇게 적는다.
12. **목록을 넘기는 자리를 빼먹으면 조용히 옛 동작으로 돈다.** `books` 가 선택 인자라
   타입 에러도 안 난다. 함수에 인자를 더하면 `grep` 으로 **모든 부르는 자리**를 센다
   (`rankWorksheets` 안에서도 `worksheetTypeOf` 를 부른다 — 거기도 넘겨야 한다).

13. **들어간 줄이 어디서 왔는지 남겨 둔다.** 진단평가는 제목을 `memo` 에 적는데
   **코어테스트는 안 적고 있었다.** 2026-11-13 에 TOMA 「연습1회」가 본고사로 들어간 것을
   바로잡으려는데 회차 말고는 자취가 없어 어느 회차에서 왔는지 알 길이 없었다
   (11월에만 40건). 지금은 코어테스트도 `memo` 에 「매쓰홀릭 · 22/25 · 원제목」을 남긴다.
   → **새로 넣는 길을 만들 때는 원제목을 같이 남긴다.** 잘못 들어갔을 때 되짚을 유일한 끈이다.
14. **한 달에 하루만 있는 것을 기본값으로 삼지 말 것.** 「회차가 없으면 본고사」가 기본값이라,
   매일 긁는 길이 생기자 본고사가 한 달에 40번 생겼다. 기본값은 **흔한 쪽**이어야 한다.
