# 잘못 잘린 문제·정답 그림 찾아서 고치기

## 목적

문제은행 그림은 교재 PDF를 문항별로 잘라 Storage 비공개 버킷 `problem-images` 에 올린 것이다
(경로는 `problems.image_path` · 정답은 `problems.answer_image_path`).
자르기 경계가 틀리면 **학습지·인쇄 화면에서만** 티가 나고 DB·문제은행 표에서는 멀쩡해 보인다.
다음 유형 개념이 학습지에 노출되거나, 학생이 엉뚱한 답 그림으로 스스로 채점하게 된다.
이 스킬은 그런 그림을 **찾고 → 원인(자르기 코드의 경계)을 고치고 → 같은 경로에 덮어 올리고 → 되받아 확인**하는 순서다.

## 언제 쓰나

- 선생님·원장님이 "학습지에 다음 문제가 같이 나와", "정답 그림이 다른 답이야" 라고 할 때
- 새 교재를 자른 직후 (업로드 전에 표본 점검, 업로드 뒤 `check-images.py`와 함께)
- 정답 판독·쌍둥이 대조(`scripts/twins/`) 중에 이상한 그림을 봤을 때 — 실제로 RPM 번호·라이트쎈 지시문 누락 모두 쌍둥이 대조 중에 찾았다

## 찾는 방법

### 숫자로 좁히기 — 단, 판정에 쓰지 말 것

```bash
node scripts/twins/edge_scan.mjs 공통수학2 <작업폴더> [--book 유형만렙] [--limit N]   # 그림 받아 두기 + list.json
python scripts/twins/edge_check.py <작업폴더> [--top 40]                              # 꼬리·오른쪽잘림·빈그림 집계
```

- 「꼬리」= 그림 안 50px 넘는 빈 띠 뒤에 또 글이 있는 높이, 「오른쪽」= 오른쪽 테두리에 닿은 글줄 수, 「빈그림」= 글줄 10 미만.
- **가장자리 재기만으로는 헛걸림이 열에 아홉이다.** 공통수학2 6,781장 전수: 유형만렙 꼬리 274 중 진짜 53,
  마플 오른쪽 212 중 진짜 0, 쎈 오른쪽 59 중 진짜 0. 빈 답란·보기 상자 테두리·난이도 배지·단 구분선이 모두 걸린다.
- 그러니 이건 **어디를 들여다볼지 좁히는 데만** 쓴다.

### 진짜 판정 — 자르기 코드의 「멈출 것」 목록과 맞대기

진짜 오류는 매번 **아래(또는 오른쪽) 경계를 「다음 문항 번호」 하나만 보고 정한 코드**에서 나왔다.
묶음·유형의 마지막 문항은 아래에 번호가 없어 단 바닥까지 잘린다. 그래서

1. 그 교재 자르기 코드가 아래 경계로 무엇을 보는지 읽는다 (다음 번호만? 유형 띠·지시문·머리말도?)
2. 이미 있는 자리 기록(`types.json` 유형 띠, `qnum.json` 문항 자리, 지시문 머리 등)을 경계 후보로 넣어 **좌표만으로** 다시 센다
3. 걸린 것을 그림으로 **눈으로 본다**. 정답 그림은 원본(빠른정답 표·풀이 본문 「답」)과 한 장씩 대조한다

### 정답 그림은 원본과 대조

두 번 따로 읽어 같아도 그림 자체가 옆 문항 답으로 잘려 있으면 **같게 틀린다**(라이트쎈 1-2 0800).
반드시 원본 값과 맞춘다. 결과는 `scripts/answers/라이트쎈_정답그림_오류.md` 처럼 번호·종류·내용 표로 남긴다.

## 고치는 순서

1. **표본·목록 만들기** — `edge_scan.mjs` + `edge_check.py` 로 좁히고, 눈으로 보고 진짜 목록을 파일로(`_fixlist.json` 같은 것).
2. **원인 고치기** — 그 교재 자르기 코드의 경계에 빠진 「멈출 것」을 넣는다. 고친 뒤 좌표만으로 다시 세어 **N → 0** 을 확인(쎈 12→0, 유형만렙 53→0).
3. **다시 자르기** — 원본 PDF가 있어야 한다(`C:\Users\USER\문제은행\…`, `C:\Users\USER\Desktop\빅픽쳐\문제은행\…`).
   - 지금 올라간 그림이 이미 번호 지우기 등 후처리를 거쳤으면 **그대로 덮지 말 것.** 다시 자른 그림은 자로만 쓰고(`trim_tail.py`)
     또는 지금 그림을 다시 뜬 그림 위에 덮는다(`fix-light/recut.py`).
   - 자동이 못 하는 것(표·그래프 「풀이 참조」, 두 줄 정답)은 좌표를 손으로 — `fix-light/answers/manual_boxes.json` + `manual_crop.py`, 눈금 보기 `context_view.py`.
4. **옛 그림 | 새 그림 나란히** 비교 그림을 만들어 한 장씩 본다.
5. **백업 → 덮어 올리기 → 되받아 확인** (아래).

## 다시 올리기

- **반드시 먼저 백업.** 경로는 그대로 두고 같은 자리에 `upsert: true` 로 덮는다(`image_path`·`answer_image_path` 는 안 바꾼다).
  - `node scripts/crop-mrl2/_reup.mjs backup` → `orig/` 에 내려받기, `… upload` → `fix/<local_no>.png` 덮어쓰기
  - `node scripts/crop-rpm/_reup.mjs check <폴더>` → `… upload <폴더>` (`<id>.png` 폴더를 그대로)
  - 정답 그림: `node scripts/fix-light/answers/upload_recut.mjs <scratchpad>` — 올리고 **되받아 바이트까지 같은지** 확인
  - 백업 위치 예: `C:\Users\USER\문제은행\backup_light_answers_20261027`, Storage `…/_backup_20261020/`
- 그림이 아예 없는 것은 `python scripts/fix-basic/reupload.py` (먼저 인자 없이 세어 보고 `--write`).
- 번호가 되살아났으면 `python scripts/strip-book-number.py --book <교재> --dry` → 확인 후 실제 실행. RPM은 `scripts/twins/rpm_strip.py`.
- Storage는 **CDN 캐시 1시간** — 올린 직후 옛 그림이 보일 수 있다.
- 정보(유형·정답)만 바꿀 때는 그림을 건드리지 말고 SQL + `되돌리기.sql` 짝을 남긴다.

## 자주 하는 실수

- 가장자리 재기 결과를 그대로 오류 목록으로 씀 → 열에 아홉이 헛걸림
- 아래 경계를 넓혀 오른쪽/아래를 되살리다 **바로 아래 문항을 삼킴** (라이트쎈 0378)
- 다시 자른 그림을 그대로 덮어 **교재 번호가 학습지에 돌아옴** (RPM)
- 베이직쎈 그림 위를 잘라 지문을 날림
- 두 번 판독이 같다고 정답 그림을 믿음 — 그림 자체가 밀려 있으면 같게 틀림
- 이웃 칸에서 지시문을 빌려 붙이기 — 표본 6개 중 1개만 맞아 접었다(같은 문장 두 번, 개념 상자 그림이 딸려 옴)
- Supabase 1000행 한도 — 문항을 읽을 때 `.order('id').range()` 로 순서를 못박고 페이지를 돈다(순서 없이 돌면 같은 줄이 두 번 오거나 빠진다)
- 백업 없이 덮어쓰기 — Storage는 DB 백업에 안 들어갈 가능성이 크다
