# 쌍둥이 대조 (twin_group 묶기)

## 목적

문제은행의 목적은 유형 분류가 아니라 **문항별 쌍둥이·유사문제를 시중교재 사이에서 찾아 주는 것**이다.
- **유사문제** = 같은 유형(`type_code`). 기계가 한다 (유형만 맞으면 끝).
- **쌍둥이** = 숫자만 다른, 또는 같은 꼴·같은 개념을 묻는 같은 문제. **기계가 못 한다 — 그림을 눈으로 읽어야** 가려진다.
  선택지가 ①6 ②7 ③8 ④9 ⑤10 으로 똑같은데 서로 다른 문제인 경우를 공통수학2에서 실제로 봤다.
- 같은 문제가 교재 서너 권(많게는 일곱 권)에 실리므로 짝이 아니라 **묶음**이다 → `problems.twin_group`.
  묶음 번호 = 그 묶음에서 **가장 작은 id**.
- 묶음은 재출제 「쌍둥이 문제」(`app/api/reprint/route.ts`), 교재연계 「쌍둥이 0~3개 추가」(`app/api/book-pick/route.ts`),
  생성 쌍둥이 요청(`lib/twinRequests.ts`, 묶음마다 한 번)이 그대로 집어 간다.

## 언제 쓰나

- 원장님이 특정 과정·소단원·유형의 쌍둥이 대조를 시킬 때
- **새 교재를 올린 뒤** — AGENTS.md 「교재 PDF 한 권을 넣는다는 것」의 3단계. 이걸 빼먹으면 교재 넣기가 안 끝난 것이다.
- 숫자 바꾼 쌍둥이를 **새로 만드는** 일(「요청 처리해줘」)은 이 스킬이 아니다 → `scripts/twin-gen/README.md`.

## 준비물

| 무엇 | 어디 |
|---|---|
| 설명서 | `scripts/twins/README.md`, `docs/문제은행.md` (「공통수학2 쌍둥이 대조」·「두 번 데었다」 절) |
| 그림 받기 | `scripts/twins/fetch.mjs` (한 유형 → 폴더, `meta.json` 에 book·local_no·twin_id) |
| 한 장에 붙이기 | `scripts/twins/sheet2.py` (2열, 한 장 12~16문항, 기본 330px 에서 자르고 「…이어짐」) / `sheet.py` (1열, 6문항) |
| 찾은 결과 | `scripts/twins/findings/<유형코드>.json` — 저장소에 남긴다 |
| 넣기 | `scripts/twins/apply.mjs` (파일 하나), `scripts/twins/merge.mjs` (findings 전체 이어 붙이기) |
| 점검 | `stat.mjs [과정]`(진행), `show.mjs`(묶음 표본, 공통수학2 고정), `clean.mjs [--dry]`(혼자 남은 묶음 비우기), `pair.mjs <폴더> id,id`(문제+정답 그림 나란히), `dump_types.mjs 공수2 <파일>`(유형표) |
| 유형 바로잡기 | findings 의 `유형고침`, 또는 교재·번호로 `retype_local.mjs <교재> <과정> <json>` |
| 테이블 | `problems` (`twin_group`, `twin_id`, `type_code`, `sub_chapter_no/title`), `standard_types` |
| 환경 | 스크립트는 저장소 루트에서 실행. `.env.local` 의 `NEXT_PUBLIC_SUPABASE_URL`·`SUPABASE_SERVICE_ROLE_KEY` 를 읽는다 |

`twin_id` 는 옛 쎈↔쎈B 1:1 짝(4,025쌍) 칸이다. **지우지 않는다** — 묶음이 망가졌을 때 되살리는 근거다.

## 단계별 순서

한 번에 **유형 하나**씩. 소단원 단위로 커밋한다.

```bash
# 0) 어디까지 했나
node scripts/twins/stat.mjs 공통수학2        # 과정 이름은 problems.grade 값 (예: 중1, 공통수학2)
ls scripts/twins/findings/                   # 이미 한 유형

# 1) 한 유형 그림 받기 (작업 폴더는 저장소 밖/스크래치)
node scripts/twins/fetch.mjs 중1-1-02-03 <폴더> [--level 3]

# 2) 한 장에 모으기 → 나온 PNG 를 Read 로 한 장씩 눈으로 읽는다
python scripts/twins/sheet2.py <폴더> <나갈이름> [--cap 330]
#    첫 두세 줄로 안 갈리면 --cap 을 늘리거나 pair.mjs 로 정답 그림까지 본다

# 3) findings 파일 쓰기 (아래 꼴)

# 4) 미리 보기 → 넣기
node scripts/twins/apply.mjs scripts/twins/findings/중1-1-02-03.json --dry
node scripts/twins/apply.mjs scripts/twins/findings/중1-1-02-03.json

# 5) 여러 유형을 했으면 반드시 merge 로 한 번 더 (겹친 묶음 잇기 + 쎈↔쎈B twin_id 짝 잇기)
node scripts/twins/merge.mjs --dry [--like=중1-1]
node scripts/twins/merge.mjs [--like=중1-1]

# 6) 확인
node scripts/twins/clean.mjs --dry            # 혼자 남은 묶음 — 먼저 --dry 로 목록을 보고 판단
node scripts/twins/stat.mjs 중1
```

findings 파일 꼴 (`apply.mjs` 머리말 기준):

```json
{"_메모": "중1-1 02-15 최대공약수와 최소공배수의 관계 — 2026-10-26",
 "중1-1-02-15": {
   "쌍둥이":  [[516, 1299, 59699], [1296, 534]],
   "유형고침": {"44444": "중1-1-02-03"}
 }}
```

- `_` 로 시작하는 키·파일(`_메모`, `_되돌리기-…json`)은 `apply`/`merge` 가 건너뛴다.
- 한 파일 안에서 한 문항이 두 묶음에 있으면 `apply` 가 멈춘다. 묶음에 하나뿐이면 건너뛴다.
- `apply` 는 id 가 그 유형이 맞는지 확인하고, 아니면 경고(`!`)를 낸다 — 경고를 읽고 넘어갈 것.
- `apply` 는 **묶기를 먼저 하고 유형고침을 나중에** 한다. 유형을 고쳐야 묶을 수 있는 **교차 쌍둥이**는
  파일을 둘로 나눠 `…-교차.json` 처럼 따로 두고 **고치기 파일 → 묶기 파일** 차례로 적용한다
  (예: `findings/공수2-01-교차.json` 의 `_메모` 「앞 파일을 먼저 적용할 것」).
- 유형고침은 소단원(`sub_chapter_no/title`)도 `standard_types` 에서 따라 옮긴다. 손으로 `type_code` 만 바꾸지 말 것.

## 판단 기준 (지금까지 커밋에 적힌 것)

- **쌍둥이로 묶는다**: 숫자만 다른 같은 문제. 진술이 책마다 달라도 **같은 꼴·같은 개념**이면 묶는다
  (쎈↔쎈B 짝도 원래 진술이 다르다 — 출판사 기준으로 같은 꼴이면 쌍둥이).
- 고르는 개수가 1개냐 2개냐는, 묻는 것이 같으면 한 묶음.
- **나눈다**:
  - 「옳은 것은?」과 「옳지 않은 것은?」 — 답을 고르는 셈이 다르다.
  - 한 수를 소인수분해 vs **두 수의 곱**을 소인수분해 — 계산 품이 다르다.
  - 선택지(숫자)만 우연히 같은 것 — 발문을 끝까지 읽어 확인. 글자·선택지 비교로 기계가 묶지 않는다.
- drill(그림에 답만 찍힌 「(1,3)」 같은 것)은 지시문이 보이는 **이웃 번호를 같이 봐야** 무엇을 묻는지 안다
  (유형만렙 0380~0387 을 대칭이동으로 옮겼다가 평행이동이라 되돌렸다).
- 쌍둥이가 적은 유형도 있다 — 유리식·무리식 계산은 교재마다 식을 새로 지어 묶음이 원래 적다(31~39%).
  억지로 채우지 말 것. 그래프·점근선·대칭 쪽은 잘 맞는다.

## 대조하다 같이 잡히는 것 (같은 커밋에서 고친다)

- **유형이 잘못 붙은 문항이 자주 나온다** → 같은 파일의 `유형고침`. 「이 교재 문항만 내용이 다르다」가 신호.
- **유형 번호가 통째로 밀린 구간**: 마플시너지 0440~0458(06-05), 0525~0546(07-01), 0562~0580(08-01),
  풍산자 필수유형 184~192·302~315·326~341 — 합쳐 190문항 가까이. **소단원 맨 앞·맨 뒤 유형부터** 읽으면 빨리 보인다.
- 짧은 이름(「원의 방정식」)으로 글자 맞추기가 한 유형에 몰린다 — 05-01 에 75문항 중 28문항이 다른 유형이었다.
  단원 마무리 문항(풍산자 라이트 08S·09S)이 엉뚱한 유형에 들어가 있기도 했다.
- **크롭 잘림**: 마플시너지 왼쪽 단 35px, 유형만렙 오른쪽 단 43px 이 잘려 있던 것을 대조하다 찾았다
  (`gutter.py` 로 고쳐 재업로드). 글자가 가장자리에 닿아 있으면 원장님께 보고하고 자르기 쪽에서 고친다
  (찾는 도구: `edge_scan.mjs` + `edge_check.py`, 헛걸림이 많으니 눈으로 확인).
- 그림 자체 흠(예: 교과서 3 #45000 발문이 두 번 들어감)은 커밋 메시지에 적어 둔다.

## 자주 하는 실수·함정 (실제 사고)

1. **`apply.mjs` 를 파일마다 따로 넣으면 묶음이 서로 덮어쓴다** (2026-10-24).
   뒤 파일에서 앞 파일의 문항을 다시 적으면 그 문항만 새 번호로 옮겨 가고 원래 짝이 혼자 남는다.
   공통수학2에서 **694문항**이 떨어져 나갔다 → 여러 유형을 한 뒤에는 **`merge.mjs` 로 한 번 더**.
   merge 후 공통수학2는 1,356묶음 4,333문항이 됐다.
2. **쎈만 적고 쎈B 짝을 안 적으면 쎈B 가 혼자 남는다** (2026-10-26) → `merge.mjs` 가 DB 의 `twin_id` 짝도
   같이 잇게 고쳤다. `apply` 만 쓰면 이 보정이 없다.
3. **`order` 없이 `.range()` 로 페이지를 넘기면 쪽마다 차례가 달라 행을 놓친다** (2026-10-24).
   `clean.mjs` 가 짝의 한쪽을 못 읽어 멀쩡한 쎈↔쎈B 쌍을 「혼자」로 보고 **601문항을 비웠다**.
   `twin_id` 가 남아 있어 `scripts/twins/02_적용-쎈B묶음복구.sql` 로 되살렸다(되돌리기 SQL 짝도 있음, 8,050쌍 전부 확인).
   → 새로 쓰는 스크립트의 **모든** 페이지 넘기기에 `.order('id')`. (`show.mjs` 는 아직 order 가 없다 — 숫자만 보는 용도로만.)
4. **`.in('id', ids)` 에 700개 넘게 넣으면 말없이 일부만 들어간다** → 100개씩 끊는다 (`merge`/`clean` 처럼).
5. **한 장이 1500px 를 넘으면 화면에서 줄어 글씨를 못 읽는다** (`sheet*.py` 의 `MAXH`). 늘리지 말 것.
6. 지우는 동작(`clean.mjs`, `twin_group = null`)은 실서비스 데이터다. **`--dry` 로 목록부터** 보고, 이상하면 멈추고 보고.
   `twin_id` 칸은 절대 비우지 않는다.

## 끝났다고 말하기 전 확인

- [ ] 이번에 한 유형마다 `findings/<코드>.json` 이 있고 `_메모` 에 내용·날짜가 적혀 있다
- [ ] `apply --dry` 경고(`!` 다른 유형) 를 다 읽고 처리했다
- [ ] 여러 유형을 했으면 `merge.mjs` 까지 돌렸다
- [ ] `clean.mjs --dry` 로 혼자 남은 묶음이 왜 생겼는지 안다 (유형고침으로 빠져나간 것만 비운다)
- [ ] `stat.mjs <과정>` 숫자를 원장님께 보고: 쌍둥이 붙은 문항/전체, 묶음 수, 교재 3권 이상 묶음 수
- [ ] 유형고침·밀린 구간·크롭 흠을 커밋 메시지에 적었다
