## R042-01 — 저장 실패가 성공처럼 보임

브라우저에서 `fetch` 를 가로채 `/api/learning/act` 의 `help` 만 **500** 으로 돌려주고 13초 재생.

| | 042 | 지금 |
|---|---|---|
| 화면 표시 | `자동 저장됨 ...` | **`저장되지 않았습니다 — 들고 있다가 다시 보냅니다`** |
| 서버 기록 | — | **0건** |

가로채기를 푼 뒤 이어서 재생:

```
표시        자동 저장됨 오후 6:19:11
도움기록수   4
행동id      86d9406c · 0a530ab9 · aca214e9 · 110d4879   ← 전부 다름 (두 번 반영 없음)
본초        10 · 13 · 14 · 23                           ← 이어서 쌓임
```

미확정 1건은 **같은 봉투**로 다시 가고, 그 뒤의 주기 저장은 **새 행동**이다.
화면 문구도 실제와 맞췄다 — 봉투를 재사용하지 않는 경우에는
「두 번 반영되지 않습니다」라고 쓰지 않는다.

## R042-02 — 늦게 온 도움이 같은 요청을 충돌로 만듦

`after_help` 를 이벤트 지문에서 **뺐다.** 원요청의 뜻이 아니라 이력 해석이기 때문이다.
저장된 `afterHelp` 칸도 없앴고, 볼 때마다 시각으로 계산한다.

시험 `R1`: 답(10:02) 저장 → 도움(10:01)이 **늦게** 도착 → 같은 답 **바이트 동일 재전송**

```
결과   200 · duplicate            (042 에서는 409 conflict, changedFields=['after_help'])
분석   resultAfterHelp = correct  ← 늦은 근거를 반영한다
```

시각은 **실제 시점**으로 견준다 (`Date.parse`). 시험 `R2`:
`2026-10-27T09:00:00Z` 와 `2026-10-27T18:00:00+09:00` 이 같은 값으로 나오고,
문자열로 견주면 뒤집히는 짝에서 순서가 맞는다. 못 읽는 시각은 「뒤」로 올리지 않는다.

## R042-03 — 관측 파생값 불일치

**완료**: 승인 구간 밖만 보낸 경우 `completed=true` 가 살아남지 않는다 (시험 `R3`).
학생이 보낸 주장은 `completedClaimed` 로 **따로** 남고, `completed` 는
유효 구간과 `COMPLETE_PCT` 기준으로 **서버가** 센다 (시험 `R5` — 학생이 `false` 라 해도
54/55초면 서버가 `true` 로 센다). 구간을 모르면 완료를 **비워 둔다**(미확인).

**척도**: `focusLostSeconds`(반복 포함 숨김 재생)와 `coveredSeconds`(서로 다른 구간)는
같은 척도가 아니다. 같은 10초를 숨긴 채 두 번 본 `숨김 20초 · unique 10초` 를
전에는 400 으로 거절했다. 이제 받는다 (시험 `R4`). 비교는 같은 척도인
`playedSeconds`(총 재생)와만 한다.

## R042-04 — loopback 안내와 런처 불일치

전에는 `next dev -p 3200` 만 넘겨 hostname 을 정하지 않았다. Next 기본값은 `0.0.0.0` 이라
「127.0.0.1 에만 열린다」는 제 안내가 **보장되지 않았다.**

지금 런처 출력과 실제 수신 주소:

```
[학습 demo] 주소는 127.0.0.1 로 고정합니다 (바깥에서 붙지 않습니다).
- Local:   http://127.0.0.1:3200
- Network: http://127.0.0.1:3200
netstat   TCP  127.0.0.1:3200  LISTENING        ← 0.0.0.0 아님
```

`--hostname` · `--host` · `-H` · `--experimental-https` 를 넘기면 **멈춘다**.
