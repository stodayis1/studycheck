# 시험지 분석

학교 시험이 끝날 때마다 하는 「시험지 수합 → 정답 → 변별문항 손풀이 → 총평 → 이너프원 매칭 →
기출문제 문제은행 반영 → 블로그」를 노션 대신 앱 안에서 관리한다. 2026-10-03 추가.

단순 체크리스트가 아니다. **기출문제를 문제은행(`problems`)에 쌓는 것**이 목적이다.

## 처음 한 번 — SQL 실행

`docs/sql/시험지분석_1_테이블.sql` 을 Supabase SQL Editor 에 붙여넣고 Run. 여러 번 실행해도 안전하다.
실행 전에는 「시험지 분석」 화면이 "불러오지 못했습니다"로 뜬다 (다른 화면에는 영향 없다).

끝에 나오는 확인 결과가 `시험지 7 / 문항 1 / 보관함 1 / 정책수 0` 이면 정상.

윤T 확인 필요 / 완료)는 어느 탭에서나 보인다.

## 파일명 규칙

```
시험지   2026_2학기중간_도래울중_중3_문제.pdf      (구분: 문제 · 정답 · 해설 · 문제정답해설)
손풀이   도래울중_중3_18번_손풀이_김T.png          (JPG·PNG)
원본     2026_2학기중간_도래울중_중3_원본.hwp      (HWP·PDF·JPG·PNG — 원장만 열람)
```

- 파일명 끝의 구분을 보고 자동으로 나눠 담는다. 규칙과 다르면 **안내를 띄우고 물어본 뒤** 올린다
  (막지는 않는다). 규칙과 다르게 올라간 파일에는 「파일명 확인」 표시가 붙는다.
- 손풀이는 파일명의 문항번호(`18번`, `서술형2`)를 읽어 변별문항과 맞춰 본다.
- 규칙 코드: `lib/examAnalysis.ts` 의 `checkFileName`.

## 원본 보관 · 통째 인쇄 · 기출 보관함 (원장님 결정 2026-10-03)

**기출문제는 통으로 보관한다.** 지금까지의 기출을 전부 올려 연도별로 학생에게 풀릴 수 있게 하기 위함이다.

- **원본은 따로, 원장만.** 파일 구분 `원본`(학교에서 받은 시험지, 한글 HWP 작업 원본)은 누구나 올릴 수
  있지만 **열기·지우기는 원장만** 된다. 서버가 원장 계정에게만 목록과 주소를 내준다. 선생님에게는
  「보관된 원본 n개」 개수만 보인다. (`docs/sql/시험지분석_2_원본보관.sql` 실행 필요)
- **통째 인쇄.** 작업한 `문제` PDF 가 올라와 있으면 상세 화면과 현황판에 「인쇄」 버튼이 생긴다.
  누르면 그 PDF 가 새 창으로 열리고 거기서 인쇄한다 (`문제` 가 없으면 `문제정답해설`).
  이 인쇄에는 QR 채점이 붙지 않는다 — 한글에서 만든 시험지 모양 그대로 나간다.
- **연도별 찾기.** 현황판 위에서 시험(연도·학기) · 학교 · 학년으로 고른다. 「전체 시험」도 된다.
- **지난 기출 올리기 — 파일명을 맞출 필요가 없다** (2026-10-05). 현황판의 「기출 파일 올리기」로 파일을 여러 개
  고르면 확인 창이 뜬다. 파일명에서 연도 · 학기 · 시험 · 학교 · 학년 · 종류를 **짐작해** 칸을 채워 주고
  (`lib/examAnalysis.ts` 의 `guessExamFile`), 못 읽은 칸은 빨갛게 표시한다. 사람이 틀린 칸만 고쳐 올린다.
  없는 시험은 자동으로 만들고, **보관할 때의 파일명은 서버가 규칙대로 붙인다** (`standardFileName`,
  같은 종류가 또 있으면 `…_원본2.hwp`). 상세 화면에서 올릴 때도 마찬가지 — 손풀이만 문항번호 때문에 이름을 본다.
  종류 짐작: 한글 파일 · 「원본」 · 「필기삭제」 → 원본, 그 밖의 PDF → 문제.
- 올린 파일은 지우지 않는 한 계속 남는다. 문항별로 잘라 문제은행에 넣어도 **원래 PDF 는 그대로 둔다.**

## 기출문제 → 문제은행 (가장 중요)

### 실제 작업 방식 (원장님 결정 2026-10-03)

선생님들은 기출문제를 **한글(HWP)로 작업해 PDF로 변환한 뒤 「기본 · 파일」 탭에 올린다.**
앱 안에서 문항을 다시 타이핑하지 않는다. 올라온 PDF 를 **Claude 가 교재 때와 같은 방식으로
문항별 그림으로 잘라** `exam_questions` 와 `problems` 에 넣는다 (원장님이 요청할 때마다).

- 자른 그림은 200dpi, 학습지 단 폭(87mm = 685px) 안에 들어와야 한다. 넓으면 인쇄 화면이 줄여 찍는다.
- `problems` 에 들어가는 값·`source_key` 규칙은 아래 표와 같다 (타이핑 반영과 같은 모양으로 넣을 것).
- 넣은 뒤 `exam_questions` 에도 같은 번호로 한 줄씩 만들어 `problem_id` 를 이어 준다.
  그래야 「기출문제」 탭 목록과 이너프원 매칭·적중률이 문항과 연결된다.
- 유형(`type_code`)·레벨은 교재 올릴 때처럼 정해서 넣고, 넣기 전에 문항 수·자르기 결과를 원장님께 보여 드린다.
- 화면에서 선생님이 직접 PDF 를 잘라 넣는 도구는 아직 없다 (다음 작업 후보).

#### 넣는 순서 (2026-10-03 도래울중 중3으로 처음 함)

```
python scripts/exam-paper/crop.py "<기출.pdf>" "C:\Users\USER\문제은행\기출\2026_2학기중간_도래울중_중3"
node scripts/exam-paper/upload.mjs "<위 폴더>" --year 2026 --term 2 --type 중간고사 --school 도래울중 --grade 중3 \
     --pdf "<기출.pdf>" --original "<한글 원본.hwpx>"          ← 먼저 --go 없이 돌려 무엇을 할지 본다
node scripts/exam-paper/upload.mjs … --go                      ← 실제로 넣는다 (다시 돌려도 같은 문항을 고칠 뿐 새로 넣지 않는다)
```

- **자르기 규칙**: 한글 작업 파일은 2단이고 문항 맨 앞에 작은 미주 번호 `3)` 가 있다. 그 번호가 문항의 시작.
  다음 단·다음 쪽으로 넘어가면 조각을 이어 붙인다. 마지막 쪽의 `1) 2) 3) …` 목록은 미주(정답 칸)라 문항이 아니다.
  자른 뒤 **번호가 1부터 연속인지, 문항 수가 맞는지** 출력으로 확인할 것.
- **수학의지혜 시험지 양식 인쇄** (`/teacher/exam-analysis/print?paper=<시험지 id>`, 양식 코드
  `components/exam-analysis/ExamPaperPrint.tsx`): 맨 위 「2026학년도 2학기 중간고사」 + 쪽 번호, 머리에
  [수학의 지혜] · 3학년 · 수학 · [학교명], 2단 + 가운데 세로줄, 문항 앞 「1.」, 맨 아래 「1/5」. A4.
  원장님이 말하는 "수학의지혜 시험지 양식"은 **이것**이다 (QR 학습지 양식이 아니다 — 2026-10-04 정정).
  쪽 짜기는 화면에서 재지 않고 그림 크기(px ÷ 200dpi)로 **계산**한다. 한 단의 문항 높이 합이 언제나
  본문 높이(245mm)와 같게 풀이 여백을 나눠 주므로 넘치지 않는다. 한 단보다 긴 문항은 높이에 맞춰 줄인다.
  점검값(도래울중 23문항): 5쪽, 쪽 높이 297mm, 단 높이 합 245mm, 넘침 0, 잘린 문항 0, 번호 순서 1~23.
- **QR 채점 학습지 양식 인쇄**(기존 `/teacher/gradings/print`)도 버튼으로 남겨 두었다. 아래 학습지를 쓴다.
- **통째 인쇄용 학습지**: 그 시험의 문항을 번호 순서로 담은 `exam_sheets` 를 만든다. 제목 `26년 도래울중 2학기 중간고사`,
  `note = exam_paper:<시험지 id>`. 시험지 분석 화면의 인쇄 버튼이 이 학습지의 인쇄 화면(학원 시험지 양식 · QR)으로 간다.
- **한 쪽보다 긴 문항**(세로 175mm 초과)은 그림을 줄여서 올린다. 인쇄 화면은 한 쪽을 넘는 문항을 자르기 때문이다.
- **유형·레벨은 넣지 않는다** (`type_code` null, `sub_chapter_no` 0). 그래서 자동 출제에는 아직 안 뽑힌다.
  통째 인쇄와 적중률 대조에는 필요 없고, 유형을 붙이면 그때부터 자동 출제에 섞인다.
- **정답은 나중에** 「정답 · 변별 · 손풀이」 탭의 정답표에 넣고 저장하면 문항과 문제은행 정답에 같이 들어간다 (QR 채점용).
- 한글 파일에 스캔 그림과 다시 친 표가 같이 남아 있으면 그대로 두 번 찍힌다. 파일을 고쳐 다시 받으면
  같은 명령을 한 번 더 돌린다 (그림만 바뀐다).

아래 「타이핑 → 그림으로 굽기」는 **PDF 가 없는 문항을 따로 넣을 때 쓰는 보조 수단**이다.

### 왜 그림으로 굽나

문제은행 27,000여 문항은 **전부 200dpi 그림**이고, 인쇄 화면은 「원본 px ÷ 200 × 25.4mm」로 찍는다.
글자로 된 문항을 찍는 길이 없다. 그래서 타이핑한 문항을 **반영하는 순간 학습지 한 단 폭(87mm)으로
그려 200dpi PNG(가로 685px)로 구워** `problem-images` 에 올리고 `problems` 에 한 줄을 넣는다.

→ 인쇄(`app/teacher/gradings/print`) · QR 채점 · 재출제 · 답지·해설 화면을 **하나도 고치지 않았다.**
  기출 문항도 교재 문항과 똑같은 길을 탄다.

- 그리는 곳: `components/exam-analysis/QuestionRender.tsx`
- `COL_MM = 87` 은 인쇄 화면의 `COL_MM` 과 **같아야 한다.** 인쇄 단 폭을 바꾸면 여기도 바꿀 것.
- `html2canvas` 는 분수선·루트를 엉뚱한 자리에 그려서 쓰지 않는다. 상자를 SVG `foreignObject` 에 넣어
  브라우저가 그대로 그리게 한다. 수식 CSS·글꼴(KaTeX)은 그림 안에 같이 넣는다.
- 굽고 나서 **숫자로 확인**한다: 가로가 685px 이 아니거나 아래가 잘렸으면 반영을 멈추고 알린다.
- 수식은 `$ … $` 사이에 LaTeX. 화면의 「수식 넣기」 버튼(수학 키패드)으로 넣을 수 있다.
- 도형처럼 타이핑이 안 되는 것은 「그림 넣기」. 「이 그림이 문제 전체입니다」를 켜면 캡처 한 장을
  그대로 문제로 쓴다.

### 중복 방지 (source_key)

- `exam_questions.source_key` 는 unique. 같은 번호를 또 저장하려 하면 **「이미 입력된 문항이 있어요」
  경고**가 뜨고, 확인하면 덮어쓴다.
- `problems.source_key` 에도 unique 색인(null 제외). 반영할 때 같은 열쇠가 있으면 **새로 넣지 않고
  그 줄을 고친다.** 문항 id 가 그대로라 이미 만든 학습지가 깨지지 않는다.

### 알아둘 것 (원장님 결정: 2026-10-03)

- 반영된 기출은 **자동 출제에도 섞여 나온다.** (유형·레벨이 맞으면 다른 교재 문항과 함께 뽑힌다)
- 반영은 **원장만** 할 수 있다. 선생님은 「문제은행 반영 요청」까지.
- 반영된 문항은 지울 수 없다 (이미 학습지에 쓰였을 수 있다). 고쳐서 「다시 반영」은 된다.
- 학습지에 실린 문항의 정답은 QR 채점 화면으로 내려간다 — 이건 교재 문항과 같은 기존 동작이다.

## 적중률 (이너프원 매칭)

기출분석의 목적은 **학원 교재(이너프원)와의 적중률**이다. 「이너프원 매칭」 탭 위와 현황판에 나온다.

- 적중 = 이너프원에 **쌍둥이 · 매우 유사 · 유형 유사** 문항이 있는 기출 문항. **참고는 세지 않는다.** (원장님 결정 2026-10-03)
- 적중률 = 적중 문항 수 ÷ 전체 문항 수. 전체 문항 = 정답표의 번호 + 타이핑한 문항 번호.
  정답표가 비어 있으면 적중률을 내지 않는다.
- 한 문항에 매칭을 여러 개 적으면 가장 가까운 것 하나로 센다.
- 정답표에 없는 번호로 적은 매칭은 세지 않고 「번호를 확인해 주세요」로 알린다.
- 이너프원 단원 목록에는 **이 시험용으로 올린 것만** 뜬다 (시험 종료일 이전에 올린 것 중 가장 최근 묶음).
- **그림 나란히 보기**: 매칭 탭은 기출 문항 그림 옆에 매칭된 이너프원 문항 그림을 닮은 순서대로 보여 준다.
  이너프원 문항은 표 `enough_problems`(교재 · 세트 · 번호 · 그림 경로)에 있고 그림은 보관함 `exam-analysis` 의
  `enough-one/2026-2/<책>/<세트>_<번호>.png`. 매칭을 저장할 때 **교재명 · 단원 · 문항번호가 표와 같으면**
  자동으로 이어진다(`enough_problem_id`). 단원은 「대푯값과 산포도 - 3회차」처럼 줄표가 있든 없든 같게 본다.
  새 학기 이너프원은 `scripts/enough-one/` 의 `index.py → crop.py → upload.mjs images / rows` 순서로 넣는다.
- 적중 대조 자체는 Claude 가 기출 그림과 이너프원 모아보기(`…\이너프원\2026-2학기\sheets`)를 읽어 하고,
  결과를 `scripts/exam-paper/add-matches.mjs` 로 넣는다. 시험지 하나에 2~3분.
- 계산 코드: `lib/examAnalysis.ts` 의 `hitSummary`. 배점 기준 적중률은 아직 없다 (문항 수 기준).

## 블로그 — 버튼 한 번으로 임시저장까지 (2026-10-08)

「블로그」 탭의 **블로그 글 작성 요청**을 누르면 `blog_status='작성중'`, `tasks.blog_requested_at` 이 남는다.
그 뒤 원장님이 Claude 에게 **「블로그 요청 처리해줘」** 라고 하면 Claude 가 요청 목록을 읽어 카드 그림 → 글 → 네이버 임시저장까지 한다.
(자동 예약은 쓰지 않는다 — 원장님 결정 2026-10-08. 예약으로 바꾸려면 `scripts/exam-blog/예약작업_지시문.md`.)
순서와 도구가 막는 것들은 **`scripts/exam-blog/README.md`** 에 있다. 견본은 `scripts/exam-blog/sample/`.

- 끝나면 `tasks.blog_drafted_at`, 못 쓰면 `tasks.blog_failed_at` + 이유(`tasks.blog_auto_note`)가 버튼 옆에 보인다.
  재료(변별문항·손풀이·총평·적중 대조)가 비면 쓰지 않고 이유만 남긴다. 채운 뒤 다시 누르면 다시 시도한다.
- **서버가 아니라 원장님 컴퓨터에서 돈다.** 네이버는 블로그 도구의 전용 크롬에 로그인돼 있어야 한다.
- 발행은 원장님이 네이버에서 직접. 「블로그 상태 · 주소 · 올린 날」도 원장님이 적는다.
- `savePaper` 는 `tasks.blog_*` 를 「작성 요청」을 새로 눌렀을 때만 바꾼다 (선생님의 「할 일」 체크가 옛 값으로 덮어
  같은 글을 두 번 쓰는 일을 막는다).

## 표

```
exam_papers          학교·학년별 시험 1건 + 정답표 + 총평 + 체크리스트(tasks) + 블로그 상태
                     unique (exam_year, term, exam_type, school_name, grade)
exam_paper_files     시험지 PDF · 손풀이 이미지 (실제 파일은 Storage exam-analysis)
exam_questions       타이핑한 기출문항. problem_id 로 problems 와 연결. source_key unique
exam_enough_matches  기출 ↔ 이너프원 매칭 (쌍둥이 / 매우 유사 / 유형 유사 / 참고, 블로그 사용 여부)
problems             + source_key, source_meta  (칸 2개 추가)
```

기존에 있던 비슷한 이름의 표와는 **다른 것**이다:
`exams`(학생 평가 점수) · `school_exams`(학생 학교시험 성적) · `exam_schedule`/`exam_periods`(시험 일정) ·
`exam_sheets`(학습지) · `inner_enough`(이너프원 진도표 — 단원별 문항 수만 있고 문항 단위 자료는 없다).

## 권한

- 새 표 4개는 **RLS 를 켜고 정책을 만들지 않았다** → 브라우저에서는 학생·학부모는 물론 선생님도
  직접 못 읽는다. 서버(`app/api/exam-analysis`)만 service_role 로 접근하고, 첫 줄에서 직원인지 확인한다.
- 보관함 `exam-analysis` 도 비공개·정책 없음. 올릴 때는 서버가 만들어 준 1회용 주소로, 볼 때는
  2시간짜리 임시 주소로만.
- 원장 전용: 문제은행 반영, 블로그 탭 수정, 이너프원 매칭의 「블로그 사용」.
- 지우기: 파일·문항·매칭은 올린(입력한) 본인 또는 원장만.
