# 카톡 수업 브리핑

학부모에게 **어제 수업을 다음 날 오전 11시**에 알림톡으로 보낸다.
학부모가 앱에 들어오지 않아도 읽게 하는 것이 목적이다.

## 왜 "다음 날 오전 11시"인가

선생님들이 학습현황을 저장하는 시각을 최근 30일(1,809건)로 재 봤다.

| 저장 완료 | 누적 |
|---|---|
| 당일 21시까지 | 55% |
| 당일 22시까지 | 72% |
| 당일 23시까지 | 95% |
| 다음날 새벽(0~3시) | 나머지 3.5% |

**그날 밤에 보내면 절반이 빈 브리핑으로 간다.** 다음 날 오전이면 1,809건이 전부 기록 완료였다.
밤 11시 발송은 기록은 차지만 그 시각 카톡은 민원이 된다.

## ★ 알리고는 고정 IP 에서만 받는다 — Supabase 를 거친다

알리고는 **등록된 고정 IP 에서만** API 를 받는다. 고객센터 답변도 같다 —
「유동 IP 만 가능하다면 발송 로직을 별도의 고정 IP 서버에서 호출해 달라」.
그런데 Vercel 서버리스는 나가는 IP 가 매번 바뀌어 등록할 수가 없다.

**그 "고정 IP 서버" 가 이미 있다 — Supabase 다.** 거기서 http 로 나가면 늘 같은 IP 로 나간다
(2026-10-08 측정 `16.184.57.154`, 6회 동일). 서버를 새로 사거나 관리할 필요가 없다.

    Vercel (본문 만들기 · 링크 찍기 · 기록)
       └→ Supabase  public.aligo_call()   ← 고정 IP 로 나간다
             └→ 알리고

 · `docs/sql/알리고_고정IP_중계.sql` — service_role 만 부를 수 있고,
   보낼 수 있는 주소를 `kakaoapi.aligo.in` 으로 못박았다(SSRF 방지).
 · 알리고 「발송 서버 IP」 에 그 IP 를 등록해 두어야 한다.
 · **Supabase 가 인프라를 옮기면 IP 가 바뀔 수 있다.** 그러면 다시 「인증되지 않는 서버 IP」
   오류가 나는데, 오류 문구가 지금 IP 를 확인하는 SQL 까지 알려 준다:
   `select (extensions.http_get('https://api.ipify.org')).content`

## 보내는 곳 — 알리고 (Aligo)

2026-10-08 에 **솔라피 → 알리고**로 옮겼다(원장님 결정). 옛 `/api/send-kakao`(솔라피)와
`/admin/test-kakao` 는 지웠고, 한 사람짜리 발송도 브리핑과 **같은 경로**를 쓴다 —
업체도 템플릿도 요금도 하나다.

알리고가 이 일에 더 나은 점:

| | 솔라피 | 알리고 |
|---|---|---|
| 변수 치환 | 알림톡 서버가 `#{변수}` 를 채움 | **완성된 본문을 그대로 보냄** (우리가 이미 만든다) |
| 시험 발송 | 없음 — 진짜로 나가고 요금도 나감 | **`testMode=Y`** 로 전 과정을 요금 없이 |
| 잔액 | 따로 확인 | **응답이 남은 포인트·건당 단가를 준다** |
| 템플릿 등록 | 콘솔에서 손으로 | **API 로도 가능** (`/akv10/template/add/` + 검수요청) |
| 실패 시 문자 | 따로 구현 | `failover=Y` 로 내장 |

### ★ 반드시 알아야 할 두 가지

1. **알리고는 변수를 채워 주지 않는다.** 우리가 만든 본문을 그대로 보내고,
   그 본문이 **승인된 템플릿 서식과 일치해야** 전송된다. 안 맞으면 조용히 안 간다.
   그래서 `lib/briefing.ts` 의 `BRIEFING_TEMPLATE` 하나가 「등록할 원문」이자 「보낼 본문의 틀」이다.
   **템플릿을 바꾸면 그 상수도 같이 바꿔야 한다.**
2. **실패해도 HTTP 200 을 준다.** 응답 본문의 `code` 로만 성패를 안다(알림톡은 `0` 이 성공).
   `res.ok` 만 보고 성공으로 치면 한 건도 안 갔는데 「발송 완료」가 찍힌다.
   `lib/aligo.ts` 가 이걸 막는다.

> **버튼이 왜 3개인가** — 원장님이 말씀하신 두 가지(점수 현황·출결과 달성률)에 하나를 더했다.
> **알림톡은 본문에 가변 이미지를 못 싣는다**: 템플릿당 고정 이미지 1장만 되고 그 이미지엔 링크도
> 못 건다. 즉 학생마다 다른 사진(알림장 첨부 사진)은 애초에 본문에 넣을 수 없다. 사진이 열릴
> 자리가 필요해서 3번째 버튼을 뒀다. 사진이 없는 날엔 그날 알림장 전문·진도·과제가 보인다.
> 1·2번만 등록하셔도 되고, 그러면 사진은 앱에서만 보인다 (코드에서 버튼 하나를 빼면 된다).

### 2-1. 심사 통과 뒤 — **보내기 전에 반드시 템플릿 대조**

학습관리 → 수업일지 맨 위 「카톡 수업 브리핑」 칸의 **「템플릿 맞는지 확인」** 을 먼저 누른다.

알리고는 변수를 채워 주지 않는다. 우리가 만든 본문이 **승인된 템플릿과 글자 단위로 같아야**
전송되고, 안 맞으면 **에러도 없이 그냥 안 간다.** 심사 과정에서 카카오가 문구를 고치게 하는
일이 흔한데, 그걸 모르고 발송을 걸면 185명이 통째로 실패한다.

이 버튼이 알리고에서 **실제 등록된 템플릿**을 가져와 `lib/briefing.ts` 의 `BRIEFING_TEMPLATE`
과 대조하고, 다르면 **몇 번째 글자부터 어떻게 다른지** 보여 준다. 그대로 알려주면 코드를
알리고 쪽에 맞추면 된다. 승인상태(APR)와 버튼 개수도 함께 확인한다.

### 2-3. 「데일리테스트」 판 두 개를 더 등록한다 (2026-10-17)

원장님 말씀 — 「고등부는 학습지도 학습지지만 **데일리테스트**를 더 많이 활용하거든.
데일리테스트가 학습브리핑에 올라와야 할듯해」

**지금은 점수가 묻힌다.** 예전 판의 「▶ 지난 학습지」 칸은 `learning_notes.worksheet_score`
를 쓰고, 그게 **비어 있을 때만** 데일리테스트로 대신했다. 그런데 0점도 「있는 값」이다.
10/15 고1 이수아·이수연 두 학생은 데일리테스트 **95점·100점**을 받았는데, 그날 과제
성취도가 0 이어서 브리핑엔 「지난 학습지 0점」만 나갔다.

그래서 **「▶ 데일리테스트」 한 줄이 더 있는 판**을 등록한다. 「과제 성취도」 판(아래 ②)에
한 줄만 더한 것이다. 데일리테스트를 **본 날만** 이 판으로 나간다 — 안 본 날까지 줄을
띄우면 초·중등 브리핑마다 「데일리테스트 해당 없음」이 붙는다(알림장 빈말을 뺀 것과 같은 이유).

**템플릿 이름**: `수업 브리핑 (일일) - 데일리테스트` / `… - 데일리테스트, 알림장 없음`

```
[수학의지혜 수업 브리핑]
#{학생명} 학생 · #{날짜}

▶ 출결  #{출결}
▶ 과제 달성률  #{과제달성률}
▶ 과제 성취도  #{과제성취도}
▶ 데일리테스트  #{데일리테스트}

▶ 오늘 나간 진도
#{진도}

▶ 다음 시간까지 과제
#{과제배부}

▶ 선생님 알림장
#{알림장}

아래 버튼에서 아이의 누적 현황을 보실 수 있어요.
```

알림장 없는 판은 위에서 **「▶ 선생님 알림장」과 `#{알림장}` 두 줄만 빼고** 똑같이. 버튼은
알림장 있는 판 3개, 없는 판 2개 — 2-2 와 같은 규칙이다.

승인되면 코드를 **`ALIGO_BRIEFING_TPL_CODE_V3`** / **`ALIGO_BRIEFING_TPL_CODE_V3_NONOTE`**
에 넣고 Redeploy. 값이 없으면 지금 쓰는 판으로 그대로 나간다 — 되돌릴 때는 값을 지우면 된다.

들어가는 값: `class_sessions.daily_test_score` (점수) + `daily_test_unit` (범위).
「85점 · 이차함수의 그래프」처럼 나가고, 범위를 안 적으셨으면 「85점」만 나간다.
결석한 날은 이 판을 쓰지 않는다.

> **네 판이 된다** — (알림장 O/X) × (데일리테스트 O/X). 어느 판으로 본문을 만들었는지와
> 보내는 템플릿 코드가 **반드시 같아야** 한다. 어긋나면 에러도 없이 그냥 안 나간다.
> `lib/briefing.ts` 가 판을 고르고, 발송 코드는 그 결과(`dailyShown`·`template`)를 그대로 따른다.
> 「템플릿 대조」 버튼에서 네 판을 한 번에 볼 수 있다.

### 2-4. 템플릿을 새로 만들지 않고도 나가게 해 뒀다 (2026-10-17)

데일리테스트 **한 줄**(2-3)은 심사를 기다려야 한다. 그걸 기다리는 동안에도 점수가 묻히면
안 되니, 줄을 늘리지 않고 **점수 칸 뒤에 붙인다.**

```
▶ 과제 성취도  100% · 데일리테스트 95점 · 2-4. 명제의 증명
```

**변수 칸 안의 글자는 심사와 무관하다.** 그래서 이건 지금 쓰는 판 그대로 **오늘부터** 나간다.
2-3 의 판이 승인돼 `_V3` 코드가 들어오면 그때 줄이 따로 생기고, 꼬리는 자동으로 안 붙는다
(두 번 나가면 안 되니까).

**이름에도 학년을 붙였다** — 「이수아 학생(고1) · 10월 17일」.

> 왜 — 한 집에 자녀가 여럿인 가정이 많다. 이미진 어머님 번호 하나로 이수아(고1)·
> 이수연(중1)·이수애(초5) 세 자매 브리핑이 간다. 게다가 고1 반에는 **이수아와 이수연이
> 같이** 있어 진도도 알림장도 글자까지 같다. 그래서 「고등부 이수연 브리핑이 중등부 이수연
> 어머님께 갔다」는 오해가 생겼다(2026-10-17. 발송 기록을 다 뒤져 봤고 **발송은 정확했다**).
> 이름 옆 학년 두 글자가 그 오해를 막는다. 이것도 변수 칸이라 재심사가 없다.

### 2-4-2. 그날 **학습지 점수**도 같은 수법으로 붙인다 (2026-10-30)

원장님 — 「학습지 매쓰홀릭에서 붙여서 점수를 넣었거든? 그런데 알림장에는 안뜨는데?」

매쓰홀릭 붙여넣기(`app/teacher/assignments/matholic`)로 점수는 잘 들어가고 있었다.
그런데 **어느 판에도 「▶ 학습지」 줄이 없었다.** 「▶ 과제 성취도 70%」는 선생님이 고르시는
판단값이고 학습지 점수(90점)와 **다른 값**이다. 학부모님은 그날 학습지를 몇 점 받았는지
브리핑으로는 알 수 없었다.

줄을 새로 쓰면 또 심사다. 그래서 2-4 와 같이 **점수 칸 뒤에 붙인다.**

```
▶ 과제 성취도  70% · 학습지 전범위 Lv4 90점
▶ 과제 성취도  90% · 학습지 3단원 Lv3.5 92점 · 합동과 대칭 Lv4 88점 외 1장
```

- 값은 `student_worksheets` 에서 **그날(한국시간) 제출 + 점수 있음**인 것을 읽는다.
  매쓰홀릭 붙여넣기든 QR 채점이든 같다. **선생님이 알림장을 먼저 쓰셨어도 나간다** —
  브리핑이 DB 를 직접 읽기 때문이다(학습일지 화면의 초록 칩은 쓰실 때 보시라고 있는 것이고,
  점수가 나가는 것과는 상관이 없다).
- 꼬리가 붙는 날은 `worksheet_unit`·`worksheet_level` 을 **빼고** 꼬리에 맡긴다. 같은 말이
  두 번 나가지 않게 하려는 것이다. 그 두 칸은 주간 보고서·OPS 로 계속 간다.
- **결석한 날은 안 붙인다.** 그날은 학습지를 볼 수 없다.
- 단원 이름은 바깥 프로그램에서 온 것이라 아주 길다(중등은 40자가 넘는다). 괄호 안 설명과
  별표·「레벨학습지」 군더더기를 떼고, 칸(72자)에 맞게 줄이고, **끝내 안 들어가면 안 붙인다.**
  낱말 한가운데서 「…」로 끊긴 글을 보내지 않기 위해서다. 실데이터 8,241건에서 못 붙은 건 7건.
- 재는 법: `node --import ./scripts/ts-resolve.mjs scripts/briefing-check.ts` 와
  같은 명령에 `--v2` 를 붙여 **두 판 모두** 돌린다. 길이·골격·끊김·못 붙음을 한 번에 센다.

### 2-5. ★ 템플릿 코드는 이제 **손으로 안 넣어도 된다** (2026-10-19)

원장님 — 「과제달성률 밑에 "지난 학습지"가 과제 성취도로 바꾸기로 했는데 안바꼈네?
「지난 학습지가 나가면 안돼. 그래서 우리 템플릿을 바꾸기로 하지 않았었나?」

바꿔 놓긴 했었다. 새 판(「▶ 과제 성취도」)을 등록해 **승인까지 받아** 뒀다. 그런데 코드가
그 판으로 보내려면 **템플릿 코드를 Vercel 환경변수에 손으로 넣어야** 했고, 그 한 걸음이
빠져서 승인된 새 판을 두고도 **예전 판 그대로** 나가고 있었다. 아무 에러도 안 난다.

사람이 기억해야 하는 단계는 언젠가 빠진다. 그래서 그 단계를 없앴다.

**지금은 보낼 때마다 알리고에 물어본다**(`lib/briefingTemplate.ts`). 등록된 템플릿 중
우리 원문과 **글자 단위로 같고**, **승인(APR)** 됐고, **버튼 개수·이름·링크까지 같은** 것을
찾아 그 코드로 보낸다. 그 셋이 맞으면 그게 바로 「이 본문으로 보내면 통과하는 템플릿」이라,
코드를 손으로 적어 넣는 것보다 오히려 안전하다.

> 그러니 **새 판을 쓰려면 알리고에 등록해 승인만 받으면 된다.** 승인되는 순간부터 그 판으로
> 나간다. 환경변수는 **안 써도 되고**, 넣어 두면 못 물어봤을 때(키 없음·연결 실패)의 보조로만
> 쓰인다. 되돌리고 싶으면 알리고에서 그 템플릿을 내리면 된다.

**지금 어느 판으로 나가는지 보는 법** — 학습일지 모달의 「학부모님께 이렇게 나갑니다」
상자 맨 아래에 **원장님께만** 「지금 판: …」이 적힌다. 빨간 글씨면 새 판이 안 잡힌 것이다.

### 2-6. 월간 학습 리포트 템플릿 (2026-10-24) — **아직 등록 전**

월간 리포트는 링크까지 만들어져 있는데(보고서 → 월간 보고서 → 새 양식·링크) **카톡으로
보낼 길이 없다.** 알림톡 템플릿이 없기 때문이다. 아래를 등록하고 심사를 받아야 한다.

**템플릿 이름**: `월간 학습 리포트` · **유형**: 기본형(BA) / 강조유형 없음(NONE) / 정보성

**본문** — 아래를 그대로. (코드 쪽 원문은 `lib/monthlyReportTemplate.ts` 의 `MONTHLY_TEMPLATE`)

```
[수학의지혜 월간 학습 리포트]
#{학생명} 학생 · #{기간}

▶ 수업 출석  #{출석}
▶ 과제 달성률  #{과제달성률}
▶ 과제 성취도  #{과제성취도}
▶ 이번 달 오른 단원  #{오른단원}

▶ 담당 선생님 한마디
#{선생님한마디}

아래 버튼에서 이번 달 리포트를 보실 수 있어요.
단원별 도달 레벨, 시험대비 진행, 오답 재도전까지 한 장에 담았습니다.
```

**버튼 1개** — `웹링크(WL)`, 모바일·PC 같게:

| 순서 | 버튼명 | 링크 (모바일 = PC) |
|---|---|---|
| 1 | `월간 학습 리포트 보기` | `https://studycheck-five.vercel.app/report/#{리포트토큰}` |

> 버튼 이름에는 달을 넣을 수 없다(템플릿에 박히는 고정 글자다). 그래서 「10월 리포트 보기」가
> 아니라 「월간 학습 리포트 보기」다.

승인되면 템플릿 코드를 Vercel 의 **`ALIGO_MONTHLY_TPL_CODE`** 에 넣고 Redeploy.

**본문이 왜 짧은가** — 내용은 링크 뒤 한 장에 다 있다. 본문에는 「열어 볼 이유」만 담는다.
변수가 적을수록 심사도 수월하고, 글자 단위 대조가 어긋날 자리도 줄어든다.
실제 길이는 240~270자다(한도 1000자).

**★ 「담당 선생님 한마디」는 월간용 한 줄 평만 쓴다.** 그 달 마지막 알림장으로 떨어뜨리면
「오늘 15분 지각을 해서…」 같은 **하루치 이야기**가 한 달 총평 자리에 실린다(2026-10-24 확인).
안 쓰셨으면 「○월 한 달 기록을 정리했습니다…」로 나간다. 보고서 화면에서 학생마다 한 줄씩
적어 두시면 그게 나간다.

## ★ Vercel cron 은 **하루 한 번**만 된다 — 10분마다 쓰면 **배포가 실패한다** (2026-10-17)

이걸 모르고 `vercel.json` 을 `*/10 8-11 * * *` 로 바꿨다가, **그 뒤 모든 배포가 조용히
실패했다.** 10/17 11:09 부터 14:29 까지 올린 것이 하나도 안 떴다 — 토요일 18시 발송,
미작성 문자 한 번만, 일요일 시간표, 이름에 학년, 데일리테스트 전부.

* GitHub 커밋에 Vercel 이 `failure` 를 달아 두는데 아무도 안 본다. 링크를 따라가면
  `vercel.com/docs/cron-jobs/usage-and-pricing` 이다 — **플랜 제한**이라는 뜻이다.
* 이 프로젝트의 Vercel 플랜에서 cron 은 **최대 2개, 각각 하루 한 번**이다.
  (Supabase 는 Pro 지만 Vercel 은 별개다.)
* 게다가 하루 한 번짜리는 **정시에 안 나간다** — 한 시간 안에 아무 때나 깨운다.
  그래서 11시 발송이 11:50 에 나갔다.

**확인하는 법** — 배포가 됐는지 눈으로 믿지 말고 이렇게 본다:

```bash
curl -s https://api.github.com/repos/stodayis1/studycheck/commits/main/status
```

`state` 가 `success` 가 아니면 안 떴다. Vercel 화면에서는
Deployments → 맨 위 줄의 상태(Error/Ready) 를 본다.

**제시간에 깨우려면** Vercel cron 말고 **Supabase pg_cron** 을 쓴다. Supabase 는 Pro 라
분 단위로 돌 수 있고, 알리고를 거치는 그 고정 IP 와 같은 곳이다. `CRON_SECRET` 을
Supabase 쪽에 넣어 두고 10분마다 `/api/cron/briefing/evening` 을 부르면 된다.
그때까지는 `vercel.json` 을 **하루 한 번**으로 두어야 배포가 된다.

## ★ 제시간에 깨우는 것은 **Supabase pg_cron** 이다 (2026-10-20)

Vercel cron 은 이 플랜에서 **하루 한 번**, 그것도 **한 시간 안에 아무 때나** 깨운다.
재어 보면 늘 40~50분 늦었다 — 11:49 · 11:49 · 20:40 · 11:49. 게다가 하루 한 번으로는
토요일 18시와 평일 20시를 같은 자리에서 맞출 수 없다.

그래서 **Supabase pg_cron** 이 10분마다 깨운다(`docs/sql/제시간_자동발송_pgcron.sql`).

| 일거리 | 일정(UTC) | 한국시간 |
|---|---|---|
| `briefing-evening` | `*/10 8-11 * * *` | 17:00~20:50, 10분마다 |
| `briefing-morning` | `*/10 2 * * *` | 11:00~11:50, 10분마다 |

**10분마다 깨워도 하루 한 번만 나간다.** 깨어난 쪽은 라우트를 부를 뿐이고, 그 안에서
시각으로 막고(토 18:00 / 평일 20:00 / 오전 11:00) `cron_runs` 한 줄을 선점한다.
그래서 **Vercel cron 도 그대로 뒀다** — 둘이 같이 깨워도 한 번만 나간다(보험).

비밀값은 **Vault** 에 둔다(`studycheck_cron_secret`). `cron.job` 에 그대로 적으면
대시보드에서 다 보인다. 함수 `public.wake_briefing(text)` 는 **postgres 만** 부를 수 있다 —
학생·학부모도 `authenticated` 라, 열어 두면 아무나 발송을 깨울 수 있다.

> ★ Vercel 의 `CRON_SECRET` 과 Vault 의 값이 **같아야** 한다. 다르면 401 이 나고 조용히
> 안 나간다. 바꿀 때는 **두 곳을 같이** 바꿀 것. 닿는지는 아래로 확인한다:
> ```sql
> select public.wake_briefing('morning');
> select id, status_code, left(content,200) from net._http_response order by id desc limit 1;
> ```

## 자동 발송 (2026-10-12 켬)

하루 두 번, Vercel Cron 이 돌린다. `vercel.json` 의 crons 두 줄이 그것이다.

| 시각 | 경로 | 보내는 것 |
|---|---|---|
| **저녁 8시** (11:00 UTC) | `/api/cron/briefing?phase=1` | **그날** 수업 중 기록이 끝난 학생 (학년 구분 없음) |
| **다음 날 오전 11시** (02:00 UTC) | `/api/cron/briefing?phase=2` | **전날** 수업 중 그때 못 나간 나머지 |

중복은 `briefing_sends` 가 막는다 — 같은 학생·같은 수업일은 두 번 나가지 않는다.
그래서 2차에는 자연히 「1차에 못 나간 것」만 남는다.

예전에는 1차를 **초등부만** 보냈는데 2026-10-12 에 학년 구분을 없앴다. 기준이 학년이
아니라 「그 시각까지 작성이 끝났나」다.

### ★ 1차는 「출결만 찍힌 껍데기」를 보내지 않는다 (2026-10-22)

선생님들은 **출결을 먼저 찍고 진도·과제·알림장을 나중에 채우신다.** 그 사이에 저녁 8시가
지나면 「진도 기록 없음 / 오늘은 따로 낸 과제가 없어요」만 적힌 글이 학부모님께 가 버리고,
뒤에 채운 내용은 **영영 안 나간다** (`briefing_sends` 가 재발송을 막기 때문).

> 2026-10-21 이지훈·최다윤(고1): 19:44 에 출결만 찍힌 채 저장 → 20:00 발송 **153자**.
> 원장님이 그 뒤에 진도·과제·알림장을 채우셨고, 지금 값으로 다시 만들면 519자·540자다.
> 10월 들어 같은 모양이 45건이었다.

그래서 1차에서는 **출결 말고 적힌 것이 하나라도** 있어야 보낸다 — 진도·교재·과제·학습지
범위·영상·데일리테스트 점수·메모·보강메모·알림장 중 아무거나. 없으면 2차(다음 날 오전
11시)로 미룬다. 그 사이 선생님께는 담당 강사 알림 문자가 「진도·과제 비었음」으로 나간다.

- **결석은 이 기준을 쓰지 않는다.** 결석 자체가 할 말이고 보강 안내가 붙는다.

### 한 번 돌 때 하는 일 — 순서가 중요하다

1. **오타·문장 자동 교정** — AI 가 고칠 것을 내놓고, `lib/polishGuard.ts` 의 **기계 검사**를
   통과한 것만 반영한다. 숫자가 바뀌거나 교재 이름(쎈B·개념+유형라이트 등)이 바뀌거나
   글 길이가 튀면 **손대지 않는다.** 사람이 없는 시각이라 AI 를 믿고 맡기지 않는다.
   통과 못 한 것은 원장님이 「오타·문장 점검」 화면에서 직접 보고 고를 수 있다.
2. **학부모 발송** — `/api/kakao-briefing` 을 그대로 부른다(보내는 길은 한 곳뿐이다).
3. **담당 강사 알림** — 그 시각에도 덜 채워진 수업일지를 선생님별로 묶어 **문자**로 보낸다.
   발송 **뒤에** 세야 「지금도 덜 된 것」이 정확히 잡힌다.

알림톡이 아니라 문자인 이유 — 알림톡은 심사를 통과한 템플릿과 본문이 글자 단위로 같아야
하는데, 선생님께 가는 알림은 그날 학생 이름이 매번 다르다. 문자는 OPS 의 솔라피 경로를
쓴다(`lib/opsSms.ts` → OPS `api/sms/send-from-studycheck`).

### 끄는 법

`vercel.json` 에서 crons 를 빼고 배포한다. 그러면 한 건도 자동으로 나가지 않는다.
화면의 버튼(미리보기 → 발송)은 그대로 쓸 수 있다.

## 「시험기간 결석」은 브리핑을 보내지 않는다 (2026-10-08)

중·고등학생은 학교 시험기간에 학원을 안 나와도 원장님이 봐주신다. 그걸 일반 「결석」으로 적으면
보강이 잡히고 학부모 카톡에도 「결석」으로 나가는데, 학부모도 아는 상황을 굳이 들춰 보는 꼴이다.

그래서 학습일지 출결에 **「시험기간 결석」** 버튼을 따로 뒀다(세 버튼 아래 한 줄). 이걸 누르면:

| | |
|---|---|
| 카톡 브리핑 | **안 나간다.** 발송 결과에 「시험기간이라 건너뜀」으로 보고된다 |
| 출석률 | 분모에서 빠진다. 성실한 학생의 정시 출석률이 시험 때마다 떨어지지 않게 |
| 보강 | 안 잡는다. OPS 보강명단에는 올라가되 **「보강 안 함」**으로 닫혀서 뜬다 |
| 과제·성취도 | 저장하지 않는다 (결석과 같다) |
| 학부모 화면 | 빨간 「결석」이 아니라 보라색 「시험기간 결석」으로 보인다 |

값은 `learning_notes.attendance = '시험기간 결석'`. 코드에서는 `lib/attendance.ts` 의
`ATT_EXAM` 상수와 `isExamAbsence()` 로만 다룬다 — 2026-10-08 에 「시험기간」에서 이름을 바꿨고,
토큰 리포트의 jsonb 스냅샷에는 옛 이름이 얼어 있어 둘 다 받아 줘야 한다.

## 보내기 전에 미리 보는 법

`lib/briefingSnapshots.ts`)를 쓰므로, 여기서 본 글과 화면이 실제로 학부모에게 가는 것과 같다.

```

본문 전문과 세 링크를 찍어 준다. 그 링크를 폰에서 열면 학부모가 볼 화면 그대로다.
미리보기 링크는 7일 뒤 닫힌다(실제 발송분은 90일).

### 이 미리보기가 실제로 잡은 것 (2026-10-08)

1. **`report_links` 의 `report_type` CHECK 제약** 이 `daily/monthly/quarterly` 만 허용하고 있었다.
   안 넓혔으면 **첫 자동 발송에서 185명 전원이 링크 생성 단계에서 실패**했을 것이다.
2. **「통과율 97%」가 평균 60점인 학생에게 찍혔다.** `status='passed'` 를 통과로 세고 있었는데
   그건 「합격」이 아니라 **「처리 완료」** 다 — 전체 3,466건 중 513건이 70점 미만인데도 passed 다.
   진짜 규칙(`docs/초등레벨학습지.md`)은 **그 단원에서 가장 최근 채점한 본 학습지(main)가 70점 이상**.
   같은 학생을 SQL 로 따로 계산해 대조하니 **단원 통과 3/8** 이었다.

> 둘 다 코드만 읽어서는 안 보였다. **만들어서 열어 봐야** 보였다.

## 1,000자 한도 — 사람 눈으로 보지 말 것

알림톡 본문은 **변수를 끼운 뒤** 1,000자를 넘으면 카카오가 발송을 거부한다
(강조표기·아이템리스트·부가정보까지 합산).

실데이터 최악값: 진도 365 + 과제쪽 276 + 학습지범위 274 + 알림장 893 + 메모 418 = **2,226자**.
평소엔 220자쯤이라 눈으로 보면 늘 멀쩡하고, **긴 알림장을 쓴 날 그 학생만 조용히 실패**한다.

그래서 칸마다 상한을 두고 전체를 950자에서 한 번 더 조인다. 매번 사람이 확인하지 않아도 되게:

```bash
node scripts/briefing-check.ts
```

수업 6,560건 전량에 대해 길이를 재고 1,000자 초과가 0건인지 확인한다.
2026-10-08 기준: 중간값 218자 · 99% 431자 · **최대 537자 · 초과 0건**.

> 이 검사가 실제로 버그를 잡았다. 처음에 치환 정규식을 `/#\{(\w+)\}/` 로 썼는데 `\w` 가
> 한글을 못 잡아 `#{학생명}` 이 그대로 남았다. 모든 본문이 171자(=골격 그대로)로 똑같이
> 나오는 걸 보고 알았다. 눈으로 한 건만 봤으면 못 찾았다.

## 보안

- 토큰은 16바이트 난수(32자)라 추측이 안 된다.
- `report_links.data` 는 **발송 시점의 값을 떠 둔 사진**이다. 페이지가 DB 를 더 읽지 않으니
  링크를 주워도 살아 있는 자료나 **남의 자녀 기록으로 넘어갈 수 없다.**
- `get_report_by_token` 만 이 표를 읽는다(SECURITY DEFINER). `report_links` 자체는 RLS 로 막혀 있다.
- 90일이 지나면 링크가 닫히고 Cron 이 치운다.
- 브리핑에 나오는 「학습지」는 **레벨학습지**(전원 대상)다. 문제은행 학습지·QR 채점은
  아직 시범 대상(윤수지 학생)만이라 브리핑과 버튼 화면에 섞지 않았다 — `lib/pilot.ts` 참고.

## 비용

월 발송량 약 1,750건. 알리고 알림톡 단가 기준 **월 2만원 안팎**.
