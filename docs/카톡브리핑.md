# 카톡 수업 브리핑

학부모에게 **어제 수업을 다음 날 오전 11시**에 알림톡으로 보낸다.
학부모가 앱에 들어오지 않아도 읽게 하는 것이 목적이다.

## 왜 "다음 날 오전 11시"인가

선생님들이 학습현황을 저장하는 시각을 최근 30일(1,809건)로 재 봤다.

| 저장 완료 | 누적 |
|---|---|
| 당일 21시까지 | 55% |
| 당일 22시까지 | 72% |
| 당일 23시까지 | 95% |
| 다음날 새벽(0~3시) | 나머지 3.5% |

**그날 밤에 보내면 절반이 빈 브리핑으로 간다.** 다음 날 오전이면 1,809건이 전부 기록 완료였다.
밤 11시 발송은 기록은 차지만 그 시각 카톡은 민원이 된다.

## 보내는 곳 — 알리고 (Aligo)

2026-10-08 에 **솔라피 → 알리고**로 옮겼다(원장님 결정). 옛 `/api/send-kakao`(솔라피)와
`/admin/test-kakao` 는 지웠고, 한 사람짜리 발송도 브리핑과 **같은 경로**를 쓴다 —
업체도 템플릿도 요금도 하나다.

알리고가 이 일에 더 나은 점:

| | 솔라피 | 알리고 |
|---|---|---|
| 변수 치환 | 알림톡 서버가 `#{변수}` 를 채움 | **완성된 본문을 그대로 보냄** (우리가 이미 만든다) |
| 시험 발송 | 없음 — 진짜로 나가고 요금도 나감 | **`testMode=Y`** 로 전 과정을 요금 없이 |
| 잔액 | 따로 확인 | **응답이 남은 포인트·건당 단가를 준다** |
| 템플릿 등록 | 콘솔에서 손으로 | **API 로도 가능** (`/akv10/template/add/` + 검수요청) |
| 실패 시 문자 | 따로 구현 | `failover=Y` 로 내장 |

### ★ 반드시 알아야 할 두 가지

1. **알리고는 변수를 채워 주지 않는다.** 우리가 만든 본문을 그대로 보내고,
   그 본문이 **승인된 템플릿 서식과 일치해야** 전송된다. 안 맞으면 조용히 안 간다.
   그래서 `lib/briefing.ts` 의 `BRIEFING_TEMPLATE` 하나가 「등록할 원문」이자 「보낼 본문의 틀」이다.
   **템플릿을 바꾸면 그 상수도 같이 바꿔야 한다.**
2. **실패해도 HTTP 200 을 준다.** 응답 본문의 `code` 로만 성패를 안다(알림톡은 `0` 이 성공).
   `res.ok` 만 보고 성공으로 치면 한 건도 안 갔는데 「발송 완료」가 찍힌다.
   `lib/aligo.ts` 가 이걸 막는다.

## 원장님이 하셔야 하는 일 (한 번만)

### 1. 알리고 가입 + 카카오채널 연동

[알리고](https://smartsms.aligo.in) 가입 → 카카오채널(`@수학의지혜` 등)을 연동한다.
별도 신청 절차 없이 채널 연동만으로 쓸 수 있다. 채널이 없으면
[카카오 채널 관리자센터](https://center-pf.kakao.com)에서 먼저 만든다.

### 2. 템플릿 등록 → 카카오 심사 (4~5일)

**템플릿 이름**: `수업 브리핑 (일일)` · **유형**: 기본형(BA) / 강조유형 없음(NONE) / 정보성

**본문** — 아래를 그대로 넣는다. **글자 하나, 줄바꿈 하나라도 다르면 전송이 거부된다.**
(코드 쪽 원문은 `lib/briefing.ts` 의 `BRIEFING_TEMPLATE` 하나뿐이고, 길이 검사도 그걸 쓴다)

```
[수학의지혜 수업 브리핑]
#{학생명} 학생 · #{날짜}

▶ 출결  #{출결}
▶ 과제 달성률  #{과제달성률}
▶ 지난 학습지  #{학습지결과}

▶ 오늘 나간 진도
#{진도}

▶ 다음 시간까지 과제
#{과제배부}

▶ 선생님 알림장
#{알림장}

아래 버튼에서 아이의 누적 현황을 보실 수 있어요.
```

**버튼 3개** — 모두 `웹링크(WL)`, 모바일·PC 링크 같게:

| 순서 | 버튼명 | 링크 (모바일 = PC) |
|---|---|---|
| 1 | `레벨학습지 점수 현황` | `https://studycheck-five.vercel.app/report/#{점수토큰}` |
| 2 | `출결·과제달성률 현황` | `https://studycheck-five.vercel.app/report/#{출결토큰}` |
| 3 | `알림장·사진 보기` | `https://studycheck-five.vercel.app/report/#{알림장토큰}` |

> **버튼이 왜 3개인가** — 원장님이 말씀하신 두 가지(점수 현황·출결과 달성률)에 하나를 더했다.
> **알림톡은 본문에 가변 이미지를 못 싣는다**: 템플릿당 고정 이미지 1장만 되고 그 이미지엔 링크도
> 못 건다. 즉 학생마다 다른 사진(알림장 첨부 사진)은 애초에 본문에 넣을 수 없다. 사진이 열릴
> 자리가 필요해서 3번째 버튼을 뒀다. 사진이 없는 날엔 그날 알림장 전문·진도·과제가 보인다.
> 1·2번만 등록하셔도 되고, 그러면 사진은 앱에서만 보인다 (코드에서 버튼 하나를 빼면 된다).

### 2-1. 심사 통과 뒤 — **보내기 전에 반드시 템플릿 대조**

학습관리 → 수업일지 맨 위 「카톡 수업 브리핑」 칸의 **「템플릿 맞는지 확인」** 을 먼저 누른다.

알리고는 변수를 채워 주지 않는다. 우리가 만든 본문이 **승인된 템플릿과 글자 단위로 같아야**
전송되고, 안 맞으면 **에러도 없이 그냥 안 간다.** 심사 과정에서 카카오가 문구를 고치게 하는
일이 흔한데, 그걸 모르고 발송을 걸면 185명이 통째로 실패한다.

이 버튼이 알리고에서 **실제 등록된 템플릿**을 가져와 `lib/briefing.ts` 의 `BRIEFING_TEMPLATE`
과 대조하고, 다르면 **몇 번째 글자부터 어떻게 다른지** 보여 준다. 그대로 알려주면 코드를
알리고 쪽에 맞추면 된다. 승인상태(APR)와 버튼 개수도 함께 확인한다.

### 3. Vercel 환경변수 (Settings → Environment Variables)

| 이름 | 어디서 얻나 |
|---|---|
| `ALIGO_API_KEY` | 알리고 → API 연동 → 인증키 |
| `ALIGO_USER_ID` | 알리고 로그인 아이디 |
| `ALIGO_SENDER_KEY` | 발신프로필 키 (채널 연동하면 발급) |
| `ALIGO_SENDER_PHONE` | 알리고에 등록된 발신번호 |
| `ALIGO_BRIEFING_TPL_CODE` | **심사 통과한 템플릿 코드** (`TXXXXXXXX` 꼴) |
| `CRON_SECRET` | 아무 긴 임의 문자열. 없으면 자동 발송이 401 로 막힌다 |
| `ALIGO_TEST_MODE` | **안 넣으면 `Y`(테스트)가 기본.** 진짜로 보낼 때 `N` 으로 |
| `ALIGO_FAILOVER` | 알림톡이 안 닿는 번호에 문자로 대신 보낼지 (기본 `N`) |

> **`ALIGO_TEST_MODE` 가 기본 켜짐인 이유** — 설정을 덜 한 상태에서 실수로 185명에게 나가는
> 사고를 막는다. 테스트 모드에서는 요금도 안 나가고 학부모에게도 안 간다.
> 화면과 응답에 「테스트 모드」라고 분명히 표시된다.

## 보내기 전에 미리 보는 법

**보내지 않고** 실제 데이터로 링크 3개를 만든다. 발송 라우트와 **같은 함수**(`lib/briefing.ts`,
`lib/briefingSnapshots.ts`)를 쓰므로, 여기서 본 글과 화면이 실제로 학부모에게 가는 것과 같다.

```bash
node scripts/briefing-preview.ts 2026-10-07
```

```bash
node scripts/briefing-preview.ts 2026-10-07 박지호
```

본문 전문과 세 링크를 찍어 준다. 그 링크를 폰에서 열면 학부모가 볼 화면 그대로다.
미리보기 링크는 7일 뒤 닫힌다(실제 발송분은 90일).

### 이 미리보기가 실제로 잡은 것 (2026-10-08)

1. **`report_links` 의 `report_type` CHECK 제약** 이 `daily/monthly/quarterly` 만 허용하고 있었다.
   안 넓혔으면 **첫 자동 발송에서 185명 전원이 링크 생성 단계에서 실패**했을 것이다.
2. **「통과율 97%」가 평균 60점인 학생에게 찍혔다.** `status='passed'` 를 통과로 세고 있었는데
   그건 「합격」이 아니라 **「처리 완료」** 다 — 전체 3,466건 중 513건이 70점 미만인데도 passed 다.
   진짜 규칙(`docs/초등레벨학습지.md`)은 **그 단원에서 가장 최근 채점한 본 학습지(main)가 70점 이상**.
   같은 학생을 SQL 로 따로 계산해 대조하니 **단원 통과 3/8** 이었다.

> 둘 다 코드만 읽어서는 안 보였다. **만들어서 열어 봐야** 보였다.

## 1,000자 한도 — 사람 눈으로 보지 말 것

알림톡 본문은 **변수를 끼운 뒤** 1,000자를 넘으면 카카오가 발송을 거부한다
(강조표기·아이템리스트·부가정보까지 합산).

실데이터 최악값: 진도 365 + 과제쪽 276 + 학습지범위 274 + 알림장 893 + 메모 418 = **2,226자**.
평소엔 220자쯤이라 눈으로 보면 늘 멀쩡하고, **긴 알림장을 쓴 날 그 학생만 조용히 실패**한다.

그래서 칸마다 상한을 두고 전체를 950자에서 한 번 더 조인다. 매번 사람이 확인하지 않아도 되게:

```bash
node scripts/briefing-check.ts
```

수업 6,560건 전량에 대해 길이를 재고 1,000자 초과가 0건인지 확인한다.
2026-10-08 기준: 중간값 218자 · 99% 431자 · **최대 537자 · 초과 0건**.

> 이 검사가 실제로 버그를 잡았다. 처음에 치환 정규식을 `/#\{(\w+)\}/` 로 썼는데 `\w` 가
> 한글을 못 잡아 `#{학생명}` 이 그대로 남았다. 모든 본문이 171자(=골격 그대로)로 똑같이
> 나오는 걸 보고 알았다. 눈으로 한 건만 봤으면 못 찾았다.

## 보안

- 토큰은 16바이트 난수(32자)라 추측이 안 된다.
- `report_links.data` 는 **발송 시점의 값을 떠 둔 사진**이다. 페이지가 DB 를 더 읽지 않으니
  링크를 주워도 살아 있는 자료나 **남의 자녀 기록으로 넘어갈 수 없다.**
- `get_report_by_token` 만 이 표를 읽는다(SECURITY DEFINER). `report_links` 자체는 RLS 로 막혀 있다.
- 90일이 지나면 링크가 닫히고 Cron 이 치운다.
- 브리핑에 나오는 「학습지」는 **레벨학습지**(전원 대상)다. 문제은행 학습지·QR 채점은
  아직 시범 대상(윤수지 학생)만이라 브리핑과 버튼 화면에 섞지 않았다 — `lib/pilot.ts` 참고.

## 비용

월 발송량 약 1,750건. 알리고 알림톡 단가 기준 **월 2만원 안팎**.
정확한 단가와 남은 포인트는 **발송 응답이 직접 알려 준다**(`info.unit`, `info.current`) —
화면의 발송 결과에 「남은 포인트」로 찍힌다. 포인트가 떨어지면 `code: -99 포인트가 부족합니다`
가 오는데, 그때는 **남은 사람도 전부 같은 이유로 실패하므로 거기서 멈추고** 원장님께 알린다.

`ALIGO_FAILOVER=Y` 로 두면 알림톡이 안 닿는 번호에 같은 내용을 문자로 보낸다.
본문이 300자쯤이라 장문(LMS) 요금이라 알림톡보다 훨씬 비싸다 — 기본은 꺼 둔다.
