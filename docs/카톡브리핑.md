# 카톡 수업 브리핑

학부모에게 **어제 수업을 다음 날 오전 11시**에 알림톡으로 보낸다.
학부모가 앱에 들어오지 않아도 읽게 하는 것이 목적이다.

## 왜 "다음 날 오전 11시"인가

선생님들이 학습현황을 저장하는 시각을 최근 30일(1,809건)로 재 봤다.

| 저장 완료 | 누적 |
|---|---|
| 당일 21시까지 | 55% |
| 당일 22시까지 | 72% |
| 당일 23시까지 | 95% |
| 다음날 새벽(0~3시) | 나머지 3.5% |

**그날 밤에 보내면 절반이 빈 브리핑으로 간다.** 다음 날 오전이면 1,809건이 전부 기록 완료였다.
밤 11시 발송은 기록은 차지만 그 시각 카톡은 민원이 된다.

## 원장님이 하셔야 하는 일 (한 번만)

### 1. Solapi 콘솔에 템플릿 등록 → 카카오 심사 (1~3영업일)

**템플릿 이름**: `수업 브리핑 (일일)`
**메시지 유형**: 기본형 / **정보성**

**본문** — 아래를 그대로 복사해서 넣는다. 글자 하나라도 다르면 심사받은 것과 달라져 발송이 거부된다.
(코드 쪽 원문은 `lib/briefing.ts` 의 `BRIEFING_TEMPLATE` 하나뿐이고, 길이 검사도 그걸 쓴다)

```
[수학의지혜 수업 브리핑]
#{학생명} 학생 · #{날짜}

▶ 출결  #{출결}
▶ 과제 달성률  #{과제달성률}
▶ 지난 학습지  #{학습지결과}

▶ 오늘 나간 진도
#{진도}

▶ 다음 시간까지 과제
#{과제배부}

▶ 선생님 알림장
#{알림장}

아래 버튼에서 아이의 누적 현황을 보실 수 있어요.
```

**버튼 3개** — 모두 `웹링크(WL)` 형, 모바일/PC 링크 같게:

| 순서 | 버튼 이름 | 링크 |
|---|---|---|
| 1 | 레벨학습지 점수 현황 | `https://studycheck-five.vercel.app/report/#{점수토큰}` |
| 2 | 출결·과제달성률 현황 | `https://studycheck-five.vercel.app/report/#{출결토큰}` |
| 3 | 알림장·사진 보기 | `https://studycheck-five.vercel.app/report/#{알림장토큰}` |

> **버튼이 왜 3개인가** — 원장님이 말씀하신 두 가지(점수 현황·출결과 달성률)에 하나를 더했다.
> **알림톡은 본문에 가변 이미지를 못 싣는다**: 템플릿당 고정 이미지 1장만 되고 그 이미지엔 링크도
> 못 건다. 즉 학생마다 다른 사진(알림장 첨부 사진)은 애초에 본문에 넣을 수 없다. 사진이 열릴
> 자리가 필요해서 3번째 버튼을 뒀다. 사진이 없는 날엔 그날 알림장 전문·진도·과제가 보인다.
> 3개로 심사받고 싶지 않으시면 1·2번만 등록하시면 되고, 그러면 사진은 앱에서만 보인다.

### 2. Vercel 환경변수 (Settings → Environment Variables)

| 이름 | 설명 |
|---|---|
| `SOLAPI_API_KEY` · `SOLAPI_API_SECRET` | Solapi 계정 키 |
| `SOLAPI_PF_ID` | 카카오 채널 발신프로필 키 |
| `SOLAPI_BRIEFING_TEMPLATE_ID` | **위에서 심사 통과한 템플릿의 ID** (없으면 기존 `SOLAPI_TEMPLATE_ID` 를 쓴다) |
| `SOLAPI_SENDER_PHONE` | 등록된 발신번호 |
| `CRON_SECRET` | 아무 긴 임의 문자열. Vercel 이 자동 발송 요청에 붙여 주고, 이 값이 없으면 자동 발송이 401 로 막힌다 |

### 3. 빠진 보호자 번호 채우기

지금 **강보민(중3)** 한 명만 보호자 전화번호가 비어 있다(최근 30일 수업 10회).
번호가 없으면 그 학생은 브리핑에서 조용히 빠진다.

### 4. DB 준비 (한 번)

`docs/sql/카톡브리핑_준비.sql` 적용. 되돌리기는 `docs/sql/카톡브리핑_준비_되돌리기.sql`.
- `report_links.expires_at` — 링크 90일 만료 (지금은 영구히 산다)
- `get_report_by_token` — 만료된 링크는 안 내준다
- `briefing_sends` — **(학생, 날짜) 유일 제약으로 중복 발송을 DB 가 막는다**

## 어떻게 돌아가나

```
매일 02:00 UTC = 11:00 KST
  Vercel Cron → GET /api/kakao-briefing   (Authorization: Bearer CRON_SECRET)
     ├ 어제 날짜의 class_sessions 를 모은다
     ├ learning_notes 에 출결이 적힌 학생만 (기록 미완은 건너뛰고 보고)
     ├ 보호자 번호 있는 학생만
     ├ briefing_sends 에 이미 있으면 건너뜀 (중복 차단)
     ├ 본문을 만들고 (lib/briefing.ts) 1,000자 안으로 조인다
     ├ report_links 3건 생성 — 점수 / 출결 / 알림장
     ├ Solapi 알림톡 발송
     ├ briefing_sends 에 결과 기록 (성공·실패·본문 길이)
     └ 만료된 report_links 정리
```

원장님이 직접 돌리실 때는 **학습관리 → 수업일지** 맨 위 「카톡 수업 브리핑」 칸에서
날짜를 고르고 **미리보기 → N명에게 발송**. 미리보기를 안 보면 발송 버튼이 나오지 않는다.

## 1,000자 한도 — 사람 눈으로 보지 말 것

알림톡 본문은 **변수를 끼운 뒤** 1,000자를 넘으면 카카오가 발송을 거부한다
(강조표기·아이템리스트·부가정보까지 합산).

실데이터 최악값: 진도 365 + 과제쪽 276 + 학습지범위 274 + 알림장 893 + 메모 418 = **2,226자**.
평소엔 220자쯤이라 눈으로 보면 늘 멀쩡하고, **긴 알림장을 쓴 날 그 학생만 조용히 실패**한다.

그래서 칸마다 상한을 두고 전체를 950자에서 한 번 더 조인다. 매번 사람이 확인하지 않아도 되게:

```bash
node scripts/briefing-check.ts
```

수업 6,560건 전량에 대해 길이를 재고 1,000자 초과가 0건인지 확인한다.
2026-10-08 기준: 중간값 218자 · 99% 431자 · **최대 537자 · 초과 0건**.

> 이 검사가 실제로 버그를 잡았다. 처음에 치환 정규식을 `/#\{(\w+)\}/` 로 썼는데 `\w` 가
> 한글을 못 잡아 `#{학생명}` 이 그대로 남았다. 모든 본문이 171자(=골격 그대로)로 똑같이
> 나오는 걸 보고 알았다. 눈으로 한 건만 봤으면 못 찾았다.

## 보안

- 토큰은 16바이트 난수(32자)라 추측이 안 된다.
- `report_links.data` 는 **발송 시점의 값을 떠 둔 사진**이다. 페이지가 DB 를 더 읽지 않으니
  링크를 주워도 살아 있는 자료나 **남의 자녀 기록으로 넘어갈 수 없다.**
- `get_report_by_token` 만 이 표를 읽는다(SECURITY DEFINER). `report_links` 자체는 RLS 로 막혀 있다.
- 90일이 지나면 링크가 닫히고 Cron 이 치운다.
- 브리핑에 나오는 「학습지」는 **레벨학습지**(전원 대상)다. 문제은행 학습지·QR 채점은
  아직 시범 대상(윤수지 학생)만이라 브리핑과 버튼 화면에 섞지 않았다 — `lib/pilot.ts` 참고.

## 비용

월 발송량 약 1,750건. Solapi 알림톡 단가 기준 **월 2만원 안팎**(VAT 별도).
발송 실패분을 문자로 대체 발송하지는 않는다 — 문자가 훨씬 비싸고, 실패는 화면에 목록으로 뜬다.
