# 배포 · 환경변수 · 백업

## 배포

- **Vercel** 프로젝트 `studycheck`. `main` 브랜치에 push하면 자동 배포된다.
- 주소: https://studycheck-five.vercel.app
- 환경변수만 바꿨을 때는 push가 없으므로 **Deployments → 맨 위 → Redeploy**를 눌러야 반영된다.
- 문제가 생기면 **Instant Rollback**으로 직전 배포로 즉시 되돌릴 수 있다.

## 환경변수 (Vercel Settings → Environment Variables)

| 이름 | 용도 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 주소 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 브라우저용 공개 키 (`sb_publishable_...`, Type=**Config**) |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 마스터키 (`sb_secret_...`, Type=Secret) |
| `ANTHROPIC_API_KEY` | AI 보고서 생성 |
| `OPS_SUPABASE_URL` / `OPS_SUPABASE_SERVICE_ROLE_KEY` | 수학OPS DB 직접 접근 |
| `OPS_SYNC_URL` / `OPS_SYNC_SECRET` | OPS 결석 연동 |
| `SOLAPI_*` | 알림톡/문자 발송 |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | 웹 푸시 |

모두 Production and Preview에 체크돼 있어야 한다.
로컬 개발용 같은 값이 `.env.local`에 있다 (git에는 올라가지 않음 — `.gitignore`의 `.env*`).

## 백업 — 여기가 제일 약하다

Supabase는 **Pro 플랜**(조직 `수학의지혜`). 자동 일일 백업이 돈다.

**확인·결정이 필요한 것:**
1. **PITR(특정 시점 복구)은 Pro 기본 포함이 아니다.** 유료 추가 옵션.
   없으면 "어제 백업 시점"으로만 돌아갈 수 있다. Database → Backups에서 확인.
2. **Storage(문제 이미지 23,257장)는 DB 백업에 포함되지 않을 가능성이 크다.**
   날아가면 문제은행이 텅 빈다. 원본 PDF/이미지를 별도로 보관해야 한다.
   원장님 컴퓨터 `C:\Users\USER\문제은행` 에 원본이 있다 — 이게 사실상 유일한 백업이므로
   외장하드나 클라우드에 한 벌 더 두는 게 좋다.
3. 코드는 GitHub에 있으므로 별도 백업이 필요 없다.

## 장애가 났을 때

| 증상 | 먼저 볼 것 |
|---|---|
| 화면이 비거나 데이터가 안 뜸 | Vercel 최근 배포 → 실패했으면 Instant Rollback |
| 로그인이 안 됨 | Supabase 키가 만료·비활성화됐는지 (Settings → API Keys) |
| 특정 화면만 데이터가 사라짐 | 최근 RLS 정책 변경 의심. `pg_policies` 확인 |
| 학생이 "로그인이 잠겼다" | 15분 5회 실패 잠금. 15분 기다리거나 `student_login_attempts`에서 해당 행 삭제 |
| OPS 연동이 조용히 안 됨 | 양쪽 `*_SERVICE_ROLE_KEY` 환경변수 불일치 의심 |

## 로컬에서 돌리기

```bash
npm install
npm run dev     # http://localhost:3000
```
`.env.local`이 있어야 한다. 없으면 Vercel 환경변수에서 복사.
