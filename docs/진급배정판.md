# 진급 배정판 — 중3 → 고등 · 초6 → 중등 · 초등 진급

학년이 올라갈 때 **누가 어느 선생님·어느 타임으로 가는지** 미리 맞춰 보는 판.
화면은 `app/teacher/move-assign` 한 곳이고 탭이 **세 장**이다. 메뉴 이름은 「진급 배정판」.

**이것은 계획이다.** 저장해도 `schedules`(실제 시간표)·`students.teacher_name`(담당)은 건드리지 않는다.
진급할 때 옮기는 일은 따로 한다 — 그러니 여기서 아무리 고쳐도 지금 수업·브리핑·출결에 영향이 없다.
화면 맨 위에도 그 한 줄을 적어 두었다(안 적으면 눌러 보기를 무서워하신다).

## 세 판이 다르다

| | 고등 (중3 →) | 중등 (초6 →) | 초등 (초1~초5 →) |
|---|---|---|---|
| 정하는 것 | 선생님 + **평일 타임** + **토·일 타임** | **선생님만** | 선생님 + **바뀔 시간** |
| 왜 | 고등부는 정해진 타임으로 돌아간다 | 초6은 지금 쓰는 시간표를 그대로 가져온다 | 같은 초등부 안에서 다시 나누는 것이다 |
| 첫 제안 | 원장님이 맞춰 두신 `DRAFT_HIGH` | 원장님이 맞춰 두신 `DRAFT_MID` | **지금 담당 그대로** (`elemDraft`) |
| 보는 것 | 타임별 인원 · 선생님별 시간표(새 타임) | 그 시각에 그 선생님 반이 몇 명이 되나 | 같음 — 빠지는 자리는 중등으로 올라가는 **초6** |

### 초등 판 (원장님 2026-11-17)

> 「초등학생들도 한학년 올라가면서 윤주희, 조윤희 강사 담당 학생들을 다시 배정할거거든.
>  현재 담당 학생들 학년 올라가면서 배정할수 있도록 진급배정판에 초등버전 하나더 만들어줘」

- 오르는 학년 `GRADES_ELEM` = **초1~초5** (초6 은 중등 판이 맡는다)
- 고를 수 있는 선생님 `ELEM_PICKS` = **윤주희 · 조윤희 · 이규숙** (원장님이 2026-11-17 에 고르심)
- 첫 제안은 **지금 담당 그대로**(`elemDraft`) — 부(部)를 옮기는 것이 아니라서 **바꿀 학생만** 고치면 된다.
  담당 칸에 「조윤희, 이규숙」처럼 **두 분이 같이** 적힌 줄은 기계가 고를 수 없으므로 **비워 둔다.**
- 2026-11-17 기준 초1~초5 **51명** (윤주희 26 · 조윤희 17 · 이규숙 8) — 모두 첫 제안이 찬다.
- 격자 `ROWS_ELEM` = 14:00~18:00 한 시간 칸. 지금 초등 시간표가 14·15·16·17시 시작 2교시뿐이다.
- 바꾼 학생은 줄이 초록으로 바뀌고 「바뀜 · 윤주희 → 조윤희」가 붙는다.

#### 바뀔 시간 (원장님 2026-11-18)

> 「시간이 바껴서 진급하는 학생들도 있거든. 담당도 바뀌고. … 시간도 변경하는 기능이 지금은 없어」

고등 판은 정해진 타임(`ja`·`at1` …)을 고르지만 초등엔 그런 반이 없다. 그래서 **요일 + 시작 시각 + 교시**
를 그대로 고른다(`class_move_assign.new_time` · jsonb).

```json
{ "days": ["월","수"], "start": "16:00", "periods": 2 }
```

- **비워 두면 지금 시간표 그대로**다. 요일을 다 끄면 도로 비워진다(「지금 그대로」).
- 처음엔 지금 시간표가 **흐리게** 들어가 있고, 하나라도 건드리면 그때부터 「바꾼 것」이다.
- 고르는 값은 `ELEM_STARTS`(14:00~18:00 30분 간격) · `ELEM_PERIODS`(1·1.5·2·2.5·3). 1교시 = 60분.
- 판단은 `parseNewTime()` **한 곳**에만 있다 — 화면·서버·검사가 같이 쓴다. **반쯤 맞는 값은 null**
  (= 지금 시간표 그대로)로 떨어뜨린다. 받아 주면 **격자에 안 그려지는 학생**이 조용히 생긴다.
- **격자가 바뀐 자리로 다시 그려진다**(`newTimeAt`). 이게 핵심이다 — 시간을 옮겨 놓고 격자가
  옛 자리로 세면 「그 칸에 몇 명」이 **거짓이 된다.**
- 「못 오시는 요일」도 **바꾼 요일**로 본다.
- 선생님만 바꿔도 시간은 **그대로 둔다**(반대도 같다). 둘은 따로 정하는 것이다.

★ 격자(`ROWS_ELEM`)를 2026-11-18 에 한 시간 칸 → **30분 칸**(14:00~19:00)으로 바꿨다.
16:30 을 고를 수 있는데 한 시간 칸이면 그 학생이 17:00 줄에만 그려진다(지금도 16:30 시작이 6명).

★ `new_time` 칸은 `docs/sql/진급배정판_초등시간.sql`(되돌리기 짝 있음)을 **코드보다 먼저** 넣어야 한다.

## 타임 열쇠 — `lib/moveAssign.ts` 한 곳

`weekday_slot` · `weekend_slot` 에 들어가는 글자의 뜻은 거기 있다. 한 타임은
**키움쌤 수업 + 채움쌤(이규숙) 클리닉**으로 이어진다.

- 평일 `at1`·`at2`·`at3` = 월·금 4~7 / 5~8 / 7~10 (최대호), `bt1`~`bt3` = 같은 타임의 수요일
- 평일 `ja`·`jb` = 화·목 5:30~8:30 / 6:30~9:30 (주한), `jb0` = 정규만 다니는 자리(solo)
- 토·일 `sat-r1`·`sat-r2` = 토 정규 10~12 + 클리닉 1·2타임(수 반), `sat-c1`·`sat-c2` = 클리닉만(월·금 반)
- 토·일 `j-sat1`·`j-sat2` = 주한 토 클리닉 1·2반(어느 반 학생이든 고를 수 있다), `j-sun` = 일 09~12
- `solo: true` 인 자리는 그 학생 혼자 쓰는 시간표라 **고르는 목록에 내보이지 않는다**

**추가 클리닉** (`EXTRA` · `class_move_assign.extra_slot`) — 채움쌤 근무가 9시까지라
**월·수·금 20:00~21:00** 에 따로 부르는 자리가 있다 (원장님 2026-11-17 「그때 더 남는 애들이나
추가로 부를 애들 부르는 것으로」). 반(평일 타임)과 **겹쳐도 된다** — 반은 그대로 두고 이 칸만
더 고르면 된다. `c-mwf`(세 날 다) · `c-mf`(월·금) · `c-w`(수). 비워 두면 안 부르는 것이다.

**살펴볼 줄** — 수 반(`b*`)은 토 정규까지 오고 월·금 반(`a*`)은 클리닉만 오는 것이 기본이다.
어긴 줄은 맨 위 목록에 띄우지만 **막지 않는다**(원장님이 일부러 그러실 수 있다).

**못 오시는 요일** — `NO_SHOW` (지금은 신애진 선생님 목요일). 중등 판에서 그 요일에 수업이 있는
학생을 그분께 보내면 빨간 줄로 알린다.

## 명단은 **서버 API 로** 읽는다 — RLS 때문에

`app/api/move-assign` (GET 읽기 · POST 한 줄 저장). 화면이 브라우저에서 `students` 를 직접 읽지 않는다.

★ **왜** (2026-11-17, 원장님 「왜 초등이 중등으로 넘어오는 시간표가 안보이는거지?」 — 신애진
선생님 화면에서 초6 이 **0명**으로 나왔다)
학생 조회 정책(`students.staff_or_own`)은 **담당 학생 + 주임 학년**만 읽힌다. 중등 선생님은
초6 을 한 명도 못 읽는데, 「초6 → 중등」 탭이 보여야 하는 분이 바로 그분들이다.
브라우저에서 직접 읽으면 **조용히 0명**이 된다 — 에러도 안 난다.
그렇다고 `students` 정책을 넓히면 **앱 전체에서** 초등이 열리므로, 이 화면이 쓰는 학년
(초6·중1·중2·중3·고1·고2)만 서버가 `service_role` 로 읽어 내려 준다.

막는 길은 두 겹이다 — `staffOrDeny`(직원인가) → **그 사람 토큰으로** `can_see_high_curriculum()`
(이 화면을 볼 사람인가). 규칙을 TS 로 베껴 쓰지 않고 **DB 함수 한 곳**을 그대로 따른다.
POST 는 없는 타임 열쇠도 막는다(화면에서 그 학생이 아무 칸에도 안 그려지게 되므로).

## 명단은 DB 에서 읽는다

학생은 `students`, 시간표는 `schedules` 를 그대로 읽는다. 원생이 들어오고 나가면 저절로 맞는다.
코드에 박아 둔 것은 **처음 제안**(`DRAFT_HIGH` · `DRAFT_MID`)뿐이고, 저장된 것이 있으면 저장된 쪽이 이긴다.

처음 제안은 **원장님이 아티팩트에서 2026-11-13 까지 맞춰 두신 그대로**를 옮긴 것이다.
이어 붙이는 열쇠는 `이름|학년` 이고, 한 열쇠에 학생이 둘 이상 걸리면 **붙이지 않는다** —
2026-11-17 기준 재원생에 유연우·이수연·이지훈이 각각 두 명이고 셋 다 고등부 명단에 있었다.

## 표와 보이는 사람

`class_move_assign` (`docs/sql/진급배정판.sql` · 되돌리기 짝 있음). 한 학생 한 줄,
`track` 이 '고등'/'중등'/**'초등'**.

★ 칸이 **하나씩 늘어난다** — `new_time`(초등 바뀔 시간)이 2026-11-18 에 생겼다. 검사가 칸 이름을
하나하나 읽어 보므로, 칸을 더할 때는 `scripts/move-assign-check.ts` 의 목록에도 이름을 넣는다.

★ `track` 에는 **CHECK 가 걸려 있다.** '초등' 을 더하려면 `docs/sql/진급배정판_초등판.sql`
(되돌리기 짝 있음)을 **코드보다 먼저** 넣어야 한다. 안 넣으면 화면은 멀쩡히 뜨는데
**고르는 순간 저장만** 빨간 글로 막힌다. 검사가 없는 학생 id 로 일부러 실패하는 넣기를 해 보고
돌아온 코드로 가른다(23514 = 아직 안 넣음 · 23503 = 넣었음). 아무것도 써지지 않는다.

권한이 **세 갈래**다 (원장님 2026-11-17 「전체 인원을 볼 필요가 없어 / 진급 배정판만 보는 권한을
따로 만들자」 — 초6 27명 중 13명의 담당인 조윤희·윤주희 선생님이 판을 못 보고 계셨다).

| | 고등 커리큘럼 | 진급 배정판 | 보이는 탭 |
|---|---|---|---|
| 원장님 · 주한 · 최대호 · 이규숙 · 김은수 · 박경미 · 신애진 | ○ | ○ | 세 장 다 |
| **조윤희 · 윤주희** (초등 담당) | ✗ | ○ | **「초6 → 중등」·「초등 진급」** |
| 행정 · 학생 · 학부모 | ✗ | ✗ | — |

- `can_see_high_curriculum()` — 원장님, 재원 고등학생을 맡은 강사, `app_settings.high_curriculum_teachers`
- `can_see_move_assign()` — 위에 더해 `app_settings.move_assign_teachers`
  (`docs/sql/진급배정판_권한분리.sql`, 운영 적용함)

탭을 가리는 것은 화면이 하고, **서버도 같이 가린다** — 전체 권한이 아닌 사람에게는 고1·고2 학생을
아예 안 내려 주고(`GRADES_MID`), 고등 판 줄도 빼고, 고등 판 저장은 403 으로 막는다.
화면만 가리면 주소를 직접 쳐서 열 수 있다.

★ 사람을 더하고 뺄 화면은 **아직 없다.** `app_settings` 를 SQL 로 고친다.

## 재는 법

```
node --import ./scripts/ts-resolve.mjs scripts/move-assign-check.ts
```

「진급 배정판 자가확인 ✓」가 나와야 한다. `.env.local` 이 있으면 운영 데이터로도 센다
(중3·초6 인원이 초안과 같은지, 동명이인이 걸리지 않는지, 못 오시는 요일에 걸린 학생이 없는지,
**초1~초5 가 실제로 읽히는지**, **DB 가 `track='초등'` 을 받는지**).
