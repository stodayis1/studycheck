# 초등 레벨학습지 70점 규칙

초등 레벨학습지는 **학기 중 학교 단원평가 대비용**이다. 학교는 진도 순서대로 단원평가를 보고,
날짜는 미리 알 수 없다. 그래서 "앞 단원을 통과 못 한 채 다음 단원으로 넘어갔는지"로 관리한다.

## 규칙

- 초등 본 학습지(`worksheet_type='main'`, `grade_level` 이 `초`로 시작)가 **70점 미만**이면
  **재도전**(같은 레벨), **레벨↓ 재도전**(0.5 낮춰 같은 단원), **오답유사**만 누를 수 있다. 레벨업/완료 버튼은 안 보인다.
  레벨↓ 재도전은 혼자 힘으로 그 레벨을 못 넘는 학생용 — 단원 통과는 필수지만 닿을 수 있는 레벨에서 통과시킨다.
- **오답유사는 재도전을 대신하지 못한다.** 오답유사를 채점하면(원래 학습지가 70점 미만이었을 때)
  점수와 상관없이 같은 레벨 재도전이 자동 배정된다. 오답유사는 틀린 문제만 모은 거라 점수가
  잘 나온다 (도입 전 데이터: 80점 미만의 70%가 오답유사로 처리됐고, 오답유사 평균이 87~94점이라
  대부분 그대로 다음으로 넘어갔다).
- 꼭 넘겨야 하면 **예외요청**(강사) → 원장이 학습지관리 첫 화면에서 승인/거절.
  원장은 **예외처리**로 사유를 남기고 바로 처리한다.
- 중등/고등 레벨학습지와 쌍둥이학습지에는 적용하지 않는다.

## 단원 통과 판정

통과 = 그 단원(학생·학년·학기·단원)에서 **가장 최근에 채점한 본 학습지가 70점 이상**.
한 번 70점을 넘긴 뒤 레벨업해서 낮은 점수로 끝나면 통과가 아니다.
진행중인 학습지가 남아있으면 판정하지 않는다(진행중). 코드: `getUnitPass` (`app/teacher/assignments/page.tsx`).

- 학습지 배정 탭 위: "70점 못 넘기고 멈춘 단원" 목록 + 재도전 배정 버튼 (이번 학기만)
- 레벨 현황판: 통과 = 체크, 멈춤 = 빨간 테두리

## 기록 (누가 무엇을 눌렀나)

- `student_worksheets.last_action` : 화면이 상태를 바꿀 때 "누른 버튼"을 같이 보낸다
  (`retry` `retry_down` `similar` `levelup` `complete` `override_levelup` `override_complete` `auto_retry` `revert`).
  트리거가 로그로 옮기고 바로 비운다 — 행에는 남지 않는다.
- `worksheet_action_logs` : 상태 변경·삭제를 전부 기록 (트리거 `worksheet_before_update`,
  `worksheet_after_delete`). 원장만 읽을 수 있다. 삭제된 학습지도 남도록 FK가 없다.
- `worksheet_override_requests` : 예외 요청. 강사는 `pending`만 넣을 수 있고, 결정은 원장만.
- 원장 화면: 학습지관리 → **처리 기록** 탭 (최근 30일, 선생님별).

## DB 차단

화면만 막으면 옛 화면/실수로 뚫릴 수 있어서, DB 트리거가 같은 규칙으로 막는다:
`docs/sql/초등학습지_70점_차단.sql`. **새 화면 배포 후에** 실행해야 한다 (파일 머리말 참고).

## 기준 변경 이력

- 2026-09-19 도입 시 80점 → 같은 날 **70점**으로 낮춤 (원장 결정). 도입 전 데이터 분석(80점 미만의 70%가
  오답유사로 처리됨)은 80점 기준으로 한 것이다. 중등 레벨학습지는 규칙 대상이 아니라 화면 색만 80점 그대로.
- 재도전 회차: 이번 학기 같은 학생·단원·레벨의 본 학습지를 배정순으로 센 것 (1차=처음). 학습지 목록·
  제출현황·점수입력·멈춘 단원 목록에 "2차/3차" 뱃지로 보인다 (3차부터 진한 빨강). 오답유사는 세지 않는다.
- 기준 점수는 `PASS_SCORE` (page.tsx)와 DB 트리거 두 곳에 있다 — 바꿀 때 둘 다 바꿀 것.
