## 파일

- 문제 그림에 문제 말고 다른 것(풀이·다른 문제)이 같이 잘려 있으면 problem 에 "crop": [x0,y0,x1,y1] (그림 픽셀)로 문제만 남긴다. 풀이 상자가 문제 그림 안에 같이 있으면 그 부분을 풀이 기준으로 쓴다.
- 풀이에 그래프·도형 그림이 꼭 필요하면 "figure": {"image": "<local_no>_a.png", "crop": [..]} 로 교재 풀이 그림 일부를 노트 오른쪽 위에 붙일 수 있다(최대 460x400 으로 줄어듦, 그 옆 줄은 좁아진다). crop 은 PIL 로 잘라 스크래치 폴더에 저장해 Read 로 확인한 뒤 정한다.

## 대본 규칙
- 단계(steps) 5~8개. 흐름: ① 문제 소개(pose A, 무엇을 구하나) ② 「먼저 혼자 풀어 봐」(영상 멈추라고) ③~ 풀이 ④ 답(빨강 box) ⑤ 마지막: 정리 + 자주 틀리는 점 + 마무리(pose E).
- 문제가 (1)(2) 로 나뉘면 각각 풀고, 노트에 "(1)" "(2)" 를 빨강으로 쓴다.
- **숫자를 다 읽지 않는다**: 식 세우는 첫 줄과 왜 그 식인지, 주의할 한 군데, 답만 읽는다. 전개·이항·인수분해·대입 계산은 `[[쓰기]]` 자리에서 `"quiet": true` 줄로 보여만 준다.
- **끊김 줄이기**: 한 토막(/, //, {강조}로 나뉘는 조각)은 8자 이상. [[쓰기]] 앞뒤는 완결된 문장. {강조}는 꼬리말까지 감싼다.
- say 에는 영문자·숫자·기호를 쓰지 않는다(에이, 엑스, 일, 이, 루트, 제곱 …). 수식 읽기는 _말투.md 의 원장님 식.
- 말투 버전: _말투.md 의 시작·먼저 풀어 보기·계산·답·주의·마무리 묶음에서 **예제마다 다른 번호**를 고른다. 내 담당 안에서 연달아 같은 말을 쓰지 않는다. 같은 소단원에서 비슷한 문장이 반복되지 않게.
- pose 는 A·B·C·D·E 를 고루. A=가리키며 말하기, B=이것만 기억, C=갸웃(질문), D=지시봉(풀이), E=화이팅(마무리).
- bubble(말풍선)은 짧게(15자 안팎).
- 노트 줄(tex)은 matplotlib mathtext. 한 줄이 너무 넓으면 두 줄로(indent 1).
- 말 전체 600~1000자 정도(한 편 1.5~2.5분). 길어지면 설명을 줄인다.
- **정확성이 최우선**: 문제를 먼저 혼자 풀고, 교재 풀이와 답을 맞춘다. 다르면 교재를 다시 읽고, 그래도 다르면 보고에 적는다. 노트에 쓰는 모든 식은 수학적으로 맞아야 한다.
- JSON 을 쓸 때 수식의 역슬래시는 JSON 안에서 `\\` 두 개다. Bash heredoc 은 역슬래시를 망가뜨리니 **Write 도구로 파일을 쓴다.**

- **숫자 뒤 조사 「이」 조심**: 「십이 나오죠」는 12, 「이 루트 십이야」는 2√12, 「사, 이, 이 세 개」는 「이이」로 들린다.

- **증명형 예제**(문제 그림 안에 「증명」 상자가 같이 잘려 있는 것, 높이 1680px 짜리): problem crop 으로 문제만 남기고, 그 그림 속 증명 상자를 풀이 기준으로 쓴다. 이때 `_a.png` 가 다른 문제 그림일 수 있으니 문제와 맞는지 꼭 확인하고, 안 맞으면 보고한다.
- 집합 기호(∈ ⊂ ∪ ∩ ∅ ᶜ), 명제 기호(→ ⇔ ~), 함수 기호(∘ ⁻¹) 는 tex 의 $\in$ $\subset$ $\cup$ $\cap$ $\varnothing$ $A^{C}$ $\rightarrow$ $\Leftrightarrow$ $\sim$ $\circ$ $f^{-1}$ 로 쓰고 검사기 미리보기로 그려지는지 본다. 말풍선(bubble)에는 이런 기호를 쓰지 않는다.
- 말로 읽을 때: 합집합 「에이 합집합 비」, 교집합 「에이 교집합 비」, 여집합 「에이의 여집합」, 원소 개수 「엔 에이」, 합성함수 「에프 합성 지」 또는 「에프 지 엑스」, 역함수 「에프 인버스」.
