# PDF 학습지 (강사 자료)

선생님이 가진 **PDF 한 개**를 올려 문항별 그림으로 잘라 문제은행에 넣고, **수학의지혜 시험지 양식**으로
인쇄하고, 학생에게 배정하는 길. 2026-11-17 추가.

> 원장님 2026-11-17
> 「고등강사가 가지고 있는 pdf파일이 있어. 그걸 스터디체크 문제은행에 업로드하면 바로 수학의지혜 양식으로
> 출력할 수 있도록 기능을 하나 만들자」
> 「기출이 될수도 있고, 모의고사 일수도 있고, 오답이 될수도 있지. 아니면 이전에 있던 학원에서 만들어둔
> 자료일수도 있고. 강사가 pdf파일을 올리면 제목을 공통수학-단원명-난이도 상중하로 적게해서 어느 학생에게
> 배정했는지를 기록하게 하면 될듯. 그래서 그 학생의 학습지 기록에 남길수 있도록」
>
> 같은 날 바로잡음 — 「기출은 기출모음에 넣기로 했잖아」

## ★ 학교 기출 시험지는 여기가 아니다

**기출은 「기출 모음」 현황판의 「기출 파일 올리기」(기출모음)로 간다.** 원장님이 2026-11-17 에 못박으셨다.
적중률(이너프원 매칭) · 블로그 · 연도별 찾기 · 원본 보관이 모두 그쪽에 달려 있고, 그 길은 파일명을 맞출
필요도 없이 연도 · 학기 · 학교 · 학년을 짐작해 채워 준다 (`docs/시험지분석.md` 의 「기출 보관함」 절).

여기 올리는 것은 **학교 시험이 아닌 자료**뿐이다 — 모의고사 · 오답 모음 · 이전 학원에서 만든 자료.

## 「기출 모음」과 무엇이 다른가 (먼저 읽을 것)

> 「기출 모음」은 `/teacher/exam-analysis` 다 — 메뉴 이름이 2026-11-17 에 「시험지 분석」에서 바뀌었다.
> 주소·표 이름(`exam_papers` 등)·문서 이름(`docs/시험지분석.md`)은 그대로다.

둘 다 PDF 를 문항으로 잘라 문제은행에 넣는다. **자르는 코드는 같다**(`lib/examPdfCrop.ts`).
다른 것은 **무엇에 매달리는가**다.

| | 기출 모음 | PDF 학습지 (이 문서) |
|---|---|---|
| 먼저 있어야 하는 것 | `exam_papers` 한 줄 — 학교 · 연도 · 학기 · 중간/기말 | **없다**. PDF 만 있으면 된다 |
| 무엇을 올리나 | **학교 기출 시험지** (기출모음) | 모의고사 · 오답 모음 · 이전 학원 자료 |
| 쓰는 사람 | 올리기·반영은 원장님 | 원장님 + **고등 담당 선생님** |
| 교재(`problems.book`) | `학교기출` | `강사자료` |
| 제목 | `26년 도래울중 2학기 중간고사` | `공통수학2-삼각함수-중` |
| 딸려 오는 것 | 정답표 · 변별문항 · 총평 · 이너프원 적중 · 블로그 | 없다. 인쇄와 배정뿐이다 |
| 자르기 | 자동만 (못 읽으면 막힌다) | 자동 + **손으로 네모 그리기** |

**학교 기출 시험지는 「기출 모음」의 「기출 파일 올리기」로 간다** (위 ★ 절).
이 화면은 그 네 칸을 채울 수 없는 자료 — 모의고사 · 오답 모음 · 이전 학원 자료 — 를 위한 것이다.

## 화면

| 주소 | 내용 |
|---|---|
| `/teacher/pdf-worksheets` | 올린 자료 목록 (문항 수 · 배정 · 푼 사람) + 「PDF 올리기」 |
| `/teacher/pdf-worksheets/print?code=<코드>` | 수학의지혜 시험지 양식 인쇄 (A4 2단 · 빠른 정답) |

사이드바 「과제 · 평가 > PDF 학습지」. **원장님과 고등 담당 선생님에게만** 보인다.

### 네 걸음

1. **PDF 고르기** — 쪽을 그려 놓고 자동 자르기를 한 번 해 본다.
2. **자리 손보기** — 자동이 틀렸거나 못 읽었으면 쪽 그림 위에 **네모를 그려** 문항을 만든다.
   번호는 「쪽 → 왼쪽 단 → 오른쪽 단」 순서로 매긴다 (체크를 켜면 그린 차례대로).
3. **확인** — 제목 세 칸(과정 · 단원명 · 난이도) · 문항 수 · 번호 연속 · 배점.
4. **넣기** — 문항마다 한 번씩 보낸다 → 바로 인쇄 · 배정.

## 자르기 — 자동이 못 읽는 것이 보통이다

자동 자르기는 **한글에서 2단으로 짠 작업본**(문항 앞에 작은 `1)` 미주 또는 `1.`)만 읽는다.
아는 꼴은 세 가지뿐이고(`docs/시험지분석.md` 의 「자르기 규칙」 절), 강사가 가진 PDF 는 그 꼴이 아닌 것이
보통이다. 그래서 **못 읽어도 막다른 길이 아니게** 만들었다.

- 0개면 화면이 **왜 못 읽었는지** 적고(「「1)」 꼴을 N개 찾았지만 문항 시작으로 보지 않았습니다」 등)
  곧바로 손으로 자르기로 보낸다.
- 자동으로 찾았어도 「자리 손보기」로 돌아가 다시 그릴 수 있다.
- 쪽 그림을 전부 200dpi 로 들고 있으면 13쪽에서 200MB 가 넘는다. 그래서 **보여 주는 것은 낮은 해상도**
  (`VIEW_SCALE = 1.4`, 약 100dpi)로 그리고, **자를 때만** 그 쪽을 200dpi 로 다시 그린다.
  쪽마다 한 번만 그린다 — 네모마다 그리면 같은 쪽을 수십 번 다시 그린다.

## 제목 — 「과정 - 단원명 - 학습지 종류 - 난이도」

원장님이 적으라고 하신 꼴이다. 규칙은 `lib/tutorWorksheet.ts` 한 곳에 있고 **화면과 서버가 같은 함수를
쓴다**(`tutorKeyError`) — 화면만 막으면 주소로 직접 부르는 길이 열린다.

- 과정: `공통수학1` `공통수학2` `대수` `미적분1` `확률과통계` `기하`
  — `problems.grade` 에 **그대로** 들어가므로 `lib/curriculumProgress.ts` 의 `GRADE_ORDER` 와 글자가 같아야 한다.
- 단원명: 자유 입력. **줄표(-)는 못 쓴다** — 제목을 줄표로 가르기 때문이다.
- **학습지 종류**(원장님 2026-11-17 「학습지 종류도 쓰게 해줘 … 교과서 … 단계별 학습지라던가」):
  **고르는 목록이 아니라 적는 칸**이다. 범주를 지어내지 않는다(원장님 2026-10-31 「현재 쓰고 있는
  규칙에서 우리가 범주를 만들어가는게 맞아`). `TUTOR_KINDS` 는 **자주 쓰실 말을 한 번에 넣는 단추**일
  뿐이고 다른 말을 적어도, 비워 두어도 된다. `problems.source_meta.source_kind` 에 남는다.
- 난이도: `상` `중` `하` → `problems.difficulty`

### 제목을 되읽는 법 — `parseTutorTitle`

★ **`split('-')` 한 자리를 번호로 집지 않는다.** 종류가 생기기 전(2026-11-17 낮)에 만든 학습지는
세 칸이고 그 뒤는 네 칸이다. 그래서 **과정은 밖에서 받고(`exam_sheets.grade`), 난이도는 맨 뒤에서,
나머지를 가운데로** 읽는다. 난이도가 언제나 맨 뒤인 까닭이 이것이다.
서버(`action: 'question'`)와 인쇄 화면이 둘 다 이 함수를 쓴다.

## problems 에 들어가는 값

| 칸 | 값 |
|---|---|
| `book` | `강사자료` |
| `grade` | 과정 (`공통수학2`) |
| `semester` | `1` (고등 과정은 학기로 갈리지 않는다 — 쎈 공통수학1 과 같게 맞췄다) |
| `sub_chapter_no` / `sub_chapter_title` | `0` / 단원명 |
| `local_no` | `삼각함수-중-7` |
| `step` / `difficulty` | `강사자료` / `상`·`중`·`하` |
| `type_code` / `level` | **둘 다 null** (아래 ★) |
| `answer_kind` / `answer_text` | 정답을 적었으면 `choice`·`number`, 비었으면 `image`(학생 자기채점) |
| `image_path` | `tutor/<학습지 id>/<번호>.png` (`problem-images` 보관함) |
| `source_key` | `tutor:<학습지 id>:<번호>` — unique. 같은 번호를 또 보내면 **고친다** |
| `source_meta` | `source_type: tutor`, 과정·단원·난이도·번호·배점·PDF 이름·올린 사람 |

★ **유형(`type_code`)과 레벨(`level`)은 넣지 않는다.** 학교기출과 같은 방침이다 — 유형을 붙이면
그때부터 **자동 출제에 섞여** 다른 학생 학습지에 나온다. 강사가 올린 자료는 유형·학원 공통 레벨(1~6)이
정해지지 않은 것이므로 섞이면 안 된다. 원장님이 「상/중/하」로 적으신 난이도는 `difficulty` 에 글자로 둔다.

## 배정 — 학생 학습지 기록에 남는 길

새 표를 만들지 않았다. **이미 있는 배부표**(`exam_sheet_targets`, `docs/sql/학습지_배부표_추가.sql`)를 쓴다.

```
exam_sheets        한 벌 (code · title · created_by · note = 'tutor:<PDF 이름>')
exam_sheet_problems  번호 순서로 문항
exam_sheet_targets   누구에게 냈는지 (+ 마감일)
gradings             푼 결과 (QR 채점 · 학생 앱)
```

- 배정하면 학생 앱 「할 일 > 선생님이 보낸 학습지」(`app/student/assignments`)에 제목 · 마감 · 점수가 뜬다.
  **종이가 없어도 된다** — 인쇄해서 줘도 되고, 폰으로 답만 넣어도 된다.
- **강사는 본인 담당 학생만** 배정할 수 있다(원장님 2026-10-29). 규칙을 베껴 쓰지 않고
  **그 사람 토큰으로 `students` 를 읽어 본다** — RLS(`students.staff_or_own`)가 정답이다.
  담당이 아닌 학생이 섞여 오면 조용히 빼고 몇 명을 뺐는지 알려 준다.
- **이미 푼 학생은 체크를 풀어도 빠지지 않는다.** 기록이 사라진 것처럼 보이면 안 된다.
- 테스트 학생으로 해 보는 길이 배정 창에 있다 (원장님 = 윤수지, 강사 = 「테스트」, `lib/testStudents.ts`).

## 인쇄 — 양식은 한 벌만 둔다

`components/exam-analysis/ExamPaperPrint.tsx` 를 **그대로** 쓴다. 2026-11-17 에 머리 글자를 밖에서
넣는 길(`heading`)을 더했다 — 양식(쪽 짜기 · 치수 · CSS)은 한 벌이고 글자만 바뀐다.
`heading` 을 안 넘기면 기출 인쇄는 전과 똑같다.

| 자리 | 기출 | PDF 학습지 |
|---|---|---|
| 맨 윗줄 | `2026학년도 2학기 중간고사` | 제목 `공통수학2-삼각함수-중` |
| 큰 글씨 | `3학년` | `고1` / `고2` (`tutorGradeLabel`) |
| 오른쪽 상자 | 학교 이름 | `난이도 중` |

큰 글씨 칸은 25pt 짜리 **짧은 글자 자리**다. 「공통수학2」를 그대로 넣으면 44mm 를 먹어 머리 띠가 밀린다
— 그래서 과정을 학년으로 바꿔 넣고 과정·단원·난이도는 맨 윗줄 제목에 적는다.

## 권한

| 하는 일 | 누가 |
|---|---|
| 메뉴 · 화면 | 원장님 + `can_see_high_curriculum()` 이 true 인 사람 |
| 올리기 · 문제은행에 넣기 · 인쇄 | 같음 (원장님 2026-11-17 「고등 강사까지 열기」) |
| 목록 | 원장님은 전부, 선생님은 **본인이 올린 것만** |
| 배정 | 본인 담당 학생만 (원장님은 전부) |

판단은 **DB 함수 `can_see_high_curriculum()` 한 곳에만** 있다 (`docs/sql/고등커리큘럼_고등강사만.sql`).
서버는 `lib/apiAuth.ts` 의 `highOrDeny(req)` 가 **그 사람의 토큰으로** 그 함수를 불러 그대로 따른다
— 규칙을 베껴 쓰지 않는다. 그래야 원장님이 명단에 한 사람을 더해도 앱을 고치지 않는다.
같은 가드를 `app/api/move-assign` 도 쓴다.

## 새 SQL 은 없다

표·칸·정책을 하나도 더하지 않았다. `exam_sheets` · `exam_sheet_problems` · `exam_sheet_targets` ·
`problems` · `problem-images` 보관함이 모두 이미 있는 것이다. 그래서 **배포만 하면 바로 쓸 수 있다.**

## 안 한 것 · 알아둘 것

- **지우는 길은 두지 않았다.** 넣은 문항은 이미 학생 학습지에 쓰였을 수 있다(학교기출과 같은 규칙).
  같은 자료를 고치려면 새로 올리고 예전 것은 배정하지 않으면 된다.
- **같은 PDF 를 또 올리면 새 학습지가 하나 더 생긴다.** 학교 기출처럼 「시험 한 건」이라는 열쇠가 없어서
  무엇이 같은 자료인지 기계가 가릴 수 없다.
- **학교 기출을 여기 올려도 기계가 막지는 않는다.** 막을 열쇠가 없다(학교 이름을 묻지 않으므로).
  그래서 올리는 화면 · 목록 · 매뉴얼 세 곳에 「기출은 「기출 파일 올리기」로」를 적어 두었다.
- **해설 그림은 넣지 않는다.** 자동 자르기가 정답 칸을 그림으로 잡았으면 그것만 들어간다.
- **적중률·이너프원 매칭에는 안 섞인다.** 그 셈은 `exam_papers` 에 달려 있다.
- 문항 수가 많으면 넣는 데 시간이 걸린다 — 문항마다 요청을 하나씩 보낸다(23문항을 한 요청에 담으면
  본문이 몇 MB 가 되어 막힌다. 「기출 모음」의 `importPdfQuestion` 과 같은 방식).

## 검사

```bash
node --import ./scripts/ts-resolve.mjs scripts/pdf-worksheet-check.ts         # 규칙 (120/120)
node --import ./scripts/ts-resolve.mjs scripts/pdf-worksheet-guard-check.ts   # 가드 (18/18)
```

- **규칙**: 제목(`tutorKeyError` · `tutorTitle`) · 점검(`tutorCheck`) · problems 한 줄(`tutorProblemRow`) ·
  인쇄 머리 학년(`tutorGradeLabel`). `lib/tutorWorksheet.ts` 를 **그대로 불러** 잰다 (사본으로 재지 않는다).
  제목을 `split('-')` 로 **되읽을 수 있는지**도 본다 — 서버와 인쇄 화면이 그렇게 세 칸을 되살린다.
- **가드**: `app/api/pdf-worksheets/route.ts` 를 그대로 불러 **토큰 없이** GET · POST 를 눌러 보고 401 을
  확인한다(DB 에 닿지 않는다). 강사 계정이 없어 눌러 볼 수 없는 가드를 이렇게 재 둔다.
  같이 바꾼 `app/api/move-assign` 도 전과 똑같이 막히는지 함께 본다.
- 둘 다 **일부러 망가뜨린 값·사본에서 실패하는지**까지 본다 (통과만 하는 검사는 검사가 아니다).

`lib/examPdfCrop.ts` 를 고쳤으면 기출 쪽 검사도 같이 돌린다 — `scripts/exam-crop-mark-check.ts`(43/43) ·
`scripts/exam-answerkey-check.ts`(20/20).
